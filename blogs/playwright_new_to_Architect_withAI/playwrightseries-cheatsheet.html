A test Phase 0

import { test, expect } from '@playwright/test';Top of every spec file
test('name', async ({ page }) => { })One test. page is a fresh browser tab.
test.describe('group', () => { })Group tests in the report
await page.goto('/')Joined to baseURL from the config
test.only(..)   test.skip(..)Only: runs nothing else. Skip: hides a test.
test.fail() inside a testKnown bug: expected to fail. Passing then turns red.

Find it Phase 2: best first

getByRole('button', { name: /add to cart/i })First choice. Role + visible name.
getByRole('heading', { level: 1 })Roles: link, textbox, checkbox, radio, combobox, slider, img, navigation
getByRole('button', { name: 'Search', exact: true })exact: full match, not "contains"
getByLabel('In stock only')Field linked to its label
getByPlaceholder('Search gear...')No label? The hint text
getByText('Showing 10 of 10 products')Words on the page
getByTitle(..)   getByAltText(..)Hover title / image alt text
getByTestId('product-card')Ask the developer for data-testid
locator('input[type="email"]')CSS: last resort, when nothing else names it

Avoid .btn-add or #submit-btn: a restyle breaks them. A locator is a description, not a search: it looks again every time it's used.

Narrow it down Phase 2

page.getByRole('navigation').getByRole('link', { name: 'Cart' })Chain: a link, only inside the nav
cards.filter({ hasText: 'Camping Stove' })Keep matches that contain text
cards.filter({ has: page.getByRole('heading', { name: 'X' }) })Keep matches that contain an element
heading.locator('..')Parent: from the heading up to its card
.first() .last() .nth(1)By position: breaks when the order changes

Do something Phases 2, 8

await loc.click()Waits until it's visible, stable and enabled, then clicks
await loc.fill('tent')Clear, then type. Typed text: pressSequentially
await loc.check() .uncheck()Tick boxes and radios. Hidden input: { force: true }
await loc.selectOption('price-asc')Pick from a dropdown, by value
await loc.hover()   loc.press('Home')Tooltips / one key (sliders)
await from.dragTo(to)Drag. Or hover, mouse.down(), hover, mouse.up()
await loc.setInputFiles('a.csv')Upload, no file picker. Or { name, mimeType, buffer }
page.frameLocator('iframe[title="Payment form"]')Start here for anything inside an iframe

Check it Phase 3

await expect(loc).toBeVisible()Retries until it passes or times out
toHaveText('..') toContainText('..')Whole text / part of it
toHaveCount(3) toHaveValue('x')How many / what's typed
toHaveAttribute('href', '/cart')One attribute
toBeEnabled() toBeDisabled() toBeChecked()State
expect(page).toHaveURL(..) .toHaveTitle(..)The page itself
await expect(loc).not.toBeVisible()Prove the page loaded first
expect.soft(a).toBe(b)Records a failure, keeps going: for audits
expect(price).toBeGreaterThan(0)Generic: checks a value you hold, once
expect(locator).toBeTruthy()Can never fail: a locator is always truthy

Read values Phase 3

await loc.textContent()Text of one element
await loc.allTextContents()Array of every match. Doesn't wait: [] if too early.
await loc.count()How many matches. Doesn't wait for the list.
await loc.inputValue()What's typed in a field
await loc.getAttribute('href')One attribute

Wait for something visible first, then read. Prefer a locator assertion over read-then-expect.

Wait, best choice first Phase 3

await expect(loc).toBeVisible()1. Assert what the user will see
const r = page.waitForResponse(res => res.url().includes('/api/cart') && res.request().method() === 'POST'); await btn.click(); await r;2. Wait for one signal. Start the wait before the click.
await loc.waitFor({ state: 'hidden' })2. A loading message going away
await page.waitForURL('/')After login or a redirect
page.waitForLoadState('networkidle')3. Last resort
page.waitForTimeout(3000)Never: a guess that's too slow or too short
waitForEvent('filechooser' | 'download' | 'popup' | 'dialog')Listen before the click
page.once('dialog', d => d.accept())Answer a confirm. No answer: dismissed (Cancel). A listener that never answers hangs the click.

Slow tests Phase 10

timeout: 30_000One test (config)
expect: { timeout: 5_000 }One expect check
actionTimeout navigationTimeoutOne click / one goto (under use)
test.setTimeout(60_000)   test.slow()This test only / triple its time

An inner timeout can't outlast the test. Raise the right layer, not all of them.

The Quality Strategist

Test data Phase 5

`qa-${Date.now()}@peakandpack.test`A new, unique user every run
request.post(`${API}/api/auth/register`, { data })Set up through the API: fast, no browser
expect(res.status()).toBe(201)Check the status first, always
test.beforeEach(async ({ request }) => { })Per-test setup. Also afterEach, beforeAll, afterAll.
try { .. } finally { await request.delete(..) }Clean up even if the checks fail

Rule: each test makes its own data and runs in any order.

Sessions & roles Phase 6

page.addInitScript(..localStorage.setItem('token', t)..)Sign the browser in as an API user, before goto
await page.context().storageState({ path })Save a login to a file
{ name: 'setup', testMatch: /.*\.setup\.ts/ }Log in once; the real project adds dependencies: ['setup']
use: { storageState: '..customer.json' }Every test in the project starts signed in
test.use({ storageState: '..admin.json' })Switch role for one group
browser.newContext()A second, separate user in one test

Add playwright/.auth to .gitignore. Prove who's signed in first: "no Admin link" passes logged out too.

API & mocking Phase 7

request.get(url, { params: { q: 'tent' } })Query string: ?q=tent
request.post(url, { headers, data })headers: { Authorization: `Bearer ${t}` }
401 / 403 / 404 / 409Not logged in / not allowed / missing / already exists
page.route('**/api/products', r => r.fulfill({ json }))Fake the answer. Set up before goto.
route.fulfill({ status: 500, body: '..' })Force an error the app must handle
route.fetch() then route.fulfill({ response, json })Real answer, edit one field

API on another host? Use the full URL: a relative pattern resolves against baseURL.

Structure Phases 9–10

class CartPage { constructor(private readonly page: Page) {} }Page object: a page's locators in one place
proceedToCheckout(): Promise<CheckoutPage>Return the next page object
base.extend<{ customer: Customer }>({ .. })Fixture: setup, await use(x), then teardown (runs even on failure)
{ scope: 'worker' }Once per worker, not per test
import { test, expect } from '../fixtures';Specs import yours, not Playwright's

Assertions stay in the test; the page object only finds and does. Don't hide expect inside helpers.

Commands Phases 0, 4, 12

--headed   --ui   --debugWatch / UI mode / step through in the Inspector
tests/cart.spec.ts   -g "search"One file / titles containing a word
--project=chromium   --listOne project / show what would run
--grep @critical   --grep-invert @slowBy tag: test('x', { tag: '@critical' }, ..)

--retries=2   --trace onRetry / record a trace for every test
--update-snapshotsReplace visual baselines: only if the page looks right
--shard=1/4   --reporter=blobSplit across machines
npx playwright show-reportOpen the HTML report
npx playwright merge-reports ./dirJoin the shards' reports (--reporter html)

Visual Phase 11

expect(page).toHaveScreenshot('home.png', { fullPage: true })Compare to a saved baseline. First run writes it, and fails.
expect(card).toHaveScreenshot('card.png')Just one element
maxDiffPixels: 100A little difference is fine
mask: [page.getByText(/^Order ID/)]Paint over what changes each run

Baselines are per browser and OS: make them where CI runs. Stub images with page.route first.

CI Phase 12

npm ci   npx playwright install --with-deps chromiumExact versions; only the browser you use
upload-artifact with if: always()Keep the report on failure too
on: schedule: - cron: '0 2 * * *'Nightly, 02:00 UTC
Pass only on retryThat's flaky: log it and fix it. Don't hide it with more retries.

Messages, decoded

strict mode violationLocator matched several: narrow it
Timeout 5000ms exceededNever became true: wrong text or page
element is not enabledDisabled: finish the step before it (payment, login)
A snapshot doesn't existVisual test's first run: run again
Passes, but nothing was checkedNo await, or a check wrapped in if
