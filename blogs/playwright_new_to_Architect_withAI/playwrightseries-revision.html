Phase 0: Intro & Setup Open phase
1 · Setting up
Why does Playwright need Node.js, and which minimum version?
What is npm, and what is a package?
Which five things does npm init playwright@latest put in your project?
Why does node_modules never go into Git?
Why should you cd into a projects folder before mkdir?
RecapHide
  • Playwright is written in JavaScript, and Node.js runs JavaScript outside a browser. It needs version 18 or higher.
  • npm is Node's package manager, installed with Node. A package is ready-made code someone else wrote and shared.
  • package.json (the project's ID card), package-lock.json (exact versions), node_modules/ (the packages), playwright.config.ts (settings), tests/example.spec.ts (a demo you delete). Plus .gitignore, and the browsers go to a shared folder outside the project.
  • It's large, and it can be rebuilt from package.json at any time.
  • A terminal can open in a system folder, such as C:\WINDOWS\system32 when run as administrator. The project would end up there.

2 · Git and GitHub
What do git init, git add . and git commit -m each do?
What is staging?
What are a remote and origin?
Why git branch -M main, and what does -u do in git push -u origin main?
Why create the GitHub repository without a README?
RecapHide
  • init starts tracking the folder (a hidden .git folder). add . chooses everything for the next snapshot. commit -m takes the snapshot, with a message.
  • Choosing what goes into the next commit, before taking it.
  • A remote is the online copy of your repository. origin is the usual name for the main one.
  • It renames the branch from master to main, GitHub's default. -u remembers the pairing, so later pushes are just git push.
  • Your folder already has files. An empty repository avoids a clash on the first push.
→ See: Phase 0, step 3
3 · The config file
What does baseURL do, and how does it start in the generated file?
Read retries: process.env.CI ? 2 : 0 aloud. Why 0 on your own machine?
What is process.env, and who sets CI?
When does trace: 'on-first-retry' record a trace?
Why does every test run three times?
Why did VS Code underline process, and what fixed it?
RecapHide
  • It's joined to every page.goto('/'), so the address lives in one place. It starts commented out, pointing at localhost; you uncomment it and set PeakAndPack's address.
  • "On a CI server, retry twice, otherwise never." Locally, a retry could make a real problem pass on the second try and hide it.
  • Environment variables: settings the computer passes to a program. CI services such as GitHub Actions set CI; your laptop doesn't.
  • Only when a failed test is retried. Traces are large, so they're recorded only when something went wrong.
  • The projects list runs each test in Chromium, Firefox and WebKit.
  • Newer TypeScript no longer loads Node's types on its own. A tsconfig.json with "types": ["node"] fixed it. Tests run either way.
→ See: Phase 0, step 4
4 · Anatomy of a test
What do test and expect do?
What makes a good test name?
What is page, and why does every test get its own?
Why is async there?
What does await do, and what happens without it?
What is an assertion?
RecapHide
  • test creates a test; expect checks that something is true.
  • It says what should be true, so a failure tells you what broke without opening the code.
  • A fresh, empty browser tab. Its own tab means tests can't interfere with each other.
  • It's required whenever the steps use await.
  • It waits for the step to finish before the next line. Without it, the test races ahead and can finish, even "pass", before a check has run.
  • A statement that must be true for the test to pass. A test without one never checks anything.
→ See: Phase 0, step 5
5 · Finding and checking elements
Why find elements by role? Name two benefits.
In { name: /peakandpack/i }, what do the slashes and the i mean?
Why give a name at all?
What does getByRole give back: the element, or something else?
What does toBeVisible check, and how long does it wait?
How is the search box found when it has no label?
RecapHide
  • It survives redesigns (it's still a heading after a restyle), and it checks accessibility for free (if Playwright can't find it by role, a screen reader user probably can't either).
  • Slashes mark a pattern instead of exact text, matching any name that contains the letters. i ignores upper and lower case.
  • A page often has several headings. Without a name, Playwright doesn't know which one you mean and stops with an error.
  • A locator: a description of how to find it. Playwright searches only when it's used, and searches again each time.
  • That the element exists, isn't hidden, and takes up space on screen. It keeps retrying for up to 5 seconds.
  • By its placeholder, the grey hint text "Search gear...", which becomes its name.
→ See: Phase 0, step 5
6 · Running and reading results
What do npx and playwright test each do?
Headless or --headed: what's the difference?
Why 6 results for 2 tests? What is a worker?
How do you run a single file?
Every test failed on the first run. Most likely cause on PeakAndPack?
In the report, what are Before Hooks and After Hooks, and what does p:chromium mean?
RecapHide
  • npx runs a tool installed in the project. playwright test runs every .spec.ts file in tests/.
  • Headless runs without windows: faster, and how servers run it. --headed shows the windows, so you can watch.
  • 2 tests × 3 browsers. A worker is a separate process running tests side by side.
  • npx playwright test tests/first.spec.ts, or part of the name: npx playwright test first.
  • The free server was asleep. The page showed "Loading gear..." for longer than the 5-second wait. Open the store, wait for products, rerun.
  • Playwright preparing a fresh tab, and cleaning up afterwards. p:chromium is a filter for the chromium project, set by clicking its tag.
