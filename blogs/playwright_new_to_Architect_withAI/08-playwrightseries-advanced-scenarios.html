Advanced Scenarios

File uploads, multiple tabs, dialogs, iframes, drag and drop, and infinite scroll. The parts most automation engineers skip.

Goal

Handle the parts of real applications that make most automation engineers give up. File uploads, multiple tabs, dialogs, iframes, drag and drop, and infinite scroll: each requires a specific Playwright pattern.

Before: skipping or hardcoding workarounds

Before: skipping the hard part
// The test skips file upload because "it's too hard to automate".
// The dialog test uses a fixed wait instead of handling the dialog.
// These are not tests -- they're gaps in coverage.

test.skip('admin CSV upload'); // TODO: figure this out later

test('delete button works', async ({ page }) => {
  await page.goto('https://peakandpack-ui.onrender.com/admin/products');
  await page.getByRole('button', { name: /delete/i }).first().click();
  await page.waitForTimeout(500); // hope the dialog appears
  // Dialog never handled -- test passes without confirming the delete
});
After: every scenario handled properly
// File upload handled with setInputFiles.
// Dialog handled by registering a listener before the action.

test('admin can upload product CSV', async ({ page }) => {
  await page.goto('https://peakandpack-ui.onrender.com/admin/import');
  await page.getByLabel(/upload/i).setInputFiles('fixtures/products.csv');
  await page.getByRole('button', { name: /import/i }).click();
  await expect(page.getByRole('status')).toContainText(/imported/i);
});

test('delete button removes product after confirmation', async ({ page }) => {
  // Register dialog handler BEFORE the action that triggers it
  page.once('dialog', dialog => dialog.accept());
  await page.goto('https://peakandpack-ui.onrender.com/admin/products');
  await page.getByRole('button', { name: /delete/i }).first().click();
  await expect(page.getByRole('alert')).toContainText(/deleted/i);
});

File upload and download

setInputFiles() sets a file on a file input element without opening the OS file picker: the picker cannot be automated:

// Upload a file
await page.getByLabel(/upload csv/i).setInputFiles('fixtures/products.csv');

// Upload multiple files
await page.getByLabel(/images/i).setInputFiles([
  'fixtures/image1.png',
  'fixtures/image2.png',
]);

// Download a file and assert its content
const downloadPromise = page.waitForEvent('download');
await page.getByRole('link', { name: /export/i }).click();
const download = await downloadPromise;
const path = await download.path();
const content = require('fs').readFileSync(path, 'utf8');
expect(content).toContain('productId');

Multiple tabs and windows

When a link or button opens a new tab, Playwright gives you the new page object via the popup event:

// Open a product in a new tab and assert both tabs are consistent
const [newTab] = await Promise.all([
  page.waitForEvent('popup'),
  page.getByRole('link', { name: /open in new tab/i }).click(),
]);
await newTab.waitForLoadState();

// Assert the new tab shows the same product
await expect(newTab.getByRole('heading', { name: /trail runner pro/i })).toBeVisible();
// Assert the original tab is unchanged
await expect(page.getByRole('heading', { name: /products/i })).toBeVisible();

Dialogs and alerts

Browser dialogs (alert, confirm, prompt) must be handled by registering a listener before the action that triggers them. If you don't handle a dialog, Playwright dismisses it automatically and the test may fail for the wrong reason:

// Accept a confirm dialog
page.once('dialog', dialog => dialog.accept());
await page.getByRole('button', { name: /delete/i }).click();

// Dismiss a confirm dialog (click Cancel)
page.once('dialog', dialog => dialog.dismiss());
await page.getByRole('button', { name: /delete/i }).click();

// Handle a prompt dialog and enter text
page.once('dialog', dialog => dialog.accept('My new name'));
await page.getByRole('button', { name: /rename/i }).click();

Iframes

Elements inside an iframe are in a separate document. Use frameLocator() to scope your locator to the iframe first:

// Find an element inside an iframe
const frame = page.frameLocator('iframe[title="Payment form"]');
await frame.getByLabel(/card number/i).fill('4111 1111 1111 1111');
await frame.getByLabel(/expiry/i).fill('12/28');
await frame.getByRole('button', { name: /pay/i }).click();

Drag and drop

For HTML5 drag and drop, use dragTo(). For custom drag implementations, use dispatchEvent with the mouse events the implementation listens for:

// HTML5 drag and drop
const item = page.getByRole('listitem').nth(0);
const target = page.getByRole('listitem').nth(2);
await item.dragTo(target);

// Assert the new order
const items = await page.getByRole('listitem').allTextContents();
expect(items[0]).toContain('expected first item');

Infinite scroll and virtualized lists

Products not yet loaded into the DOM cannot be found by a locator. Scroll to load them first:

// Scroll to the bottom of the page to trigger loading more products
await page.evaluate(() => window.scrollTo(0, document.body.scrollHeight));

// Wait for the new items to appear
await page.waitForSelector('[data-testid="product-card"]:nth-child(25)');

// Now assert the items that were not in the initial load
await expect(
  page.getByRole('article').nth(24)
).toBeVisible();

Register event listeners before the action, not after. This applies to dialogs, popups, downloads, and file choosers. Playwright events fire at the moment of the action. If you set up the listener a millisecond after the click, you've already missed it.

Common mistakes in Phase 8.

  • Trying to click the OS file picker. Operating system dialogs cannot be automated by Playwright. Use setInputFiles() directly on the input element instead.
  • Handling dialogs after the click. The dialog fires immediately when the button is clicked. Set up page.once('dialog', ...) before clicking, not after.
  • Using page locators inside an iframe. Locators on page don't cross iframe boundaries. Always use page.frameLocator('...') first.
  • Asserting virtualized list items before scrolling. Items that haven't been loaded into the DOM yet return "element not found". Scroll to load them first, then assert.

Assignment

Handle a confirm dialog properly

Write two tests for PeakAndPack's product delete flow. The first accepts the confirm dialog and asserts the product is removed. The second dismisses the dialog and asserts the product is still there. Both tests must register the dialog handler before clicking the delete button. Confirm both pass.

Bonus challenge

Test the download and verify its content. PeakAndPack admin has an "Export products" link that downloads a CSV. This is a real end-to-end test of the export feature that cannot be done with an API test alone.

Accept and dismiss dialog tests

test('delete with confirmation removes the product', async ({ page }) => {
  await page.goto('https://peakandpack-ui.onrender.com/admin/products');
  const productName = await page.getByRole('article').first()
    .getByRole('heading').textContent();

  // Register BEFORE clicking
  page.once('dialog', dialog => dialog.accept());
  await page.getByRole('button', { name: /delete/i }).first().click();

  // Product should no longer appear
  await expect(page.getByText(productName!)).not.toBeVisible();
});

test('dismiss dialog keeps the product', async ({ page }) => {
  await page.goto('https://peakandpack-ui.onrender.com/admin/products');
  const productName = await page.getByRole('article').first()
    .getByRole('heading').textContent();

  // Dismiss instead of accept
  page.once('dialog', dialog => dialog.dismiss());
  await page.getByRole('button', { name: /delete/i }).first().click();

  // Product should still be there
  await expect(page.getByText(productName!)).toBeVisible();
});

Capturing the product name before the action is the key pattern here. After the delete, you need to know what to assert is gone. Reading the name before the action means you are asserting against real data, not a hardcoded string that might not match.
