Phase 6 of 8 · E2E Flows

E2E Flows, Analysed as a Whole Journey

Give it one journey's results. It verdicts every step and finds where the flow breaks, including the breaks no single step reveals.

By RN ~4 min read Series: AI-Augmented QA
Manual, No AI Manual + AI Automated, Playwright AI QA Agent

Phase 6 is about whole journeys, so this agent judges a whole journey. You give it the step-by-step results of one flow, what you did at each step and what actually happened, and it analyses the journey as a connected whole: where it first breaks, how that break ripples forward, and what a real customer would experience walking that exact path. It reasons from the results you give it; it does not run the flow itself.

What it does

  1. You give it one journey's results: each step, what you did, and what happened (a status code, a response body, or what appeared on screen). Optionally, the requirements too.
  2. It walks the steps in order and gives a verdict on each: pass, or fail with the reason.
  3. It names the first step where things diverge and traces how that ripples through the rest of the flow, then calls out the single most important cross-step issue and its customer impact.

How it works

Same mechanism as the earlier agents: your pasted flow results plus the system prompt go to Claude, and the analysis comes back. The design work is in the prompt, which tells the agent to judge the journey as a connected whole rather than step by step, and never to trust a status code alone.

Why "judge the whole journey" is the point. Every step in a flow can return 200 and the flow can still be broken, because the failure lives in how the steps connect. A discount that is right in the cart but wrong at checkout, an order history that returns 200 while showing another user's purchases: no single-step check catches these, but a flow-level read does. That instruction is the whole reason this agent exists.

How to build it: three forms

The agent ships in three forms, listed easiest-first. Same prompt, same kind of report; they differ only in how you hand over the flow results.

1Prompt only, no key, no code

The fastest path. Open e2e-trace-agent-prompt.md, paste the prompt into a Claude chat, then paste one journey's step-by-step results. Include the requirements if you have them. Claude replies with the flow analysis.

2Browser form, a reusable tool

A small web page that runs on your own machine.

  1. Download e2e-trace-agent.html and double-click it to open in your browser (it runs from file://, no host needed).
  2. Paste your Anthropic API key (console.anthropic.com → API Keys → Create Key).
  3. Paste your flow results into the text box (and the requirements, optionally), then click Analyse this flow.

Under the hood: the page sends your pasted text plus the system prompt straight to Anthropic with your key. Nothing is uploaded elsewhere and the key never leaves the tab.

3Node.js form, in a terminal

A script that reads a results file and writes the analysis to disk. It needs Node.js installed, nothing else; it is not Claude Code, the script calls the API itself. New to Node or Playwright? The Playwright Basics primer covers installing Node.

  1. Check Node.js: run node --version; if it errors, install the LTS build from nodejs.org.
  2. Get an API key from console.anthropic.com.
  3. Put two files in one folder: e2e-trace-agent.js and your saved results as flow-results.md.
  4. Set your key: export ANTHROPIC_API_KEY=sk-ant-your-key (Mac) or set ANTHROPIC_API_KEY=sk-ant-your-key (Windows).
  5. Run it: node e2e-trace-agent.js. It reads flow-results.md and writes e2e-trace-output.md.

How to tell if the agent actually read your flow

A flow analysis can sound convincing whether or not it used your specific results. Here is the check.

Trustworthy
It points at a concrete cross-step link in your data, "the cart showed $90 but the checkout charged $0," using the actual numbers you pasted. It could only say that by reading your results.
Warning sign
Generic flow advice that fits any shop ("test the full checkout path," "verify auth works") with nothing tied to the steps you gave it. If it never references a specific step or value from your results, it may not have used them.

Your deliverable

One file: e2e-trace-output.md, the agent's flow analysis after you confirm each verdict against the real journey. Same review discipline as every AI approach in this series: keep what is real, drop the generic, and confirm anything the agent marked uncertain before it counts.

Time: ~10 minutes per flow to analyse. Confirming the verdicts against the real journey is the work that keeps a human in the loop.
