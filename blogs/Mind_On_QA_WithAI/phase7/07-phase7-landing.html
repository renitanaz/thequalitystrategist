Bug Detection

Seven bugs were planted in PeakAndPack at the start of this series. This phase surfaces all of them, documents them properly, and asks which approach found what.

By RN AI-Augmented QA Series Live site: peakandpack-ui.onrender.com

This is the payoff phase. Every earlier phase planted a flag. Phase 3 wrote test cases designed to fail. Phase 4 captured visual bugs on screen. Phase 5 found the API contract violations. Phase 6 showed how the bugs feel end to end. Phase 7 brings them all together into a formal bug report set and asks the question the series has been building to: which approach caught what, and how early?

What this phase does

Phase 7 is not about running more tests. Every test that catches these bugs was already written in earlier phases. This phase is about formal documentation: turning a failing assertion or a screenshot into a proper bug report that a developer can act on, a stakeholder can understand, and a future tester can use to confirm the fix.

It also introduces the detection analysis: which approach caught which bug first, what it would have cost if each bug had reached production, and what the automated approach adds when bugs are fixed.
