Phase 7 of 8 · Bug Detection

Bug Detection, by Running the Tests

The tests designed to fail in Phases 3 to 6 are the bug detection suite. Run them. Read the output.

By RN ~5 min read Series: AI-Augmented QA
Manual, No AI Manual + AI Automated, Playwright AI QA Agent

The automated approach to bug detection is not a new set of tests. It's running the tests that were written in Phases 3, 4, 5, and 6 — tests that were designed to fail against the current build — and reading the output as a bug detection report.

This is why those tests were called "designed to fail." TC-101 (BUG-009), TC-104 (BUG-008), the visual baseline diffs (BUG-010, 011, 012), the orders isolation test (BUG-013), and the search contract test (BUG-014) were all written to pass against a correct implementation and fail against the current one. Running them now is bug detection in under 60 seconds.

Running the full detection suite

All tests from Phases 3–6 are tagged. Run only the ones targeting known bugs:

npx playwright test --grep "BUG-008|BUG-009|BUG-013|BUG-014"
npx playwright test tests/visual.spec.ts --update-snapshots=never

The second command runs the visual suite without re-baselining, so any diff from the stored baseline (captured in Phase 4) counts as a failure.

38 tests, 7 known failures, 31 passing. The 31 passing tests are not noise — they confirm that the rest of the system works correctly. The 7 failures are precisely the 7 planted bugs. Every failure is named, linked to a bug ID, and points to the exact file and line. A developer can go from this output to a fix without a meeting.

When a bug is fixed

This is the automation payoff. When a developer fixes BUG-009 (the discount logic), TC-101 turns green on the next run — automatically, with no changes to the test. The fix is verified the moment CI runs. No manual re-test needed. The same applies to every one of the seven bugs: fix the code, run the suite, watch the corresponding test pass.

Your deliverable

The CI output itself is the deliverable. Save it as bug-detection-report.txt — a snapshot of the full test run showing all 7 failures with their test names, file locations, and failure messages. This is the automated bug detection report.

Time: ~60 seconds to run the suite. The tests were already written in Phases 3–6.
