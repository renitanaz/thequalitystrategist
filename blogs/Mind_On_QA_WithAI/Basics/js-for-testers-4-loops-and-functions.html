JavaScript for Testers · Part 4 Loops Functions

Loops and Functions

Check every item in a list, not just the first one, and stop repeating yourself, explained for testers with a real product list.

Series: JavaScript for Testers Demo: PeakAndPack By: RN

Draft. Structured from study notes; every example still needs running during review.

Goal

  • Repeat code a set number of times with a for loop
  • Go through every item in a list with for...of
  • Check every item, count, and total as you go
  • Stop a loop early with break, and know when to avoid forEach
  • Write a check once as a function, and reuse it anywhere, even from other files

1. Why testers need this

A test that checks only the first product proves very little. PeakAndPack's product list has a negative price and a product with no name, and neither is first in the list. Loops let a test check every item, however many there are, with the same few lines. They also let you run one check across several inputs, such as the boundary values 0, 1, 4 and 5 from Part 3.

2. The counting loop: for

A for loop runs the same block of code a set number of times:

// Runs 5 times: i is 0, 1, 2, 3, then 4
for (let i = 0; i < 5; i++) {
  console.log('Checking product', i);
}
Explain this code, line by line
  • The round brackets hold three parts, separated by semicolons:
    • let i = 0 runs once, at the start: a counter called i, starting at 0. (i is the traditional name, short for "index".)
    • i < 5 is checked before every round. While it's true, the loop keeps going; once it's false, the loop ends.
    • i++ runs after every round. It adds 1 to i; it's short for i = i + 1.
  • The curly braces hold the body: the code that repeats.
  • It prints 0 to 4, not 1 to 5, and stops before 5 because 5 < 5 is false. That's five rounds, starting from 0, the same way array positions count (Part 2).
  • The counter must be let: i++ changes it, and a const can't change.

A loop that never ends. If the check can never become false, for example i-- (subtract 1) instead of i++, the loop runs forever and the terminal stops responding. Click in the terminal and press Ctrl+C to stop it.

3. Going through a list: for...of

Most loops in tests go through a list. for...of hands you each item in turn, with no counter to manage:

const products = [
  { name: 'Trekking Poles (Pair)', price: 34.99, stock: 50 },
  { name: '4-Season Tent', price: 320, stock: 15 },
  { name: 'Sleeping Bag (-15C)', price: -89, stock: 30 },
  { name: 'Headlamp', price: 24.99, stock: 0 },
  { name: '', price: 9.99, stock: 5 },
];

for (const product of products) {
  console.log(product.name, product.price);
}
Explain this code, line by line
  • products is an array of objects, the shape an API sends a product list in (Part 2).
  • for (const product of products) reads "for each product in products". Each round, product holds the next item: first the Trekking Poles, then the tent, and so on to the end.
  • You choose the name. product (singular) for an item of products (plural) keeps it readable.
  • const is fine here, because each round gets a fresh product rather than changing the old one.
  • The fifth product prints as a blank name and 9.99: it really has no name. That's one of PeakAndPack's seeded bugs.

When you need the position as well, use the counting loop with the list's length:

for (let i = 0; i < products.length; i++) {
  console.log(i, products[i].name); // 0 Trekking Poles (Pair), 1 4-Season Tent, ...
}
Explain this code, line by line
  • i < products.length stops after the last item: with 5 products, i goes 0 to 4.
  • products[i] is the item at position i.
  • Using <= here is the classic mistake: the last round asks for products[5], which doesn't exist, and .name fails with "Cannot read properties of undefined" (Part 2).

4. Checking, counting and totalling as you go

Put a condition inside the loop, and it checks every item. Keep a variable outside the loop, and you can count or add up as you go:

let inStockCount = 0;
let total = 0;

for (const product of products) {
  // Check every item against the rules
  if (product.price < 0) {
    console.log('Negative price:', product.name);
  }
  if (product.name === '') {
    console.log('Product with no name, priced', product.price);
  }

  // Count and total as you go
  if (product.stock > 0) {
    inStockCount++;
  }
  total += product.price;
}

console.log('In stock:', inStockCount); // 4
console.log('Total:', total);           // 300.97
Explain this code, line by line
  • The two if checks run for every product, so both of PeakAndPack's bugs are reported, wherever they sit in the list.
  • inStockCount and total are created before the loop, with let, so they keep their values between rounds. Created inside, they'd start again from 0 every round.
  • inStockCount++ adds 1 each time a product has stock. The Headlamp has 0, so the count is 4.
  • total += product.price is short for total = total + product.price.

Decimals don't add exactly. 34.99 + 24.99 gives 59.980000000000004. Computers store decimals in binary, which can't hold most of them exactly. Round before comparing money: total.toFixed(2) (Part 1), or compare amounts in cents.

Notice too that the total includes the Sleeping Bag's -89. Bad data doesn't just fail its own check: it quietly distorts every number calculated from it.

5. Stopping early: break

Once you've found what you're looking for, there's no need to check the rest. break leaves the loop straight away:

for (const product of products) {
  if (product.price < 30) {
    console.log('First product under $30:', product.name);
    break; // stop: no need to check the rest
  }
}
// First product under $30: Sleeping Bag (-15C)
Explain this code, line by line
  • break ends the whole loop immediately; the code after the loop runs next.
  • The answer is the Sleeping Bag, not the Headlamp: -89 is less than 30. The bad price has corrupted a search that has nothing to do with prices being valid.

6. forEach: the other way you'll see

Lists also have a built-in forEach, which you'll see in a lot of JavaScript:

products.forEach((product) => {
  console.log(product.name);
});
Explain this code, line by line
  • products.forEach(...) runs the code inside the brackets once for each item.
  • (product) => { ... } is a short way to write a function: a named-later block of code that receives the current item as product. Functions are the next section of this page.
  • It prints the same names as the for...of loop above.

In Playwright tests, prefer for...of. Test steps use await to wait for the browser (Phase 0). forEach doesn't wait for await inside it: it starts every item at once and moves on, so the test can finish before the checks run. for...of waits for each round. Part 6 explains why.

7. Functions: write a check once, use it everywhere

The price rule from section 4 will be needed in many tests. Copying it into each one means fixing every copy when the rule changes. A function gives a piece of work a name, so you write it once and call it wherever it's needed:

// Create the function once
function isValidPrice(price) {
  return price >= 0;
}

// Call it as often as you like
console.log(isValidPrice(34.99)); // true
console.log(isValidPrice(-89));   // false
Explain this code, line by line
  • function isValidPrice(price) { ... } creates a function: the keyword function, a name, round brackets, then the body in curly braces. Creating it doesn't run it.
  • price in the brackets is a parameter: a placeholder name for the value the function will be given.
  • return price >= 0; works out the answer and hands it back to whoever called the function. return also ends the function: nothing after it runs.
  • isValidPrice(34.99) calls the function. The value in the brackets is the argument: inside the function, price becomes 34.99. The call is replaced by the answer, true.
  • Name functions after what they answer or do. A function giving true or false often starts with is or has.

Functions can take several values, separated by commas, and can be used inside loops and other functions:

function describe(name, price) {
  return `${name}: $${price.toFixed(2)}`;
}

for (const product of products) {
  if (!isValidPrice(product.price)) {
    console.log('Invalid price:', describe(product.name, product.price));
  }
}
// Invalid price: Sleeping Bag (-15C): $-89.00
Explain this code, line by line
  • describe(name, price) has two parameters. Arguments are matched by position: the first value goes to name, the second to price.
  • !isValidPrice(product.price) calls the function and flips the answer: "if the price is not valid".
  • The loop now reads almost like the business rule. If the rule changes, say prices must be above 0, you change one line inside isValidPrice, and every test using it follows.

return versus console.log. Printing an answer isn't the same as giving it back. A function that ends with console.log(result) instead of return result shows the answer in the terminal, but hands back undefined, so const ok = check(5) gets nothing. The same happens if you forget the return line altogether.

Missing arguments. Call describe('Tent') with only one value, and price is undefined inside the function. price.toFixed(2) then fails with Cannot read properties of undefined (reading 'toFixed'): the same error as in Part 2, from a different cause.

8. Three ways to write a function

You'll meet three styles. They do the same job; the third is the one you'll see most in tests:

// 1. A function declaration
function double(n) {
  return n * 2;
}

// 2. A function stored in a variable (a function expression)
const triple = function (n) {
  return n * 3;
};

// 3. An arrow function
const square = (n) => {
  return n * n;
};

// An arrow function that only returns can be shortened to one line
const half = (n) => n / 2;

console.log(double(5), triple(5), square(4), half(9)); // 10 15 16 4.5
Explain this code, line by line
  • Declaration: function name() {}, as in section 7.
  • Function expression: a function with no name of its own, stored in a const. You call it by the variable's name.
  • Arrow function: (n) => { ... }, read as "takes n, then does this". No function keyword.
  • The one-line arrow: with no curly braces, the value after => is returned automatically, so there's no return to write.
  • You already know this shape from Playwright: test('name', async ({ page }) => { ... }) passes an arrow function to test. The async is Part 6.

One difference that matters: when you can call it. A declaration can be called from anywhere in the file, even above where it's written. A function stored in a const can only be called after its line has run:

console.log(greet('Ana')); // works: declarations are ready from the start
function greet(name) {
  return `Hello, ${name}`;
}

console.log(shout('Ana')); // ReferenceError: Cannot access 'shout' before initialization
const shout = (name) => `HELLO, ${name}`;
Explain this code, line by line
  • JavaScript prepares all function declarations before running the file, so greet exists from the first line. This is called hoisting.
  • shout is a const, which only gets its value when its line runs. Calling it earlier fails with "Cannot access 'shout' before initialization".
  • Simplest habit: define functions above the code that uses them, whichever style you choose.

9. Sharing functions between files

A check written once is most useful when every test file can use it. Put shared functions in their own file, export them there, and import them where they're needed:

// helpers/product-checks.js
export function isValidPrice(price) {
  return price >= 0;
}

export const formatPrice = (price) => `$${price.toFixed(2)}`;
// audit.js, in the folder above helpers
import { isValidPrice, formatPrice } from './helpers/product-checks.js';

console.log(isValidPrice(-89), formatPrice(89)); // false $89.00

// Or bring in everything from the file under one name
import * as checks from './helpers/product-checks.js';
console.log(checks.formatPrice(24.99)); // $24.99
Explain this code, line by line
  • export in front of a function makes it available to other files. Without it, the function stays private to its own file.
  • import { isValidPrice, formatPrice } from '...' brings in the named functions. The names in the curly braces must match the exported names.
  • './helpers/product-checks.js' is the path from this file: ./ means "this folder". Include the .js ending, or Node can't find the file.
  • import * as checks brings in everything the file exports, as one object: you then call checks.formatPrice(...), with a dot, like reading a key (Part 2).
  • You've seen this before: every Playwright test starts with import { test, expect } from '@playwright/test';. That's the same thing, importing from a package instead of your own file.

"Cannot use import statement outside a module"? Plain Node.js needs to be told that your files use import. Add "type": "module" to your practice folder's package.json:

{
  "name": "js-practice",
  "type": "module"
}

Your Playwright project doesn't need this: Playwright handles imports in test files itself.

Common mistakes.

  • <= with a list's length. The last round reads past the end. Use i < list.length.
  • Checking only the first item. Bugs hide in the middle of lists. Loop over all of them.
  • Creating a counter or total inside the loop. It resets every round. Create it before the loop.
  • Comparing decimal totals exactly. Round with toFixed(2) first.
  • forEach with await inside. It doesn't wait. Use for...of.
  • Printing instead of returning. A function without return hands back undefined.
  • Calling a const function before its line. "Cannot access ... before initialization".
  • Forgetting export, or the .js in an import path. The import fails to find what you asked for.
Exercise

Audit the product list

Create exercise-loops.js, start it with the products list from section 3, write code for each step, and run it with node exercise-loops.js:

  1. With a for loop, print "Check 1" to "Check 3". (Careful: the counter starts at 0.)
  2. With for...of, print each product's name and price.
  3. With a counting loop and length, print each product's position and name.
  4. In one loop, report every product with a negative price, and every product with no name.
  5. Count the products in stock, and add up all the prices. Print the count, and the total with two decimals.
  6. Print 34.99 + 24.99. Why isn't it 59.98, and how would you compare it safely?
  7. Find the first product under $30 with break. Is the answer the one you expected? Why not?
  8. Print every name again with forEach.
  9. Break it on purpose, one at a time: change the step 3 loop to <=; change a counter's let to const. Read each error. (Don't run a loop with i--: it never ends. If you do, press Ctrl+C.)
  10. Write a function isValidPrice(price) that returns whether a price is 0 or more. Call it with 34.99 and -89.
  11. Write describe(name, price) that returns text like Headlamp: $24.99. Use both functions in a loop to report every invalid price.
  12. Write printOnly(price) that only console.logs the price. Store printOnly(5) in a variable and print it. What do you get, and why?
  13. Rewrite isValidPrice as a one-line arrow function called isValidPriceArrow, and check it gives the same answers.
  14. Call describe('Tent'), with one argument. Read the error: which value was missing?
  15. Call a declaration above its definition, then a const arrow function above its definition. Which works?
  16. Move isValidPrice and describe into helpers/product-checks.js, export them, and import them into your exercise file, first by name, then with import * as. (Add "type": "module" to package.json first.)

const products = [
  { name: 'Trekking Poles (Pair)', price: 34.99, stock: 50 },
  { name: '4-Season Tent', price: 320, stock: 15 },
  { name: 'Sleeping Bag (-15C)', price: -89, stock: 30 },
  { name: 'Headlamp', price: 24.99, stock: 0 },
  { name: '', price: 9.99, stock: 5 },
];

// 1. The counter starts at 0, so print i + 1
for (let i = 0; i < 3; i++) {
  console.log(`Check ${i + 1}`);
}

// 2. Every item in turn
for (const product of products) {
  console.log(product.name, product.price);
}

// 3. Position and item
for (let i = 0; i < products.length; i++) {
  console.log(i, products[i].name);
}

// 4. Check every item against the rules
for (const product of products) {
  if (product.price < 0) {
    console.log('Negative price:', product.name);
  }
  if (product.name === '') {
    console.log('No name, priced', product.price);
  }
}

// 5. Count and total, created before the loop
let inStockCount = 0;
let total = 0;
for (const product of products) {
  if (product.stock > 0) {
    inStockCount++;
  }
  total += product.price;
}
console.log('In stock:', inStockCount, 'Total:', total.toFixed(2));

// 6. Decimals don't add exactly: round before comparing
console.log(34.99 + 24.99, (34.99 + 24.99).toFixed(2) === '59.98');

// 7. Stop at the first match
for (const product of products) {
  if (product.price < 30) {
    console.log('First under $30:', product.name);
    break;
  }
}

// 8. forEach
products.forEach((product) => {
  console.log(product.name);
});

// 9. Break it on purpose (one at a time)
// for (let i = 0; i <= products.length; i++) { console.log(products[i].name); }
//   -> TypeError: Cannot read properties of undefined (reading 'name')
// for (const i = 0; i < 3; i++) { console.log(i); }
//   -> prints 0, then TypeError: Assignment to constant variable.

// 10. A function that answers a question
function isValidPrice(price) {
  return price >= 0;
}
console.log(isValidPrice(34.99), isValidPrice(-89));

// 11. Two parameters, reused in a loop
function describe(name, price) {
  return `${name}: $${price.toFixed(2)}`;
}
for (const product of products) {
  if (!isValidPrice(product.price)) {
    console.log('Invalid price:', describe(product.name, product.price));
  }
}

// 12. Printing is not returning
function printOnly(price) {
  console.log('Price is', price);
}
const result = printOnly(5);
console.log('printOnly gave back:', result);

// 13. The same check as a one-line arrow function
const isValidPriceArrow = (price) => price >= 0;
console.log(isValidPriceArrow(34.99), isValidPriceArrow(-89));

What to notice.

  • Step 1: the counter runs 0, 1, 2, so the message uses i + 1 to read naturally.
  • Step 4 finds both seeded bugs, the negative price and the missing name, because the loop checks every product, not just the first.
  • Step 6: toFixed(2) gives the text '59.98', which compares cleanly.
  • Step 7 answers "Sleeping Bag": its broken price is under $30. One bad value can mislead checks that aren't about it at all.
  • Step 12: printOnly prints "Price is 5", but gives back undefined: it never returns anything.
  • Step 14: the missing second argument makes price undefined inside describe, so .toFixed fails.
  • Step 15: the declaration works above its definition; the const doesn't, because it has no value until its line runs.
  • Step 9: <= reads one past the end; a const counter can't be increased. The const loop prints 0 first, because the error only happens at i++, after the first round.
