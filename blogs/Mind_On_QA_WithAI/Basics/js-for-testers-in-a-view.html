JavaScript for Testers · In a View Mind Map Cheat Sheet

JavaScript for Testers, in a View

Every part on one page: a map of how the topics fit together, and a cheat sheet to keep open while you write tests.

Draft. All six parts are drafted and linked from the map.

JavaScript first, TypeScript at the end. Part 5 is TypeScript, the language the Playwright series is written in. TypeScript is JavaScript with labels added, so JavaScript is the easier path to learn first: you pick up the basics without the labels, then add them once the basics feel familiar.

The map

Values are what a test holds, data shapes are how they're grouped, and checks are what a test does with them. Click a part to open it.

Part 1: Values

CodeWhat it doesWatch out
const total = 0;A value that can't be replaced. The default in tests.Must get a value when created.
let price = 34.99;
price = 29.99;		A value that can be replaced.Never use var.
'text' 34.99 true null undefinedThe five everyday types: string, number, boolean, deliberately empty, never set.Quotes make it text: '34.99' isn't a number.
typeof valueThe type's name, as text.typeof null is 'object': check with === null.
'Total: ' + priceJoins text.Spaces go inside the quotes.
`Total: ${price}`Template literal: drops values into text.Needs backticks, not quotes.
price.toFixed(2)A number as text with two decimals.Gives text, not a number.
`test-${Date.now()}@example.com`A unique value every run.
'89.00' + 1Gives '89.001': if either side is text, + joins.Convert page text before doing arithmetic.

Part 2: Data shapes

CodeWhat it doesWatch out
const p = { name: 'Tent', price: 320 };An object: related values, each with a key.Contents can change even with const.
p.name   p['name']Read a value: dot or bracket notation.A misspelled key gives undefined, not an error.
h['Content-Type']   p[field]Brackets for keys with dashes, or a key held in a variable.p[name] without quotes reads a variable.
p.price = 300;   p.tag = 'new';Change a value, or add a key.
const list = ['a', 'b', 'c'];An array: an ordered list.
list[0]   list.length   list[list.length - 1]First item, how many, last item.Counting starts at 0. Past the end gives undefined.
body.products[0].nameNested data, read left to right.Cannot read properties of undefined: the step before is missing.

Part 3: Checks

CodeWhat it doesWatch out
> < >= <=Compare numbers; the answer is true or false.> vs >= differ only at the boundary.
===   !==Same value and type / different.Avoid ==: 0 == '' is true.
Number('89.00')Text to number.'$34.99' gives NaN; '' gives 0.
objA === objBIs it the very same object?Same contents still false: use toEqual in tests.
a && b   a || b   !aAND (all true), OR (any true), NOT (flip).&& runs before ||: add brackets.
false 0 '' null undefined NaNThe falsy values; everything else counts as true.'0' is true-like: it's non-empty text.
!!value   a || 'default'Any value to true/false; a fallback value.0 || 1 is 1: a real 0 is replaced.
if (...) {} else if (...) {} else {}Run one block: the first whose condition is true.Put the most specific condition first.
isCI ? 2 : 0One-line if/else that gives back a value.
if around a test's checksSkips the check when false.The test passes without checking anything.

Part 4: Repeat and reuse

CodeWhat it doesWatch out
for (let i = 0; i < 5; i++) { }Repeat a block: start, check, run, step.Counts from 0. The counter must be let.
for (const item of list) { }Each item of a list, in turn.The usual loop in tests.
for (let i = 0; i < list.length; i++)Each position and item.<= reads one past the end.
count++   total += xAdd 1; add to a running total.Create them before the loop.
0.1 + 0.2Gives 0.30000000000000004.Round money with toFixed(2) before comparing.
breakLeave the loop now.
list.forEach((item) => { })Run a function for each item.Doesn't wait for await: use for...of in tests.
A loop that never endsThe check never becomes false.Ctrl+C in the terminal stops it.
function f(x) { return x * 2; }Write work once, call it anywhere: f(5).Without return, it gives back undefined.
const f = (x) => x * 2;Arrow function; one line returns automatically.Can't be called above its line.
export / import { f } from './f.js'Share functions between files.Keep the .js; plain Node needs "type": "module".

new Cart('Ana')Build an instance with its own values.Without new: TypeError.
export class CartPageShare a class: the page-object pattern.Each test builds its own instance.
let price: number   type Product = {...}Types: on values, and your own shapes.? marks a property optional.

Part 6: Waiting

CodeWhat it doesWatch out
const p = page.goto('/');A promise: an answer that arrives later.Printed, it shows Promise { <pending> }: a missing await.
await page.goto('/')Wait for it to settle, then carry on.Only inside async functions (or a module's top level).
async function f() { return 1; }Can use await; always returns a promise.Its TypeScript type is Promise<number>.
try { await x; } catch (e) { e.message }Handle a rejected promise.Don't use it to keep a failing test going.
const r = page.waitForResponse(...), then click, then await rStart a wait before the action.No await on the first line, on purpose.
for (const x of list) { await ... }One at a time, in order.forEach doesn't wait.
await Promise.all([a, b])Several at once; wait for all.Only for independent work.
