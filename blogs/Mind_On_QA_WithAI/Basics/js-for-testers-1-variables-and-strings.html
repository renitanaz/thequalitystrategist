JavaScript for Testers · Part 1 Variables Constants Data Types Strings

Variables, Data Types and Strings

The building blocks every Playwright test is made of, explained for testers, with examples from a real store's test suite.

Series: JavaScript for Testers Demo: PeakAndPack By: RN

Draft. Structured from study notes; every example still needs running during review.

Goal

  • Run a JavaScript file on your own computer with Node.js
  • Store values with const and let, and know which to use
  • Tell the five everyday data types apart, and check a value's type
  • Build text from values with + and with template literals
  • Check and tidy text with includes, replace and trim
  • Read the three errors beginners hit most with variables

1. Why testers need this

A Playwright test is JavaScript (strictly, TypeScript, which is JavaScript with extra checks). Every test stores things while it runs: the product it's checking, the price it read from the page, whether the order went through. Variables are how it holds them, and data types decide what you can do with them. A price read as text can't be compared with a number, which is a classic cause of tests that fail for no visible reason.

You don't need to become a developer. You need enough to read a test, change it with confidence, and understand its error messages.

JavaScript first, TypeScript at the end. The Playwright series is written in TypeScript, and this series gets you there in Part 5. TypeScript is JavaScript with labels added, so JavaScript is the easier path to learn first: you pick up the basics without the labels, then add them once the basics feel familiar.

2. Running JavaScript on your computer

Browsers run JavaScript inside web pages. Node.js runs it directly on your computer, which is how Playwright runs your tests. Make a practice folder, open it in VS Code, create a file called hello.js, and add one line:

// Prints a message in the terminal
console.log('Hello, PeakAndPack');
Explain this code, line by line
  • // starts a comment: a note for people, which the computer ignores.
  • console.log(...) prints whatever is inside the brackets in the terminal. It's how you'll look at values while learning, and how you'll check what a test sees when it misbehaves.
  • 'Hello, PeakAndPack' is text in quote marks, called a string (section 5).
  • ; ends the instruction, like a full stop ends a sentence.

Then run it from VS Code's terminal (Terminal → New Terminal):

# Tell Node.js to run the file
node hello.js
Explain this code, line by line
  • node starts Node.js, and hello.js is the file to run. The terminal must be in the folder that holds the file; cd moves you there.
  • What you'll see: Hello, PeakAndPack, printed on the next line.

3. Variables: values that can change

A variable is a named box that holds a value while the code runs. When the code finishes, the box is gone. You create one with let, and you can put a new value in it later:

// Create a variable called price, holding 34.99
let price = 34.99;
console.log(price); // 34.99

// Put a new value in the same box
price = 29.99;
console.log(price); // 29.99
Explain this code, line by line
  • let price = 34.99;: let creates the variable, price is its name, and = puts a value in it. Read = as "becomes", not "equals": it stores a value, it doesn't compare.
  • price = 29.99; replaces the value. No let the second time: the box already exists.
  • // 34.99 after a line is a comment showing what it prints.
  • Names: no spaces, can't start with a digit, and they're case-sensitive (price and Price are different boxes). The convention is camelCase: productName, isOrderConfirmed.

You can also create a variable without a value and fill it later. Until you do, it holds undefined (section 5).

You'll see var in older tutorials. Don't use it. It also creates a variable, but with older rules about where it can be seen, which cause bugs that are hard to find. Modern code, including every Playwright example, uses let and const.

4. Constants: values that can't change

A constant is a box whose value is fixed once set. You create it with const, and it must get its value straight away:

// The product's name won't change while the test runs
const productName = 'Trekking Poles (Pair)';
console.log(productName);

// productName = 'Tent';  // would fail: TypeError: Assignment to constant variable.
// const supplier;        // would fail: SyntaxError: Missing initializer in const declaration
Explain this code, line by line
  • const productName = '...'; works like let, except the value can't be replaced afterwards.
  • The two commented-out lines show what's not allowed. Remove the // from one at a time and run the file to see the error for yourself.
  • Why it helps: a constant tells anyone reading the test "this won't change", and the computer enforces it, so a value can't be overwritten by accident halfway through a test.

In tests, const is the default. Use const unless you know the value will change, then let. That's why Playwright code is full of lines like const card = page.getByTestId('product-card');.

5. Data types: what kind of value it is

Every value has a type, and the type decides what you can do with it. You can do arithmetic with a number but not with text, even if the text looks like a number. These five cover almost everything in tests:

TypeExampleWhere you meet it in tests
string: text, in quotes'Trekking Poles (Pair)'Names, URLs, messages, and anything read from a page. A price read from a page, '$34.99', is a string.
number34.99Prices, counts, quantities.
booleantrue / falseYes/no answers: is the item in stock, did the order go through.
nullnull"Deliberately empty": a field an API sends with no value.
undefinedundefined"Nothing was ever put here": often a sign of a misspelled name.

Text can sit in single quotes or double quotes: 'Headlamp' and "Headlamp" are the same string. Pick one style and stay with it. This series uses single quotes.

typeof tells you a value's type, which is handy when a test behaves strangely:

const productName = 'Headlamp';
const price = 24.99;
const inStock = true;
const discountCode = null;   // deliberately no code
let reviewRating;            // never given a value

console.log(typeof productName);  // 'string'
console.log(typeof price);        // 'number'
console.log(typeof inStock);      // 'boolean'
console.log(typeof discountCode); // 'object'  ← a famous quirk
console.log(typeof reviewRating); // 'undefined'
console.log(typeof '24.99');      // 'string': quotes make it text
Explain this code, line by line
  • typeof value gives back the type's name, as text.
  • Quotes decide the type. 24.99 is a number; '24.99' is a string, even though they look the same.
  • typeof null says 'object'. That's a mistake from JavaScript's very first version, kept so old websites don't break. To check for null, compare directly: value === null (part 3).
  • undefined versus "not defined". let reviewRating; creates a box with nothing in it, so it holds undefined. A name that was never created at all is a different problem: console.log(rating) stops with ReferenceError: rating is not defined.
  • JavaScript has two more types, bigint and symbol. You won't need them for testing.

6. Strings: building text from values

Tests build text all the time: a message to check for, a web address, a unique email for a new test user. Usually part of the text is fixed and part comes from a variable. There are two ways to join them.

Joining with + (called concatenation): break the text into pieces and add them together.

const itemName = 'Headlamp';
const price = 24.99;

// Fixed text + variable + fixed text + variable
const message = 'The price of the ' + itemName + ' is $' + price;
console.log(message); // The price of the Headlamp is $24.99
Explain this code, line by line
  • Between two pieces of text, + joins them into one longer piece of text.
  • The spaces are part of the fixed text: 'The price of the ' ends with a space, and ' is $' starts with one. Leave them out and you get The price of theHeadlampis $24.99, the most common concatenation slip.
  • price is a number, but joined with text, it becomes text too.

Template literals (also called interpolation): write the whole sentence once, between backticks, and drop the variables in with ${...}.

const itemName = 'Headlamp';
const price = 24.99;

// One piece of text, with the variables dropped in
const message = `The price of the ${itemName} is $${price}`;
console.log(message); // The price of the Headlamp is $24.99

// Anything inside ${} is worked out first
console.log(`Two cost $${(price * 2).toFixed(2)}`); // Two cost $49.98
Explain this code, line by line
  • Backticks, `, not quote marks. On most keyboards the backtick sits to the left of the 1 key. With ordinary quotes, ${itemName} would print literally.
  • ${itemName} means "put the value of itemName here".
  • $${price}: the first $ is just a dollar sign in the sentence; ${price} drops in the value.
  • Inside ${} you can put any calculation. price * 2 doubles the price (* means multiply).
  • .toFixed(2) turns a number into text with exactly two decimals, so 89 shows as 89.00. Handy for prices, because numbers drop trailing zeros.

Both give exactly the same result. Template literals are easier to read and harder to get the spaces wrong in, so modern test code mostly uses them, especially for the jobs below.

// A unique email for every test run, so new test users never clash
const email = `test-${Date.now()}@example.com`;

// A web address built from a fixed base
const API = 'https://peakandpackshopdemo.onrender.com';
const cartUrl = `${API}/api/cart`;

console.log(email);   // test-1790830940302@example.com (the number changes every run)
console.log(cartUrl); // https://peakandpackshopdemo.onrender.com/api/cart
Explain this code, line by line
  • Date.now() gives the number of milliseconds since 1 January 1970, so it's different every time the test runs. Putting it in an email makes each run's test user unique. The Playwright series uses this in Phase 5.
  • `${API}/api/cart` builds an address from a base kept in one place. Change the base, and every address built from it follows.

The + trap. + adds numbers, but joins text, and if either side is text, it joins. So 89 + 1 is 90, but '89.00' + 1 is '89.001'. A price read from a page is text (section 5), so adding to it without converting it first gives nonsense, quietly.

7. Text helpers: checking and tidying text

Tests read text from a page or a response, then ask questions about it: does this address contain /api/cart? Remove the $ from this price. Cut the stray spaces off this label. Text comes with built-in helpers for exactly this. You call one with a dot after the value, the way .toFixed(2) worked on a number in section 6.

HelperWhat it doesExampleResult
includes('x')Is this piece of text inside?'Camping Stove'.includes('Stove')true
replace('a', 'b')Swaps the first match for other text'$89.00'.replace('$', '')'89.00'
trim()Cuts spaces and line breaks off both ends' Headlamp '.trim()'Headlamp'
toLowerCase()Turns every letter into a small one'TENT'.toLowerCase()'tent'
split(',')Cuts the text into a list at every comma'a,b'.split(',')['a', 'b']
slice(0, 4)Takes a piece, by position'Camping'.slice(0, 4)'Camp'
 
const url = 'https://peakandpackshopdemo.onrender.com/api/cart';
console.log(url.includes('/api/cart')); // true
console.log(url.includes('/API/cart')); // false: capital letters count

const priceText = '$89.00';
const withoutSymbol = priceText.replace('$', '');
console.log(withoutSymbol);        // 89.00
console.log(typeof withoutSymbol); // string: still text
console.log(priceText);            // $89.00: the original is unchanged

const typed = '  Headlamp \n';
console.log(`[${typed.trim()}]`);  // [Headlamp]

console.log('Camping'.toLowerCase());      // camping
const categories = 'Camping,Trekking,Climbing';
console.log(categories.split(','));        // [ 'Camping', 'Trekking', 'Climbing' ]
console.log('Trekking Poles'.slice(0, 8)); // Trekking
Explain this code, line by line
  • url.includes('/api/cart') answers true or false: is that piece of text anywhere inside the address? It is case-sensitive, so '/API/cart' is not the same and answers false. Playwright tests use this a lot, to pick out one request among many: response.url().includes('/api/cart').
  • priceText.replace('$', '') gives back new text with the first $ swapped for nothing (two quotes with nothing between them). Text can't be changed in place, so priceText still holds '$89.00', and you keep the new text in its own constant.
  • typeof withoutSymbol is 'string'. Removing the $ leaves '89.00', which looks like a number but is still text, so the + trap from section 6 still applies. Part 3 shows how to turn it into a real number.
  • typed.trim() cuts the spaces and the line break (\n) off both ends. The square brackets in the template literal only show where the text now starts and ends.
  • categories.split(',') breaks one piece of text into a list of three, cutting at every comma. Lists are Part 2.
  • slice(0, 8) takes the characters from position 0 up to, but not including, position 8. Positions start at 0, just like list positions in Part 2.

One more you will meet: replace only swaps the first match. 'a-b-c'.replace('-', '') gives 'ab-c'. To swap every match, use replaceAll: 'a-b-c'.replaceAll('-', '') gives 'abc'.

Common mistakes.

  • Comparing a price read from a page with a number. '89.00' and 89 aren't equal in a strict comparison. Convert the text first; Phase 3 of the Playwright series shows how.
  • Using let for everything. It works, but it hides which values are meant to stay fixed. Default to const.
  • Forgetting spaces when joining with +. 'Total:' + price prints Total:24.99. Template literals make this harder to get wrong.
  • Ordinary quotes around a template. 'Hi ${name}' prints the ${name} literally. Templates need backticks.
  • Reading undefined as "the app is broken". Check your own spelling first: a misspelled name is the most common cause.
  • Expecting includes to ignore capital letters. 'Stove'.includes('stove') is false. Make both sides the same case first, for example with toLowerCase().
  • Expecting replace to change the original. It returns new text and leaves the original alone, and it swaps only the first match. Keep the result in a constant.
Exercise

Build a product record, and its messages

You're checking a PeakAndPack product before writing a test. Create exercise-variables.js, write code for each step, and run it with node exercise-variables.js:

  1. Start the file with a comment saying what it does.
  2. Store the product's name, Sleeping Bag (-15C), and its category, Camping, in values that can never change.
  3. Store its price, -89.00, in a variable: you're about to correct it.
  4. Store whether it's in stock (it is).
  5. Store its discount code. There deliberately isn't one.
  6. Create a variable for its review rating, without a value.
  7. Print all six values on one line with console.log.
  8. The price is a known bug. Set it to 89.00 and print it again.
  9. Reviews are in: give the review rating a value of 4.5, and print it.
  10. Print the type of each of the six values. Before you run it, predict what the discount code's type will be.
  11. Create priceFromPage = '89.00', the way a price looks when read from a web page, and print its type.
  12. Using +, build and print: Sleeping Bag (-15C) costs $89. Check your spaces.
  13. Build the same sentence with a template literal, this time showing the price with two decimals: Sleeping Bag (-15C) costs $89.00.
  14. Build a unique test email like test-1790830940302@example.com. Run the file twice: does it change?
  15. Predict, then print: price + 1 and priceFromPage + 1. Why are they different, and why does this matter in a test?
  16. Create priceText = '$89.00', the way a price looks on the page. Print it with the $ removed using replace, the type of that result, and whether priceText includes a $.
  17. Print ' Sleeping Bag (-15C) ' with the spaces trimmed off both ends, inside square brackets so you can see where the text starts and stops.
  18. Break it on purpose, one at a time, and read each error: change the product's name; create a const with no value; print a variable you never created; print ProductName, with a capital P.
Show solution: try it yourself first 
// 1. A comment: checks a product's details before writing a test

// 2. Constants: these never change
const productName = 'Sleeping Bag (-15C)';
const category = 'Camping';

// 3. A variable: the price is about to be corrected
let price = -89.00;

// 4. Boolean
const inStock = true;

// 5. Null: deliberately no discount code
const discountCode = null;

// 6. Undefined: created, never given a value
let reviewRating;

// 7. Print all six
console.log(productName, category, price, inStock, discountCode, reviewRating);

// 8. Allowed, because price is a let
price = 89.00;
console.log('Corrected price:', price);

// 9. A variable created empty can be filled later
reviewRating = 4.5;
console.log('Rating:', reviewRating);

// 10. Types
console.log(typeof productName, typeof category, typeof price,
            typeof inStock, typeof discountCode, typeof reviewRating);

// 11. A price read from a page is text
const priceFromPage = '89.00';
console.log(typeof priceFromPage);

// 12. Joining with +: the spaces live inside the quotes
console.log(productName + ' costs $' + price);

// 13. Template literal, price shown with two decimals
console.log(`${productName} costs $${price.toFixed(2)}`);

// 14. A unique email: Date.now() changes every run
console.log(`test-${Date.now()}@example.com`);

// 15. + adds numbers, but joins text
console.log(price + 1, priceFromPage + 1);

// 16. Text helpers: a price as it looks on the page
const priceText = '$89.00';
console.log(priceText.replace('$', ''), typeof priceText.replace('$', ''), priceText.includes('$'));

// 17. trim() cuts the spaces off both ends
console.log(`[${'  Sleeping Bag (-15C) '.trim()}]`);

// 18. Break it on purpose (remove the // from one line at a time)
// productName = 'Tent';     // TypeError: Assignment to constant variable.
// const supplier;           // SyntaxError: Missing initializer in const declaration
// console.log(rating);      // ReferenceError: rating is not defined
// console.log(ProductName); // ReferenceError: ProductName is not defined

Output (the email's number will differ):

Corrected price: 89
Rating: 4.5
string string number boolean object number
string

90 89.001

What to notice.

  • The review rating's type changed, from undefined to number, once step 9 gave it a value. A variable's type is whatever it holds right now.
  • -89.00 prints as -89, because numbers don't keep trailing zeros. Step 13's .toFixed(2) brings them back for display.
  • The discount code's type is object, JavaScript's typeof null quirk. Check for null with === null.
  • Step 15: price + 1 adds, giving 90. priceFromPage + 1 joins, giving '89.001', because one side is text. A test that adds to a price read from the page, without converting it, gets nonsense and doesn't complain.
  • Step 16: replace removes the $, but the result, '89.00', is still a string. Only a real number can be added to or compared with another number.
  • Step 18 shows three kinds of error: a constant can't change (TypeError), a constant must start with a value (SyntaxError, which stops the file before anything runs), and a name that doesn't exist (ReferenceError). ProductName fails because names are case-sensitive.
