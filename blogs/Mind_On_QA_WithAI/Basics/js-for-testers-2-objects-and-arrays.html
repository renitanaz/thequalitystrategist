JavaScript for Testers · Part 2 Objects Arrays Test Data

Objects and Arrays

The two shapes almost all test data comes in, from a single product to a whole API response, explained for testers.

Series: JavaScript for Testers Demo: PeakAndPack By: RN

Draft. Structured from study notes; every example still needs running during review.

Goal

  • Group related values in an object, and read or change them
  • Keep an ordered list in an array, and pick items by position
  • Read data nested several levels deep, the way API responses arrive
  • Recognise the error you'll see most often when data isn't where you expected

1. Why testers need this

Part 1 stored one value per variable. Real test data comes in groups: a product has a name, a price and a stock level; a cart holds a list of products. When a test asks PeakAndPack's API for its products, the answer arrives as a list of product records. Objects hold the records, arrays hold the lists, and reading them confidently is most of the work in API tests.

2. Objects: related values under one name

An object groups values that belong together, each with a label:

// One product, as a single object
const product = {
  name: 'Headlamp',
  price: 24.99,
  inStock: true,
};

console.log(product);      // { name: 'Headlamp', price: 24.99, inStock: true }
console.log(product.name); // Headlamp
Explain this code, line by line
  • Curly braces { } make an object.
  • Inside, each entry is a key and a value: name: 'Headlamp'. The key is the label, the value is what it holds, and a colon separates them. Entries are separated by commas.
  • Values can be any type from Part 1: text, numbers, true/false, even other objects and lists.
  • The comma after the last entry is optional. Many people leave it in, so adding another line later doesn't need a comma fix.
  • product.name reads one value: "the name of product". In VS Code, typing product. pops up a list of the keys it has.
  • console.log(product) prints the whole object, which is handy for seeing exactly what a test received.

3. Reading and changing values

There are two ways to read a value. Dot notation is the everyday one; square brackets cover the cases dots can't:

// Dot notation: the usual way
console.log(product.price);    // 24.99

// Bracket notation: the key goes in quotes
console.log(product['price']); // 24.99

// Brackets are needed when the key has a dash or a space...
const headers = { 'Content-Type': 'application/json' };
console.log(headers['Content-Type']); // application/json

// ...or when the key's name is stored in a variable
const field = 'price';
console.log(product[field]); // 24.99
Explain this code, line by line
  • product.price and product['price'] read the same value.
  • 'Content-Type' contains a dash, so it can't be written after a dot: headers.Content-Type would be read as "headers.Content minus Type". Keys like this need quotes when you create them, and brackets when you read them. API headers are a common place to meet them.
  • product[field], without quotes, uses the variable: field holds 'price', so it reads product.price. That lets one piece of code read whichever field it's told to.

Changing a value, or adding a new one, uses the same notation with =:

product.price = 19.99;         // change an existing value
product.category = 'Trekking'; // add a new key
console.log(product);
// { name: 'Headlamp', price: 19.99, inStock: true, category: 'Trekking' }

console.log(product.rating);   // undefined: there's no such key
Explain this code, line by line
  • Assigning to a key that exists replaces its value; assigning to a new key adds it.
  • Reading a key that doesn't exist doesn't stop the test. It quietly gives undefined (Part 1). A misspelled key, such as product.prise, does the same, which is why undefined is a hint to check spelling.

But product is a const. How can it change? const fixes which object the name points to, not what's inside it. You can change the contents freely; what you can't do is point the name at a different object: product = {} fails with TypeError: Assignment to constant variable. That's why test code declares objects with const and still updates them.

4. Arrays: ordered lists

An array is a list of values in a fixed order. There are no labels; each item is found by its position, called its index:

const categories = ['Camping', 'Trekking', 'Mountaineering'];

console.log(categories[0]);       // Camping: the FIRST item is index 0
console.log(categories.length);   // 3: how many items
console.log(categories[categories.length - 1]); // Mountaineering: the last item
console.log(categories[3]);       // undefined: there is no fourth item

categories[1] = 'Travel';         // replace the second item
console.log(categories);          // [ 'Camping', 'Travel', 'Mountaineering' ]
Explain this code, line by line
  • Square brackets [ ] make an array, with items separated by commas.
  • Counting starts at 0. The first item is [0], the second [1], the third [2]. It's the most common beginner slip, called an "off-by-one" error.
  • .length is how many items the array has. Because counting starts at 0, the last item is always at length - 1.
  • Asking for a position past the end gives undefined, not an error.
  • categories[1] = 'Travel' replaces an item. As with objects, const doesn't stop you changing what's inside.

5. Objects and arrays together: real test data

Objects can hold arrays, and arrays can hold objects. Real data, like PeakAndPack's product list from its API, is built this way. You read it by chaining the steps, left to right:

// An object holding an array
const tent = { name: '4-Season Tent', price: 320, tags: ['2-person', 'snow-rated'] };
console.log(tent.tags[0]); // 2-person

// An array of objects: the shape of an API response
const body = {
  products: [
    { id: 1, name: 'Trekking Poles (Pair)', price: 34.99 },
    { id: 2, name: '4-Season Tent', price: 320 },
  ],
};

console.log(body.products.length);  // 2
console.log(body.products[1].name); // 4-Season Tent
console.log(`${body.products[0].name} costs $${body.products[0].price}`);
// Trekking Poles (Pair) costs $34.99
Explain this code, line by line
  • tent.tags[0]: first tent.tags (the array), then [0] (its first item).
  • body.products[1].name reads in three steps: body.products is the list, [1] is its second product, .name is that product's name.
  • This is the shape PeakAndPack's API answers in. The Playwright series' Phase 7 reads its responses exactly like this, for example checking that body.products[0].price is a number.
  • The last line mixes Part 1's template literals with nested reads.

The error you'll see most: Cannot read properties of undefined (reading 'name'). It means one step of the chain didn't exist. body.products[5].name fails this way: there's no product at index 5, so body.products[5] is undefined, and you can't read .name of nothing. Read the message right to left: it tried to read name, so check the step before it.

Common mistakes.

  • Starting to count at 1. The first item is [0], and the last is [length - 1].
  • Misspelling a key. No error, just undefined, often several lines before the test actually fails.
  • Forgetting the quotes in brackets. product['price'] reads the key "price"; product[price] looks for a variable called price.
  • Assuming a list has items. Before reading [0] of a list from an API, check its length, or the test fails with "Cannot read properties of undefined".
Exercise

Read an order like a test would

Create exercise-objects.js, write code for each step, and run it with node exercise-objects.js:

  1. Create a customer object with a first name, a last name and an email, and print the whole object.
  2. Print the first name with dot notation, and the last name with bracket notation.
  3. Change the email, add a new key isMember set to true, and print the object again.
  4. Print customer.phone. What do you get, and why isn't it an error?
  5. Create const field = 'email' and use it to print the customer's email.
  6. Create a headers object with the key 'Content-Type' and print its value.
  7. Create an array cartItems with three product names. Print the first item, the number of items, and the last item using length.
  8. Replace the second item with Headlamp, then print cartItems[3]. What do you get?
  9. Create an order object with an id and an items array of two products, each an object with a name and a price.
  10. From order, print: how many items there are, the second item's name, and a sentence with a template literal: Order 7: Headlamp costs $24.99.
  11. Break it on purpose, one at a time, and read each error: point customer at a new object (customer = {}); read order.items[5].name.
Show solution: try it yourself first 
// 1. An object: related values under one name
const customer = { firstName: 'Ana', lastName: 'Silva', email: 'ana@example.com' };
console.log(customer);

// 2. Dot and bracket notation
console.log(customer.firstName, customer['lastName']);

// 3. Change a value, add a key: allowed even though customer is a const
customer.email = 'ana.silva@example.com';
customer.isMember = true;
console.log(customer);

// 4. A key that doesn't exist
console.log(customer.phone);

// 5. A key name held in a variable: brackets, no quotes
const field = 'email';
console.log(customer[field]);

// 6. A key with a dash needs quotes, and brackets to read it
const headers = { 'Content-Type': 'application/json' };
console.log(headers['Content-Type']);

// 7. An array: counting starts at 0
const cartItems = ['Trekking Poles (Pair)', 'Camping Stove', 'GPS Watch'];
console.log(cartItems[0], cartItems.length, cartItems[cartItems.length - 1]);

// 8. Replace an item, and read past the end
cartItems[1] = 'Headlamp';
console.log(cartItems, cartItems[3]);

// 9. An object holding an array of objects
const order = {
  id: 7,
  items: [
    { name: 'Trekking Poles (Pair)', price: 34.99 },
    { name: 'Headlamp', price: 24.99 },
  ],
};

// 10. Reading nested data
console.log(order.items.length, order.items[1].name);
console.log(`Order ${order.id}: ${order.items[1].name} costs $${order.items[1].price}`);

// 11. Break it on purpose (remove the // from one line at a time)
// customer = {};                 // TypeError: Assignment to constant variable.
// console.log(order.items[5].name); // TypeError: Cannot read properties of undefined (reading 'name')

What to notice.

  • Step 3 worked on a const, because changing what's inside an object isn't the same as pointing the name at a new one. Step 11's customer = {} is the part const blocks.
  • Steps 4 and 8 give undefined, not errors. A missing key or a position past the end quietly gives nothing, which can surface as a confusing failure much later in a test.
  • Long objects print over several lines. Node switches to one key per line once an object gets too wide.
  • Step 11's second error is the one you'll see most in tests. Read it right to left: it tried to read name from something that was undefined, so the step before, order.items[5], doesn't exist.
