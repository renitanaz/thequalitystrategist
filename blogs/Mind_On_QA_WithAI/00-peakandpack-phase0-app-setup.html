Get PeakAndPack Ready to Test

Before Phase 1's requirements document means anything, confirm the app it describes is actually live and reachable. This phase is five minutes of verification, not a deployment guide, you don't need to run anything yourself.

By RN ~5 min Series: AI-Augmented QA

PeakAndPack is already deployed and stays live for the whole series: the same instance, the same seeded bugs, from Phase 0 through Phase 8. You don't fork a repo or spin up your own copy, you test against the real thing directly, the same way every reader of this series does.

What PeakAndPack is

A full-stack e-commerce app, purpose-built for this series: a Node.js and SQLite API and a small React UI, deployed as two separate services on Render's free tier from one monorepo. It has login, a product listing, a cart, and a checkout flow, enough to teach every testing approach without a domain that gets in the way.

Step 1: confirm the API is live

The API and the UI are separate Render services with separate URLs:

  • API: https://peakandpackshopdemo.onrender.com
  • UI: https://peakandpack-ui.onrender.com

Open the API's health check in a browser or curl it:

curl https://peakandpackshopdemo.onrender.com/health

A healthy response looks like:

{"status":"ok","timestamp":"2026-08-15T18:32:09.222Z","version":"1.0.0"}

First request can take up to a minute. Render's free tier spins services down after inactivity. The first request after a quiet period returns a slow response or a brief 503 while it wakes up, that's expected, not a bug. Wait a few seconds and retry before assuming anything is broken. Every phase from here on assumes you know this, so a cold start doesn't get mistaken for a real failure partway through a testing session.

Step 2: confirm the product data loads

Once the health check passes, confirm the product endpoint returns real data:

curl https://peakandpackshopdemo.onrender.com/api/products

You should get back an array of 10 products. Three of them look wrong on purpose, don't fix your test setup to hide them, they're the point of the next several phases:

  • One product with a negative price
  • One product with an empty name
  • One product priced at $9,999.99

Step 3: confirm the UI loads against the live API

Open https://peakandpack-ui.onrender.com in a browser. You should see the product grid load (briefly showing "Loading gear…" first, that's the UI waiting on the API, not a bug). If the API is still cold-starting, the page may show an empty or stalled state, reload after a few seconds.

Step 4: confirm the test account works

A test account is pre-filled on the login page so nobody needs to register their own:

  • Email: test@peakandpack.com
  • Password: password123

Log in, confirm you land on the product listing signed in ("Hi, Test User" appears top-right), and that /cart and /orders are reachable without a redirect back to login.

Two different domains, easy to mix up. The UI (peakandpack-ui) and the API (peakandpackshopdemo) don't share a hostname, they're separate Render services from the same monorepo. Later phases writing API tests need the API domain, not the UI domain. Check DevTools → Network on the live UI if you're ever unsure which request goes where.

Verification checklist

  • /health returns {"status":"ok"}
  • /api/products returns 10 products
  • The UI loads the product grid at peakandpack-ui.onrender.com
  • Login works with the test account
  • /cart and /orders are reachable while logged in

All five passing means you're ready for Phase 1. Nothing here is testing PeakAndPack yet, it's confirming the ground you're about to test is solid.
