Phase 4 of 8 · Visual Regression

Visual Regression, By Eye

A checklist, a browser, and a willingness to resize the window a few times.

By RN ~4 min read Series: AI-Augmented QA
Manual, No AI Manual + AI Automated, Playwright AI QA Agent

Build a checklist, walk the live UI, document what's broken with screenshots. No tools beyond your eyes and a browser resized a few times.

What you actually do

  • Create a visual testing checklist covering product cards, broken data display, cart layout, checkout form, and responsive behavior
  • Go through each item on the live UI, resizing the browser to mobile width for the last one
  • Document issues with screenshots, not just descriptions

Checklist, with the actual answers

CheckWhat you'll actually see
Does a product with empty name show a blank card title?Yes, the title area renders empty, no fallback text
Does a negative price show as "-$89.00" on the card?Yes, in red, exactly as the data implies
Does $9,999.99 overflow the price display area?Check at narrow widths, large numbers are the first to wrap or clip
Does the cart total update visually on quantity change?Should update immediately, no stale total
Are all buttons accessible (visible focus state)?Tab through the page, check every interactive element gets a visible outline

This isn't a new bug list, it's the same bugs with a face. The negative price and empty name issues were already known from Phase 1's requirements doc. This checklist confirms how they actually look to a real user, which matters because "the API has a bug" and "the screen shows broken-looking pricing" land very differently with a non-technical stakeholder.

Your deliverable

One file: visual-testing-checklist.md, plus a screenshots folder documenting every issue found, named clearly enough that someone else could match screenshot to checklist item without guessing.

Time: ~1 to 2 hours. Mostly browsing and resizing, but the screenshots are what make this deliverable useful to anyone who reads it later.
