Phase 3 of 8 · Test Cases

Test Cases, Generated in One Pass

Every endpoint, scanned at once. The speed is real. So is the need to check what came back.

By RN ~4 min read Series: AI-Augmented QA
Manual, No AI Manual + AI Automated, Playwright AI QA Agent

The agent fetches the live API, analyses every endpoint and response, and generates a full test case suite, structured and ready to copy into a test management tool.

What the agent does

  1. Fetches the API and analyses every endpoint and response shape
  2. Generates test cases covering all features automatically
  3. Outputs a structured table, copy-paste ready

Speed without context is still a gap. The agent can generate test cases for every endpoint in under a minute, but it doesn't automatically know that SAVE10 should be 10% off, not 100%, unless that's findable in the data it's given or in the requirements doc it's pointed at.

What good output looks like

TC-IDTitleStepsExpectedPriority
TC-A01GET /api/products returns valid arrayCall endpoint, no params200, array of productsHigh
TC-A02Search with missing query paramGET /api/search with no ?q400 (currently 500, flagged)Critical

Notice TC-A02 already flags the expected-vs-actual gap (BUG-011), if the agent had access to live data showing the crash. That's the difference between a generic template and a finding grounded in real behavior.

Your deliverable

The agent-generated test case document, reviewed by you before it's considered final, same expectation as every other AI-assisted approach in this series.

Time: ~10 minutes for generation. Review time on top of that depends entirely on how much you trust what came out, which is exactly the harness and loop question raised earlier in this series.
