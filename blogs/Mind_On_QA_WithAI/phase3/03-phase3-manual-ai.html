Phase 3 of 8 · Test Cases

Test Cases, Drafted Fast, Checked Carefully

Claude writes the skeleton. You catch what it couldn't have known about this specific app.

By RN ~4 min read Series: AI-Augmented QA
Manual, No AI Manual + AI Automated, Playwright AI QA Agent

Give Claude each feature's requirements from peakandpack-requirements.md, get a draft test case set back, then review every case before it counts as final.

What you actually do

  1. Give Claude each feature's requirements
  2. Ask it to generate test cases covering happy, negative, and edge cases
  3. Review every case: remove duplicates, add what's missing, adjust steps

Prompts that actually work

Generate test cases for PeakAndPack's checkout flow. Include happy path, negative, and edge cases. Format as a table with TC-ID, title, steps, expected result, priority.

What edge cases am I missing for the cart feature? [paste your cases]

Generate boundary value test cases for the product price field.

Claude drafts the skeleton, you validate it. AI-generated test cases are good at breadth (covering every endpoint) but can miss app-specific context, like knowing that SAVE10 is supposed to be 10%, not 100%. That context comes from your Phase 1 requirements doc, not from the AI guessing.

Where review catches real gaps

AI gets right
Generic edge cases: empty strings, negative numbers, missing required fields, across every endpoint, fast.
You have to add
App-specific logic bugs, like the exact 10% vs 100% discount expectation, that only the requirements doc captures.

Your deliverable

One file: test-cases-ai-assisted.md, the AI-drafted set after your review pass, removing anything redundant and adding anything app-specific the draft missed.

Time: ~1 hour. Most of that hour is reviewing, not writing, which is the actual point of this approach.
