Test Strategy, Enforced by Config

Strategy isn't a document here, it's a config file that makes your decisions impossible to skip.

By RN ~4 min read Series: AI-Augmented QA
Manual, No AI Manual + AI Automated, Playwright AI QA Agent

There's no such thing as an "automated test strategy" document, strategy is a thinking exercise. But Playwright's config file is where strategy decisions get enforced in code: which browsers run, how flaky tests are retried, how results are tagged by risk.

What you actually do

Write a playwright.config.ts that encodes your Phase 2 decisions directly into config:

  • Which browsers to run (Chromium, Firefox, WebKit)
  • Retry logic (self-healing for flaky tests)
  • Reporting format
  • Test tagging by risk level: @critical, @high, @regression

The config file

import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  retries: process.env.CI ? 2 : 1,  // self-healing: auto-retry flaky tests
  reporter: [
    ['html', { outputFolder: 'playwright-report' }],
    ['json', { outputFile: 'test-results.json' }],
    ['line'],
  ],
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
    { name: 'firefox', use: { ...devices['Desktop Firefox'] } },
  ],
  use: {
    baseURL: 'https://peakandpackshopdemo.onrender.com',
    trace: 'on-first-retry',
  },
});

Self-healing pattern. Use data-testid attributes and role-based locators (page.getByRole(...)) instead of CSS classes, so tests survive UI redesigns without rewriting every selector.

Tagging by risk, in practice

test('checkout applies discount correctly @critical', async ({ page }) => {
  // ...
});

test('product listing shows correct stock @high', async ({ page }) => {
  // ...
});

test('sort order is stable on repeat load @regression', async ({ page }) => {
  // ...
});

Now you can run just the critical suite before a release: npx playwright test --grep @critical.

Your deliverable

Two files: playwright.config.ts and a short README-strategy.md explaining the tagging convention so the next person (or future you) knows what @critical means here.

Time: ~1 hour. Mostly config, not prose, but it carries the same strategic decisions as the manual document, just enforced by tooling instead of written down and trusted.
