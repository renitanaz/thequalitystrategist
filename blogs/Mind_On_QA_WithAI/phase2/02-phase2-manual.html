Test Strategy, By Hand

Reading the requirements, ranking risk, and writing the plan yourself. No AI, no shortcuts.

By RN ~5 min read Series: AI-Augmented QA
Test Strategy: Manual, No AI Test Strategy: Manual + AI Test Strategy: Automated, Playwright Test Strategy: AI QA Agent

No Claude, no agent, no config file enforcing rules. Just you, the requirements doc from Phase 1, and a blank page.

What you actually do

  1. Read peakandpack-requirements.md from Phase 1, end to end
  2. Identify the riskiest areas: what breaks causes the most damage if it ships broken
  3. Write a test strategy covering: scope, what's in/out, test types, priorities, entry/exit criteria

No special tools required. A text editor or Google Doc is enough.

Ranking PeakAndPack's risk areas

Walking the requirements doc, here's a reasonable first pass at ranking by business impact, not by which bug is easiest to spot:

AreaWhy it's riskyPriority
Checkout / discount logicA pricing bug here loses real money, silently, at scaleCritical
Auth / orders visibilityShowing one user's orders to another is a data leakCritical
Cart totalsWrong totals erode trust even if the order itself is fineHigh
Product listing/searchAnnoying if broken, but doesn't cost money or leak dataMedium
Sort orderCosmetic. Non-deterministic sort is a low-stakes nuisanceLow

Notice what's NOT top of the list. A missing product image is more visually obvious than a silent pricing bug, but it's far less risky. Manual strategy work means resisting the pull toward "what's easy to find" and sticking with "what costs the most if missed."

Your deliverable

One file: test-strategy-manual.md, covering scope, priorities, test types planned, and entry/exit criteria for calling this phase done.

Time: ~2 hours. This is the slowest of the four approaches, and that's by design, the thinking happens here, not later.
