Test Strategy, Generated From Live Data

The agent reads the API, ranks the risk, and drafts the strategy. You still have to check its work.

By RN ~4 min read Series: AI-Augmented QA
Manual, No AI Manual + AI Automated, Playwright AI QA Agent

This is where the AI QA Agent (built later in this series, see the harness and loop framing in the series intro) takes the live API and generates a risk-based strategy with no manual drafting at all.

What the agent does

  1. Fetches your app's API data directly (products, orders, endpoints)
  2. Claude analyses the data for risk signals: pricing anomalies, missing validation, auth gaps
  3. Generates a risk-ranked test strategy document automatically

You then review, refine, and save the output. The agent drafts; you're still the one who signs off.

Harness matters here. An agent given raw API access can generate a plausible-sounding strategy that misses the actual highest-risk area, if its harness doesn't push it to verify findings against real data, not just describe what it expects to see. This is the same reliability concern covered in the series intro's harness and loop section.

What "review, don't just accept" looks like

Good agent output
Flags checkout discount logic as highest risk, citing the actual SAVE10 behavior it observed in live data.
Needs your review
Generic risk list that could apply to any e-commerce app, with no reference to PeakAndPack's actual data. That's a sign it didn't really look.

Your deliverable

One file: test-strategy-agent.md, the agent's output after your review pass. Same structural elements as the other three approaches, scope, priorities, entry/exit criteria, generated from data instead of from reading a requirements doc.

Time: ~10 minutes. The fastest of the four, by a wide margin, but the value of that speed depends entirely on whether you actually read and correct what comes out.
