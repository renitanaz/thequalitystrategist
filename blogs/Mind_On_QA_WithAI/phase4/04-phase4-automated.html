Visual Regression, Pixel by Pixel

One baseline screenshot, then every future run checks itself against it automatically.

By RN ~4 min read Series: AI-Augmented QA
Manual, No AI Manual + AI Automated, Playwright AI QA Agent

Take a baseline screenshot once. On every future run, Playwright diffs the new screenshot against that baseline, pixel by pixel, and flags anything that changed.

What you actually do

  • Use Playwright's built-in screenshot comparison, toHaveScreenshot
  • Take baseline screenshots of key pages once
  • On every re-run, Playwright diffs new screenshots against baseline and flags pixel differences
  • Use maxDiffPixelRatio tolerance so minor rendering noise doesn't fail tests unnecessarily

The pattern

test('product listing page visual', async ({ page }) => {
  await page.goto('/');
  await expect(page).toHaveScreenshot('product-listing.png', {
    maxDiffPixelRatio: 0.02  // 2% tolerance, self-healing for minor changes
  });
});

test('sleeping bag card shows negative price visually', async ({ page }) => {
  await page.goto('/');
  const card = page.getByText('Sleeping Bag').locator('..');
  await expect(card).toHaveScreenshot('sleeping-bag-card.png');
  // This baseline was captured WITH the bug present.
  // Once BUG-011 is fixed, this test will correctly fail,
  // because the screenshot will no longer match.
});

Self-healing means tolerance, not blindness. A 2% pixel tolerance lets font-rendering differences between machines pass without manual re-baselining every time. It does not mean the test ignores real layout breaks, a misaligned button or missing image still exceeds that tolerance and fails correctly.

Setting it up, step by step

If you have never run Playwright before, here is the whole path from nothing to a passing visual run. It assumes Node.js is installed (check with node --version; if it errors, get the LTS build from nodejs.org first).

  1. Make a folder and go into it. In a terminal: mkdir peakandpack-visual then cd peakandpack-visual.
  2. Install Playwright. Run npm init playwright@latest. It asks a couple of questions (TypeScript: yes; tests folder: tests); accept the defaults. This downloads Playwright and the browsers it drives.
  3. Point it at the live site. Open the generated playwright.config.ts and set the base URL so page.goto('/') resolves to PeakAndPack: 
    use: {
  baseURL: 'https://peakandpack-ui.onrender.com/',
},
  4. Add the spec. Download visual.spec.ts and put it in the tests/ folder.
  5. Capture the baselines (first run). Run npx playwright test --update-snapshots. The first run has nothing to compare against, so this captures the baseline images into a snapshots/ folder. Open them and confirm they look right; a baseline captured with a bug visible will treat that bug as "correct" until you re-baseline.
  6. Run normally afterwards. From now on, npx playwright test compares each fresh screenshot against its baseline and fails on any diff beyond the tolerance. Open the HTML report it generates to see exactly which pixels changed.

If it fails unexpectedly: a diff on the very first compare usually means the page wasn't fully loaded before the screenshot, add an explicit wait for a known element. A diff that appears only in CI but not locally is almost always font rendering, which is what maxDiffPixelRatio absorbs; nudge the tolerance up slightly rather than re-baselining per machine.

Your deliverable

A tests/visual.spec.ts file plus a snapshots/ folder containing the baseline images every future run gets compared against.

Time: ~2 hours. Most of that is deciding which pages and components are worth a baseline, not writing the comparison code itself, which is just a few lines per test.
