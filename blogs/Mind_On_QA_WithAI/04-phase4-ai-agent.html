Phase 4 of 8 · Visual Regression

Visual Regression, From Data Bug to Screenshot

The agent finds it in the data. Claude Code with Playwright MCP confirms what it actually looks like.

By RN ~4 min read Series: AI-Augmented QA
Manual, No AI Manual + AI Automated, Playwright AI QA Agent

This is the approach that finally closes the loop from data anomaly to visible symptom. The agent finds the bug in the data, then Claude Code with Playwright MCP goes and looks at the actual screen to confirm it.

What the agent does, in two stages

  1. Fetches product and order data from the API
  2. Claude analyses the data for values that would create broken visual states (negative prices, empty names, overflow-prone values)
  3. Separately, Claude Code with Playwright MCP navigates the live frontend/ UI and screenshots each flagged value to confirm how it actually renders

Why two stages instead of one. The HTML agent (stage 1) can only see API data, it has no browser. Closing the gap to an actual rendered screenshot needs a tool that can drive a browser, which is exactly what Playwright MCP adds. Neither stage alone tells the full story, the data finding without a screenshot is unconfirmed; a screenshot without knowing what to look for is just noise.

What the combined report looks like

Data findingVisual confirmation
Sleeping Bag price = -89.00Screenshot shows "-$89.00" in red on the product card
One product has empty nameScreenshot shows a card with a blank title area
Water Bottle price = 9999.99Screenshot shows the price slightly overflowing its container at narrow widths

Your deliverable

The visual regression section of the agent report, containing both the raw data findings and the matching live screenshots from Claude Code + Playwright MCP.

Time: ~15 minutes. Slightly longer than a pure API-only agent pass, since the second stage actually has to load and screenshot a real page, but still far faster than a manual visual sweep.
