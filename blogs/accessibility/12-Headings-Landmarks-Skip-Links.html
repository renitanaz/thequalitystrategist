12 Headings, Landmarks and Skip Links: How to Validate Page Structure

The invisible architecture of a page. Screen reader users navigate by it. Most pages break it.

1. Why Page Structure Matters

Sighted users scan a page visually: they see headings, sections, sidebars, and navigation areas at a glance. Screen reader users do the same thing: but using structure instead of visual layout. They press H to jump between headings, R to jump between landmark regions, and they expect a skip link at the top of every page to jump over repeated navigation.

When that structure is missing, broken, or inconsistent, navigating a page by screen reader is like reading a document where someone removed all the paragraph breaks and section titles. The content is there. Finding anything is exhausting.

Heading structure, landmark regions, and skip links are not primarily a visual concern. They are navigation infrastructure for non-visual users. They cannot be seen in a browser. They can only be tested with the right tools.

2. Heading Hierarchy: The Rules and Common Failures

The rules are covered in Blog 06. This section focuses on how to detect violations in a built page.

What a correct heading structure looks like on a typical page:

Broken: what QA typically finds
<h1>Homepage</h1> <h3>Latest news</h3> <!-- H2 skipped --> <h1>About us</h1> <!-- second H1 --> <div class="title"> <!-- heading styled Our story with CSS, not markup --> </div> <h4>Founded 2010</h4> <!-- H2, H3 skipped -->
Correct structure
<h1>Homepage</h1> <h2>Latest news</h2> <h3>Article title</h3> <h3>Article title</h3> <h2>About us</h2> <h3>Our story</h3> <h4>Founded 2010</h4>

Common failures

  • Multiple H1s: one per page only. SPAs often add a second H1 when a route changes without updating the original.
  • Skipped levels: H1 to H3, or H2 to H4. Often happens when developers choose heading levels for visual size, not structure.
  • Missing headings entirely: large page sections with no heading. Screen reader users cannot jump to them.
  • Visual headings not marked up: text styled to look like a heading with CSS but using a <div> or <p>. Invisible to screen readers.
  • Heading levels that change across pages: a component that is H2 on one page and H3 on another. Common in reusable components without context-aware heading levels.

3. Landmark Regions: What They Are and What to Check

Landmark regions are HTML sectioning elements that define the major areas of a page. Screen reader users press R (in NVDA) or use the rotor to jump between them directly, the same way sighted users scan the visual layout.

HTML landmark elements, their roles, and what to check
Element Landmark role What to check
<header>bannerPresent once at the top of the page. Not nested inside other landmarks.
<nav>navigationEach nav has a unique aria-label if more than one exists. "Main navigation", "Breadcrumb", "Footer navigation": not just "navigation" twice.
<main>mainExactly one per page. Contains the primary content. Not nested inside another landmark.
<footer>contentinfoPresent at the page level. Not confused with component-level footers inside articles.
<aside>complementaryUsed for genuinely supplementary content. Not used as a generic container.
<section>region (only with aria-label)Needs an aria-labelledby or aria-label to become a navigable landmark. Without it, it is not a landmark.
<form>form (only with aria-label)Needs an accessible name to become a landmark. Without it, a screen reader cannot jump to it directly.

Common landmark failures

  • Missing main landmark: the entire page content is in divs with no <main>. Screen reader users cannot skip to the main content.
  • Multiple unlabelled navs: two or more <nav> elements with no aria-label. Both announced as "navigation" with no way to distinguish them.
  • Landmarks nested inside each other: a <header> inside <main> creates a confusing landmark tree.
  • Overuse of section: every div replaced with <section> without aria-label. Creates phantom landmarks that add noise without navigation value.

4. Skip Links: The First Tab Stop Rule

A skip link is a visually hidden link at the very top of every page that becomes visible on focus and jumps the user directly to the main content area. It exists for one reason: keyboard users should not have to Tab through an entire navigation bar on every page load to reach the content they came for.

WCAG 2.4.1 requires a mechanism to bypass repeated navigation blocks. A skip link is the standard implementation. It must be the first focusable element on the page.
Correct skip link pattern
<!-- First element in body --> <a href="#main-content" class="skip-link"> Skip to main content </a> <!-- CSS --> .skip-link { position: absolute; top: -100%; left: 1rem; } .skip-link:focus { top: 0; }
Common failures
<!-- Not first element: nav comes before it --> <nav>...</nav> <a href="#main">Skip</a> <!-- Hidden with display:none: not reachable by keyboard --> .skip-link { display: none; } <!-- href points to missing ID --> <a href="#main">Skip</a> <!-- <main id="content"> not "#main" -->

How to test a skip link

Load the page. Press Tab once. The skip link must appear. Press Enter. Focus must move to the main content area and the page must scroll to it. If Tab does nothing, or the skip link appears but Enter does nothing, or focus moves to the wrong element: each of those is a separate defect.

How to Test: Tiers and Platform Coverage

Tier 1: Pipeline automation

axe-core catches: missing landmark regions, skipped heading levels, missing skip links, and empty headings. Run with withTags(['wcag2a','wcag2aa']) in CI. These structural violations are among the most reliable automated checks: the DOM either has the correct structure or it does not.

Tier 2: Semi-automated tools

WAVE Structure tab gives the fastest visual overview of heading hierarchy and landmark regions. ANDI Structure module lists all headings in document order: faster than tabbing through headings with a screen reader for a first structural check. Accessibility Insights FastPass catches landmark and heading violations with WCAG criterion references.

Tier 3: Manual: platform coverage

  • NVDA + Firefox (Windows): Press H to walk headings. Press D for landmarks. Press 1–6 for heading levels. Verify structure matches the visual hierarchy.
  • VoiceOver + Safari (Mac): Open rotor (VO+U). Check Headings and Landmarks lists. Verify all landmark regions are named where multiple exist.
  • VoiceOver on iOS (physical iPhone): Set rotor to Headings. Swipe up/down to navigate. Verify heading structure in mobile view.
  • TalkBack on Android (physical device): Set reading controls to Headings. Swipe up to navigate. Verify structure.

6. How to Test: Tools and Manual Checks

🎯
Practice these yourself
The heading and landmark failures described below are available as interactive demos in the Headings and Landmarks Playground. For mobile testing steps, see the Mobile Testing Guide.

What automation catches

axe-core (in Playwright, Cypress, or axe DevTools) and Pa11y will flag these automatically:

  • Missing <main> landmark
  • Multiple elements with the same landmark role and no distinguishing label (e.g. two unlabelled <nav> elements)
  • Empty heading elements (<h2></h2>)
  • Page with no headings at all
  • Incorrect ARIA roles on landmark elements

Run axe-core in your CI/CD pipeline to catch these on every pull request. They are structural issues: deterministic, no interpretation needed.

What automation misses: manual check required

Automation cannot evaluate meaning or logic. These require human judgement:

  • Skipped heading levels: axe-core flags some skipped levels but not all. A page with H1 then H3 sometimes passes automated checks. Always verify with WAVE Structure tab or NVDA Insert+F6.
  • Visual headings not marked up as headings: automation sees a <div> styled to look like a heading. It has no way to know it should be a heading. Only a human reviewing the page visually against the DOM can catch this.
  • Heading hierarchy that matches the DOM but not the visual layout: automation checks the code order, not whether the heading order makes logical sense to a reader.
  • Skip link href pointing to a non-existent ID: some automated tools flag this; many do not. Always test manually: press Tab once, then Enter.
  • Landmark labels that are technically present but meaningless: aria-label="nav1" passes automation. It fails a real user.

WAVE Structure tab

The fastest way to inspect heading hierarchy on a live page. Open WAVE, click the Structure tab. The heading tree is displayed with levels, text, and any skipped levels flagged in yellow. Landmark regions are also shown with their roles. Takes under 60 seconds per page. Catches what axe-core misses on heading structure.

NVDA heading navigation

With NVDA running, press H to move to the next heading, Shift+H to move back. Press Insert+F6 to open the headings list: all headings on the page displayed with their levels. This is the ground truth: it shows exactly what a screen reader user experiences, not just what the DOM contains.

Accessibility Insights

Accessibility Insights FastPass runs automated axe-core checks and a tab stops visualisation. Assessment mode provides guided checks for landmark structure. Useful for combining automated and manual verification in one workflow.

Chrome DevTools accessibility tree

In Chrome DevTools, enable the full page accessibility tree from the Accessibility panel. Every heading, landmark, and ARIA role is visible in a tree view. Useful for checking whether a heading is marked up correctly or just visually styled: particularly helpful when WAVE flags something you cannot immediately locate in the DOM.

Manual check: the three questions

  • Skip link: Press Tab once on page load. Does it appear? Press Enter. Does focus move to main content?
  • Headings: Does the page have exactly one H1? Do heading levels progress sequentially with no skips? Are all major sections reachable via NVDA heading navigation?
  • Landmarks: Is there a <main>? Are multiple <nav> elements labelled distinctly? Test on VoiceOver (Mac/iOS) and TalkBack (Android) to confirm mobile landmark navigation works: automation does not cover this.

7. Common Defects and How to Write Them

Common structure defects with WCAG reference, severity, and reproduction steps
Defect WCAG Severity Reproduction
Skip link missing 2.4.1 Major Load page. Press Tab. No skip link appears as first focusable element.
Skip link present but broken 2.4.1 Major Press Tab, skip link appears, press Enter. Focus does not move to main content. Inspect: href ID does not match target element ID.
Multiple H1 elements 1.3.1 Major Open WAVE Structure tab or NVDA headings list (Insert+F6). Two or more H1 elements visible.
Skipped heading level 1.3.1 Moderate Open WAVE Structure tab. Heading jumps from H1 to H3 or H2 to H4 with no intermediate level.
Missing main landmark 1.3.1 Major Open WAVE Structure tab or Chrome DevTools accessibility tree. No main landmark present.
Multiple navs without aria-label 1.3.1 Moderate Open WAVE. Two or more nav elements both labelled "navigation" with no distinguishing label.
Section used as landmark without label 1.3.1 Minor Chrome DevTools accessibility tree shows section element with no accessible name. Not a navigable landmark.
The fast check

Open WAVE, click Structure, look for red and yellow flags. This catches 80% of heading and landmark defects in under a minute. Manual verification with NVDA confirms the rest.
