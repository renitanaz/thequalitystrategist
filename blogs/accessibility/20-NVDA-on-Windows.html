20 NVDA on Windows: The QA Tester's In-Depth Guide

NVDA is free, widely used, and the closest representation of real user experience on Windows. This is how to use it systematically for testing.

1. Why NVDA for QA Testing

NVDA (Non-Visual Desktop Access) is a free, open-source screen reader for Windows maintained by NV Access. It is the most widely used screen reader for web accessibility testing because it is free to install, works with Firefox and Chrome, and closely represents real-world usage patterns of Windows screen reader users.

JAWS (Job Access With Speech) is more common among enterprise users and has a higher market share in corporate environments.

For most accessibility testing programmes, NVDA + Firefox is the recommended starting configuration because the combination is free, accurate, and representative.

The core testing principle: disconnect your mouse. Navigate using only the keyboard while NVDA is running. If you cannot complete a task by listening alone, it is an accessibility defect.

2. Installation and First Launch

  • Download: nvaccess.org/download: free, no registration required
  • Install: run the installer with default settings. NVDA can also run as a portable version from a USB drive without installation.
  • Launch: Ctrl+Alt+N or Start menu. NVDA announces "NVDA has started."
  • System tray icon: NVDA appears in the system tray. Right-click for options.
  • Quit: Insert+Q then Enter. Insert is the NVDA key (also called the NVDA button): by default, every NVDA shortcut in this guide uses it as the modifier.
  • Silence speech without quitting: Ctrl

3. Recommended Configuration for Testing

Speech rate

Default NVDA speech rate is fast. For testing, slow it down to understand every announcement clearly. Insert+Ctrl+↓ to decrease speed. As you gain experience, increase the rate: experienced testers run NVDA faster to cover more ground.

Verbosity settings

NVDA Preferences, Speech, Symbol Level: set to "All" during initial testing to hear every punctuation and symbol. Reduce when it becomes noise. Preferences, Document Formatting: enable Headings, Lists, Links, and Tables to get structural announcements as you navigate.

Speech synthesiser

Default is eSpeak NG: acceptable for testing. Windows OneCore voices are clearer if you prefer. NVDA Preferences, Synthesiser: change if needed. Do not use a synthesiser that changes the content NVDA reads.

Browse mode settings

NVDA Preferences, Browse Mode: ensure "Use screen layout" is ON and "Automatic focus mode for focus changes" is ON. These match the default behaviour most users experience.

Browser recommendation

Firefox + NVDA is the standard combination. Chrome works but some ARIA announcements differ between the two. Test in both if you are investigating a specific ARIA pattern failure.

4. Navigation Methodology

🎯
Practice these yourself
Open the Navigation Practice page alongside this section and follow along: one realistic, fully accessible page with no bugs to find, built for running through every step below in order.

A systematic NVDA test session follows this sequence for every page:

  1. Page title check: Load the page. Listen to the page title announcement. Does it identify the page meaningfully?
  2. Landmark navigation: Press D to cycle through landmarks. Are main, nav, search, aside, and footer present and labelled?
  3. Heading structure: Press H to cycle through headings. Is the hierarchy logical? Are there any headings that skip levels (H1 to H4 with no H2, H3)?
  4. Interactive elements: Tab through all interactive elements. For each one: is the label announced? Is the role announced? Is the state announced (expanded, checked, invalid)?
  5. Forms: Tab to each field. Listen for label, type, constraints, and required state. Submit with empty fields: are errors announced?
  6. Tables: Press T to find each table. Use Ctrl+Alt+arrow keys to navigate cell by cell. Is a column or row header announced with each cell?
  7. Images: Press G to cycle through graphics. Is each alt text meaningful?
  8. Links: Press K to cycle through links. Does each link describe its destination? Are there any "click here" or "read more" with no context?
  9. Live regions: Trigger any dynamic update (toast, filter, form submission). Listen without moving focus. Does NVDA announce the change?
  10. Elements list: Insert+F7: open the elements list. Filter by headings, links, form fields, buttons, and landmarks to get a structural overview of the page.

5. What to Test and What to Listen For

🎯
Practice these yourself
Every pattern below has a live pass/fail demo in the NVDA playground for What to Test and What to Listen For, with the exact NVDA announcement for each.

Testing headings

How to test
  • Press H to move to each heading. Listen to the heading level and text.
  • Press 1–6 to jump to specific heading levels.
  • Use Insert+F7, select Headings to see the complete heading outline.
Correct: "Heading level 2: Our services": level and text both announced
Failure: "Our services" with no level: element is not a semantic heading, just visually styled text

Testing links

How to test
  • Press K to move through links. Listen to the link text.
  • Press Insert+K to hear the link destination URL.
Correct: "View our accessibility statement, link": destination clear from link text
Failure: "Read more, link": destination not clear. "Click here, link": describes action not destination

Testing images

How to test
  • Press G to move through graphics. Listen to the announcement.
  • Use Insert+F7, select Graphics to see all images and their alt text.
Correct: "Bar chart: Q3 revenue grew from £0.8M to £2.4M, graphic": data conveyed
Failure: "IMG_20241103.jpg, graphic": filename announced, no alt text
Failure: "graphic" with nothing else: empty or missing alt on meaningful image

Testing forms

How to test
  • Tab to each form field. Listen for the label, field type, and any constraints.
  • Submit the form empty. Listen for error announcements.
  • Tab back to each error field. Listen for the error description via aria-describedby.
Correct on focus: "Email address, required, edit text"
Correct on error refocus: "invalid, Email address, required, Enter a valid email e.g. name@example.com, edit text"
Failure on focus: "edit text, blank": no label
Failure on error: "invalid, edit text": error state announced but no description

Testing tables

How to test
  • Press T to find a table. NVDA announces the number of rows and columns.
  • Use Ctrl+Alt+arrow keys to navigate cell by cell.
  • Listen for column and row header announcements on each cell.
Correct: "Table with 5 rows and 4 columns. Column 1: Name. Row 2: Jane Smith. Jane Smith"
Failure: Cell data announced with no column header: table has no th elements or scope attributes

Testing live regions

How to test
  • Place focus on a non-live-region element (heading or paragraph).
  • Trigger the dynamic content change (add to cart, filter, submit, toast).
  • Listen without moving focus. NVDA should announce the update.
Correct (status): "Item added to cart": announced when NVDA is idle
Correct (alert): "Session expired. Please log in again.": announced immediately
Failure: silence: no live region on the container

6. Logging NVDA Defects

Every NVDA defect log must include:

  • What NVDA announced: exact text, quoted. "NVDA announces: 'edit text, blank'"
  • What NVDA should announce: "Should announce: 'Email address, required, edit text'"
  • Element and location: "Email field in the contact form, /contact page"
  • NVDA version and Firefox version: document your test environment
  • WCAG criterion: 1.3.1, 3.3.1, 4.1.2 etc.
  • Reproduction steps: numbered, starting from a fresh page load
The testing mindset
  • Close your eyes after the first few minutes. If you cannot complete the task by listening alone, it is a defect.
  • NVDA is telling you what the code says. If the announcement is wrong, the code is wrong: not NVDA.
  • Use Insert (the NVDA key)+F7 at the start of every page. The elements list gives you the structural overview in 30 seconds.
