A11y Colour Contrast Mobile Testing Guide

How to test colour contrast on iOS and Android. Covers display accommodations, colour blindness simulation, Accessibility Scanner, and the DAC app. Use alongside the Colour Contrast Playground for the matching desktop scenarios.

⚠️ Physical device required. iOS Simulator and Android Emulator do not accurately reproduce display accommodation behaviour or colour filter rendering.

Test 1: Increase Contrast
WCAG 1.4.3
1
Navigate to the screen you want to test.
2
Go to Settings, Accessibility, Display and Text Size. Toggle Increase Contrast ON.
3
Return to the screen. Look for visual changes: borders darkening, separators becoming more visible.
4
If elements that were previously hard to distinguish become clearly visible with this setting, the original contrast was borderline or failing.
Failure signal: Input borders, dividers, or secondary text that were nearly invisible at default settings become visible only after enabling Increase Contrast. The default state was a contrast failure.
Test 2: Differentiate Without Colour
WCAG 1.4.1
1
Go to Settings, Accessibility, Display and Text Size. Toggle Differentiate Without Colour ON.
2
Navigate through the app: status indicators, form validation states, charts, navigation tabs.
3
Check whether any previously colour-coded information loses its meaning.
Failure signal: Status dots become the same neutral colour. Error and success states look identical. Selected and unselected tabs become indistinguishable. Any of these is a WCAG 1.4.1 failure.
Pass looks like: Status indicators use shape or icon plus colour. Error states include an icon or text label. Meaning is preserved without colour.
Test 3: Colour Filters: Deuteranopia simulation
WCAG 1.4.1
1
Settings, Accessibility, Display and Text Size, Colour Filters. Toggle Colour Filters ON.
2
Select Green/Red Filter (Deuteranopia). This simulates the most common form of colour blindness.
3
Navigate through the app. Pay attention to: status indicators, charts, form validation, success/error states, notification badges.
4
Repeat with Red/Green Filter (Protanopia) and Greyscale for thorough coverage.
Failure signal: Red error states and green success states become the same brown-yellow colour. Available and Unavailable status dots are indistinguishable. Chart segments that relied on red vs green lose their distinction.
Test 4: DAC Color Contrast Checker app
WCAG 1.4.3 · 1.4.11
1
Download DAC Color Contrast Checker from the App Store.
2
Take a screenshot of the screen you want to test.
3
Open DAC Color Contrast Checker, import the screenshot. It overlays contrast ratio measurements on each text element.
4
Review elements flagged below 4.5:1 (normal text) or 3:1 (large text and UI boundaries).
Useful for: Native app screens inaccessible to browser-based tools. Screenshots of system dialogs, onboarding flows, and notification previews.
Test 5: Accessibility Scanner
WCAG 1.4.3 · 1.4.11
1
Download Accessibility Scanner by Accessible Developer Ltd from the App Store.
2
Open Accessibility Scanner and navigate to the screen you want to test within your app.
3
Accessibility Scanner scans the live screen and reports contrast ratios with WCAG pass/fail status per element. No screenshot needed.
DAC vs Accessibility Scanner: Accessibility Scanner scans live screens directly. DAC Color Contrast Checker works from screenshots. Use both for cross-verification on critical screens.
Test 6: Text over gradients or photos
WCAG 1.4.3
1
Navigate to any hero banner, card, or section with text sitting directly on a gradient or photo background.
2
Screenshot it and open it in DAC Color Contrast Checker.
3
Sample contrast at both the lightest and darkest points of the background under the text, not just one spot.
Failure signal: Contrast is fine where the background is darkest but drops well below 4.5:1 where the gradient or photo is lightest. A single-point automated reading misses this: only sampling multiple points catches it.
Test 7: Placeholder text contrast
WCAG 1.4.3
1
Find a form field whose only visible label is its placeholder text.
2
Screenshot it before typing anything, and check the placeholder's contrast against the input background with DAC.
3
Check again with Increase Contrast OFF: some placeholder colours are only fixed by that setting, not by default.
Failure signal: Placeholder text is noticeably lighter than body text and measures below 4.5:1. Since many forms use the placeholder as the field's only label, this is a labelling failure as well as a contrast one.
Test 8: Disabled control contrast
WCAG 1.4.3
1
Find a disabled button or input, for example a Submit button before required fields are filled in.
2
Confirm it's genuinely disabled: it doesn't respond to a tap and VoiceOver skips over it or announces "dimmed."
3
Check its contrast with DAC anyway, for reference.
What correct looks like: A genuinely disabled control is exempt from the 4.5:1 requirement: low contrast alone isn't a defect here. Flag it instead if the control still responds to taps while looking disabled: that's a state bug, not a contrast one.
Test 9: Contrast in dynamic states
WCAG 1.4.3 · 1.4.11
1
Trigger each interactive state in turn: tap into a field to focus it, select a tab, submit a form to trigger its error state, select an item in a list.
2
Screenshot each state and check contrast with DAC, or scan live with Accessibility Scanner.
3
Compare each against that same element's default, resting-state contrast.
Failure signal: A field's border or text meets contrast at rest, but the colour used for its focus, selected, or error state does not. Testing only the default state misses these entirely.

Test 1: High Contrast Text
WCAG 1.4.3
1
Settings, Accessibility, Display. Toggle High Contrast Text ON.
2
Navigate through the app. Look for text that becomes easier to read or changes appearance significantly.
Failure signal: Text that is noticeably harder to read at default and only becomes clear with High Contrast Text ON was likely below the 4.5:1 threshold. Note the specific text and screen for logging.
Test 2: Colour Correction: Deuteranomaly
WCAG 1.4.1
1
Settings, Accessibility, Colour and Motion, Colour Correction. Toggle ON. Select Deuteranomaly.
2
Navigate through status indicators, charts, form validation states, and navigation tabs.
3
Repeat with Protanomaly and Tritanomaly for full coverage.
Failure signal: Red and green indicators become the same brown-yellow. Any colour-coded meaning that is lost is a WCAG 1.4.1 failure.
Test 3: Accessibility Scanner
WCAG 1.4.3 · 1.4.11
1
Install Accessibility Scanner from the Play Store.
2
Enable it: Settings, Accessibility, Accessibility Scanner, Allow. A floating button appears.
3
Navigate to the screen to test. Tap the blue floating button to scan.
4
Scanner highlights elements with issues. Tap each highlight to see the exact contrast ratio and the required minimum.
5
Use the Record feature to scan multiple screens automatically as you navigate.
What it catches: Text contrast failures with exact ratios, small touch target sizes, missing content descriptions. It does not catch colour-only signals: that requires the Colour Correction tests above.
Test 4: DAC Color Contrast Checker app
WCAG 1.4.3 · 1.4.11
1
Download the DAC app from Google Play Store.
2
Take a screenshot of the screen to test. Open DAC, import the screenshot.
3
DAC Color Contrast Checker overlays measurements on each text element. Review all flagged items below 4.5:1.
Use DAC when: Accessibility Scanner cannot access a screen (system dialogs, permission prompts, onboarding flows). DAC works on any screenshot regardless of the source.
