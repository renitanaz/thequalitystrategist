36 Testing Video and Audio: Captions, Transcripts and Audio Descriptions

A video without captions excludes deaf users. A video without an audio description excludes blind users. Both are required for WCAG 2.1 AA compliance.

1. WCAG 1.2: The Media Criteria

WCAG 1.2 media success criteria
CriterionLevelRequirement
1.2.1 Audio-only and Video-only (Prerecorded)AAudio-only: provide a transcript. Video-only (no audio): provide a transcript or audio description.
1.2.2 Captions (Prerecorded)AAll prerecorded audio content in video has captions. Auto-generated captions without review do not meet this criterion.
1.2.3 Audio Description or Media Alternative (Prerecorded)AProvide an audio description or a text alternative for prerecorded video. Can be met by 1.2.5 at AA.
1.2.4 Captions (Live)AAAll live audio content in live video has captions. Real-time captions required.
1.2.5 Audio Description (Prerecorded)AAAudio description provided for all prerecorded video content. Required for WCAG 2.1 AA.
For WCAG 2.1 AA: 1.2.2 (captions on prerecorded video) and 1.2.5 (audio description on prerecorded video) are both required. 1.2.4 (live captions) is also required if your product includes live video.

2. Testing Captions

Captions are synchronised text of the audio track in a video. They must include all spoken dialogue, identify speakers when there is more than one, and include relevant non-speech audio (music cues, sound effects that convey meaning).

What to test

  • Captions are present: Play the video. Enable captions. If no caption option exists, the video fails 1.2.2.
  • Captions are synchronised: Captions must appear and disappear in sync with the audio. Captions that appear 5 seconds late are not accessible: the context is lost.
  • Captions are accurate: Watch 2 to 3 minutes of the video with captions enabled and audio off. Every word must be correctly transcribed. Auto-generated captions with uncorrected errors fail 1.2.2.
  • Speaker identification: When multiple speakers are present, captions must identify who is speaking. "INTERVIEWER:" or "[Sarah:]" are acceptable formats.
  • Non-speech audio: Relevant sound effects must be captioned: "[phone ringing]", "[applause]", "[tense music]". Background music does not need to be described unless it conveys meaning.
  • Auto-generated captions: Auto-generated captions (YouTube auto-captions, Teams auto-transcription) must be reviewed and corrected before they count as accessible. They are a starting point, not a finished product.

3. Testing Transcripts

A transcript is a text version of all audio content. For audio-only content (podcasts, audio interviews), a transcript is required at WCAG Level A. For video, a transcript may be provided as an alternative to audio description in some cases.

What to test

  • Transcript is linked near the media: The transcript must be easy to find: linked directly below or beside the video, not buried in a separate page.
  • Transcript includes all spoken content: Read through the transcript while watching. Every piece of dialogue must be present.
  • Transcript includes non-speech information: Speaker labels, meaningful sound effects, and descriptions of visual-only information that is referenced in the audio.
  • Transcript is accessible: The transcript document itself must pass basic accessibility: proper heading structure, readable font size, no inaccessible PDF format without tagged structure.

4. Testing Audio Descriptions

An audio description is a narration added to the audio track that describes important visual content that is not conveyed by the existing audio. It is required when the video contains visual information that a blind user would otherwise miss: on-screen text, demonstrations, changes in scene, facial expressions that carry meaning.

What to test

  • Audio description is available: Check whether the media player offers an audio description track. If visual information in the video is not described in the existing narration, and no audio description track exists, the video fails 1.2.5.
  • Audio description covers all important visual information: Watch the video with audio description enabled (or listen only). Any on-screen text read by a presenter, any demonstration of a product feature, any diagram shown without verbal description: all must be covered.
  • Extended audio description: When pauses in the main audio are not sufficient for descriptions, extended audio description (which pauses the video to allow full description) is required. This is a Level AAA criterion but may be needed at AA if the existing pauses are too short.

5. Testing the Media Player Itself

The media player controls must be accessible independently of the media content. Many embedded players have inaccessible controls even when the content itself has captions and descriptions.

  • All controls keyboard accessible: Tab through every control: play, pause, volume, mute, full screen, captions toggle, speed, progress bar. All must be reachable and operable by keyboard.
  • Controls have accessible names: NVDA must announce each control with a meaningful label: "Play, button", "Captions off, button". An icon button with no aria-label fails 4.1.2.
  • Progress bar is operable: The video timeline must be reachable by keyboard and adjustable with arrow keys. It must announce the current position.
  • Focus indicators visible: Every focused control must show a visible focus indicator. Check all controls by tabbing through the player.
  • Autoplay: If the video autoplays with audio, a mechanism to stop or pause it within 3 seconds must be the first keyboard stop on the page (WCAG 1.4.2).

How to Test: Tiers and Platform Coverage

Tier 1: Pipeline automation

No automated tool can verify caption accuracy, audio description completeness, or transcript quality. The only automated check available is confirming a <track> element is present on a <video>: axe-core checks this under the video-caption rule. This is a necessary but not sufficient check: a track element with an empty or auto-generated file still passes axe.

Tier 2: Semi-automated tools

  • axe DevTools: Run on any page with embedded video. Checks for missing track element on video elements and missing accessible name on media player controls.
  • WAVE: Flags missing captions track and inaccessible media player controls.
  • Browser DevTools: Inspect the video element: verify a <track kind="captions"> element is present with a valid src attribute pointing to a real caption file.

Tier 3: Manual: all media testing is here

The vast majority of WCAG 1.2 testing is manual. No tool can watch a video and judge whether the captions are accurate, synchronised, or complete.

  • Captions (all platforms): Enable captions. Watch 2 to 3 minutes of the video with audio off. Every word must be correct. Speaker changes must be identified. Non-speech audio must be described.
  • Audio description: Enable audio description track if available. Listen to the video without watching. All visual-only information must be described.
  • Transcript: Read the transcript against the audio. Every word present. Non-speech content described. Speaker labels present where needed.
  • Media player keyboard (Windows + Mac): Tab through all controls. Play, pause, volume, captions toggle, full screen, seek bar: all keyboard accessible with visible focus indicators.
  • NVDA + Firefox (Windows): Tab to each media player control. Verify it announces label and role. Seek bar must announce current position.
  • VoiceOver + Safari (Mac): Same control walkthrough. Safari has native video player support.
  • iOS VoiceOver: Test embedded video in Safari on iPhone. Verify captions available and media controls accessible by swipe.
  • Android TalkBack: Test in Chrome on Android. Verify captions toggle and player controls accessible.

The minimum for WCAG 2.1 AA
  • Every prerecorded video with audio must have accurate, synchronised captions (1.2.2).
  • Every prerecorded video must have an audio description track for visual content not in the audio (1.2.5).
  • Auto-generated captions must be reviewed and corrected before they count as meeting 1.2.2.
  • The media player controls must be fully keyboard accessible with meaningful accessible names.
