22 VoiceOver on Mac: In-Depth Testing with VoiceOver and Safari

VoiceOver is already installed. Safari is already running. There is no excuse to skip Mac screen reader testing.

1. Why VoiceOver on Mac

VoiceOver is Apple's built-in screen reader for macOS. It is free, requires no installation, and when paired with Safari provides the most representative test environment for Mac users. The VoiceOver and Safari combination is tightly integrated: behaviours tested in Chrome may differ, so always use Safari for primary VoiceOver testing.

2. Setup and Configuration

  • Enable/disable: Cmd+F5
  • VO key: Ctrl+Option: referred to as VO throughout
  • Recommended browser: Safari: always use Safari for primary testing
  • Speech rate: VO+F8 opens VoiceOver Utility. Under Speech, adjust rate. Slower when learning, faster with experience.
  • Verbosity: VO+F8, Verbosity: controls how much detail VoiceOver announces. Default is suitable for testing.
  • Full Keyboard Access: System Settings, Accessibility, Keyboard, Full Keyboard Access ON: required to Tab to all UI elements including non-form elements

4. The Rotor

The rotor (VO+U) is VoiceOver's most powerful navigation tool. It opens a dialog that lists all elements of a specific type on the page. Use arrow keys to navigate within each list, and left/right arrows to switch between categories.

Key rotor categories for testing: Headings (structural audit), Links (link text audit), Form Controls (label audit), Tables (table structure audit), Landmarks (page regions audit), Web Spots (custom VO bookmarks).

Open the rotor at the start of every page test. Check Headings for structural logic. Check Links for non-descriptive text. Check Form Controls to verify every input has a label. This three-step check takes under two minutes per page.

5. What to Test and What to Listen For

Headings

VO+Cmd+H cycles through headings. VO+U, Headings shows the complete list. Listen for: heading level announced before the text. A visual heading with no level announcement is a div styled as a heading: not a semantic element.

Correct: "Heading level 2, Our services" | Failure: "Our services" with no level

Forms

Tab to each field. VoiceOver announces label, type, required state, and any associated description. Submit with empty fields: errors with role="alert" are announced immediately. On refocus of an error field, the error description via aria-describedby is re-announced.

Correct: "Email address, required, text field" | Failure: "text field" with no label

Custom components

For custom dropdowns, accordions, and tabs: VoiceOver must announce the role (button, combobox, tab), the current state (expanded/collapsed, selected/not), and any associated label. Missing state announcements are ARIA implementation failures.

6. Safari Accessibility Inspector

Safari Developer Tools includes an Accessibility Inspector. Enable it at Safari Preferences, Advanced, Show features for web developers. In the Inspector panel, select any element to see its computed accessible name, role, and properties: equivalent to Chrome DevTools accessibility tree but specific to Safari/VoiceOver rendering.

The fast check
  • VO+U, Headings: structural audit in 30 seconds
  • VO+U, Links: any "read more" or "click here" visible immediately
  • VO+U, Form Controls: every unlabelled field visible immediately
