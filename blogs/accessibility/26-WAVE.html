26 WAVE: Visual Accessibility Testing in the Browser

WAVE overlays your page with icons that show exactly where accessibility issues are and what caused them. No report to parse. No line numbers to chase. The issue is right there on the element.

1. What WAVE Is and How It Works

WAVE (Web Accessibility Evaluation Tool) is a free browser extension developed by WebAIM. It injects visual icons directly onto the page: on top of the elements they relate to: so you can see accessibility issues in context rather than reading a disconnected report.

Unlike automated CI tools that produce a list of violations with DOM selectors, WAVE shows you the issue visually in the rendered page. A missing form label appears as a red icon on the input field itself. An empty button appears as an error icon on that button. This makes WAVE significantly faster for triage and explanation than reading a JSON report.

WAVE is a Tier 2 semi-automated tool. It runs in the browser on the rendered page, catching issues that require visual context and DOM inspection. It does not integrate into your CI/CD pipeline. Use it alongside axe-core in your pipeline: not instead of it.

WAVE is available as a Chrome and Firefox extension, and as a web service at wave.webaim.org for publicly accessible pages. The extension also works on pages behind authentication, which the web service cannot access.

2. The Icon System: Errors, Alerts, Features and Structure

WAVE uses a colour and letter-coded icon system. Understanding the icons is the foundation of using WAVE quickly.

E
Errors (red)
Definite WCAG failures. Missing alt text, empty buttons, missing form labels, empty links, missing document language. Act on every error.
!
Alerts (yellow)
Possible issues requiring human judgement. Suspicious link text ("read more"), missing fieldset legend, redundant title attribute, very small text. Investigate each one.
✓
Features (green)
Accessibility features present and detected. Alt text, form labels, ARIA landmarks, skip links. Confirm they are correct: presence does not guarantee quality.
S
Structural (blue)
Semantic HTML elements: headings (H1–H6), lists, tables, regions. Used to audit heading hierarchy and page structure visually.
C
Contrast (purple)
Colour contrast failures. WAVE flags elements where foreground and background colour combination fails WCAG 1.4.3 (minimum 4.5:1 for normal text).
A
ARIA (grey)
ARIA roles and attributes detected. Confirms ARIA is present but does not validate correct usage. Cross-reference with axe DevTools for ARIA validation.

3. How to Use WAVE Systematically

A systematic WAVE session follows this sequence on every page:

  1. Install the extension: WAVE Chrome extension or Firefox Add-on from WebAIM.
  2. Activate WAVE: Click the WAVE icon in the browser toolbar. The sidebar opens and icons appear on the page.
  3. Check the summary first: The sidebar shows counts for Errors, Alerts, Features, Structural elements, Contrast errors, and ARIA. Zero errors is the minimum target.
  4. Work through errors first: Click each red E icon. The sidebar shows the specific failure, which WCAG criterion it relates to, and a code snippet. Fix errors before investigating alerts.
  5. Review alerts: Each yellow alert requires human judgement. "Suspicious link text" is not automatically a failure: "Read more" on a standalone card where the heading provides context may be acceptable. "Read more" in a links list is a failure.
  6. Audit structural elements: Click the Structure tab in the sidebar. WAVE shows the heading hierarchy, list structure, and landmarks. Verify the heading levels are logical.
  7. Check features for quality: Green icons confirm accessibility features exist but not that they are correct. Click each green icon to see the alt text, label text, or landmark label and verify it is meaningful.
  8. Review contrast: Purple icons flag contrast failures. Click to see the exact ratio and the WCAG threshold it fails.
WAVE modifies the page in order to show icons. Some dynamic features may break during a WAVE session: modals may not open, JavaScript interactions may stop working. Toggle WAVE off (click the icon again) to restore normal page behaviour for testing dynamic content.

5. What WAVE Misses

WAVE catches structural and attribute-level failures well. It cannot catch issues that require runtime behaviour, human judgement about context, or dynamic content testing.

Issues WAVE cannot detect and why
Issue Why WAVE misses it How to test instead
Keyboard trapsRequires keyboard navigation: no static analysis can replicate itManual keyboard testing
Focus order problemsRequires Tab navigation to observeManual keyboard testing
ARIA live region announcementsRequires a screen reader running at the same timeNVDA or VoiceOver testing
Dynamic content after interactionWAVE scans the DOM at load: post-interaction state is not scannedTrigger interactions, then re-run WAVE or use axe DevTools
Meaningful alt text qualityWAVE confirms alt text exists, not whether it is descriptiveRead every alt text manually
Correct ARIA usageWAVE flags ARIA presence, not validity of role/state/property combinationsaxe DevTools for ARIA validation
Zoom and reflow failuresRequires viewport resize or browser zoomDevTools responsive mode at 320px
Custom component semanticsCannot evaluate whether a custom widget behaves as its role impliesScreen reader testing
Cognitive accessibilityReading level, plain language, consistent navigation: no automated check existsManual review

6. WAVE vs axe DevTools

Both tools serve different purposes and are best used together rather than choosing one over the other.

WAVE vs axe DevTools comparison
Aspect WAVE axe DevTools
Primary useVisual in-page overlay, fast triageDetailed violation reporting, CI/CD integration
Output formatIcons on the pageStructured report with DOM references
Best forShowing issues in context, communicating to developersPrecise rule-based detection, automated pipeline checks
Alerts vs errorsDistinguishes errors (definite) from alerts (possible)Categorises by impact (critical, serious, moderate, minor)
Contrast checkingBuilt in, visual on pageBuilt in, reported with exact ratios
Dynamic contentScans initial DOM onlyCan be triggered post-interaction via API
ARIA validationFlags ARIA presence, not correctnessValidates ARIA role, state, and property combinations
CI/CD pipelineNot possibleCore use case via axe-core npm package
CostFreeFree (Pro version available)
The right workflow: run axe-core in the pipeline to catch failures at build time, and use WAVE in the browser for visual triage and communicating issues to developers and designers who are not reading axe JSON output.

7. WCAG 2.1 AA Coverage

WAVE is strongest on Perceivable and Robust criteria: image alt text, form labels, colour contrast, semantic structure, and document properties. It has weaker coverage of Operable criteria (keyboard, focus) and Understandable criteria (error identification, labels and instructions) because those require runtime interaction.

WCAG 2.1 AA criteria and WAVE coverage
WCAG principle WAVE coverage Gaps requiring manual testing
1. PerceivableStrong: alt text, colour contrast, headings, labelsAlt text quality, audio/video captions, reflow
2. OperablePartial: skip links, page titles, link purpose (text only)Keyboard access, focus order, focus visibility, timing
3. UnderstandablePartial: document language, form labelsError identification, error suggestion, consistent navigation
4. RobustPartial: parsing, ARIA presenceARIA correctness, live region behaviour, status messages
WAVE alone is not sufficient for a WCAG 2.1 AA audit. Treat it as one layer in a testing stack: axe-core in CI for automated coverage, WAVE in the browser for visual triage, manual keyboard testing, and screen reader testing for the remainder.
The fast WAVE workflow
  • Activate WAVE on the page. Check the sidebar summary: zero errors is the floor.
  • Click every red E icon. Read the description. Log each one as a defect with the WCAG criterion.
  • Review yellow alerts. Decide per alert: is this a genuine failure in context? Log the ones that are.
  • Click the Structure tab. Verify heading hierarchy is logical and no levels are skipped.
  • Click green feature icons for alt text and labels. Read them. Meaningful? If not, log as a defect even though WAVE marked it green.
