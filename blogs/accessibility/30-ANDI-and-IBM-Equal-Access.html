30 ANDI and IBM Equal Access: Specialist Tools for Accessible Names and Deep Scanning

ANDI inspects accessible names and descriptions element by element. IBM Equal Access scans entire sites and exports to spreadsheet. Different jobs, both free.

1. What ANDI Is

ANDI (Accessible Name and Description Inspector) is a free bookmarklet developed by the US Social Security Administration. It is designed specifically for inspecting how assistive technologies compute the accessible name and description of interactive elements. It does not produce a violation list: it is an inspection tool for understanding what a screen reader will announce for a specific element.

ANDI is particularly useful when axe DevTools flags a violation involving an accessible name and you need to understand exactly what name is being computed and why. It shows the full accessibility tree properties for each element: accessible name, description, role, state, and the source of each (aria-label, aria-labelledby, native label, title, placeholder).

ANDI is not a scanner. It is an inspector. Use it to diagnose why a specific element has the wrong accessible name: not to find all issues on a page.

2. How to Use ANDI

  • Install: Drag the ANDI bookmarklet from ssa.gov/accessibility/andi to your bookmarks bar. Works in Chrome, Firefox, Edge.
  • Activate: Click the ANDI bookmark on any page. An ANDI panel appears at the top of the page.
  • Select a module: ANDI has modules for Focusable Elements, Images, Links, Buttons, Structure, Tables, Lists, and Colour Contrast.
  • Inspect elements: Click any element on the page. ANDI shows: accessible name, description, role, state, and which attribute is providing the name (aria-label, aria-labelledby, label for/id, title, placeholder, native text).
  • Use arrow navigation: Use the Next/Previous buttons in the ANDI panel to step through all elements of the selected type without using the mouse.
  • Alerts tab: ANDI flags accessibility alerts for the elements it inspects. These are not violations: they are warnings that require human review.

The most useful ANDI checks

  • Focusable Elements: Step through every interactive element. For each one, verify the announced name is meaningful and the role is correct.
  • Tables module: Shows header associations, scope attributes, and whether ANDI can determine the accessible name for each cell.
  • Structure module: Shows heading levels and landmark regions in sequence: fastest way to verify heading hierarchy without a screen reader.

How to Test With ANDI and IBM Equal Access

Tier 1: Pipeline automation

ANDI is a bookmarklet: it has no CI/CD integration. IBM Equal Access has a Node CLI (npm install -g accessibility-checker) that can scan URLs and fail builds. Run it alongside axe-core for broader automated coverage since the two engines catch different violations.

npx accessibility-checker https://example.com --outputFormat json

Tier 2: Semi-automated: ANDI and IBM in the browser

ANDI:

  • Drag the ANDI bookmarklet to your bookmarks bar. Click it on any page.
  • Use Focusable Elements to inspect accessible names on every interactive element
  • Use Images to verify all alt text and its source attribute
  • Use Tables to verify column header associations per cell
  • Use Structure to audit heading hierarchy visually
  • Platforms: Chrome, Firefox, Edge on Windows and Mac. ANDI does not run on mobile browsers.

IBM Equal Access:

  • Install the IBM Equal Access Chrome extension
  • Open DevTools, Accessibility Checker panel, click Scan
  • Filter to WCAG 2.1 AA. Export XLSX for multi-page audit reporting.
  • Platforms: Chrome and Firefox on Windows and Mac.

Tier 3: Manual: what these tools cannot catch

  • Accessible name quality: ANDI shows the name and its source. You decide if it is meaningful and descriptive.
  • Screen reader announcements: NVDA + Firefox on Windows confirms whether ANDI's reported name is what the screen reader actually announces.
  • iOS VoiceOver: Physical iPhone + Safari. ANDI does not run on iOS.
  • Android TalkBack: Physical Android device + Chrome.
  • Native app accessible names: For iOS use accessibilityLabel, for Android use contentDescription: these are not inspectable by ANDI but are equivalent to HTML accessible names.

4. What IBM Equal Access Is

IBM Equal Access Accessibility Checker is a free browser extension developed by IBM. It uses a different rule engine from axe-core, which means it catches a different set of violations. Running IBM Equal Access alongside axe DevTools gives broader automated coverage than either tool alone.

IBM Equal Access is particularly strong on Section 508 compliance (US federal accessibility standard), ARIA validation, and multi-page scanning. It exports results to an Excel spreadsheet: useful for enterprise audit reporting and tracking remediation across a large site.

5. How to Use IBM Equal Access

  • Install: IBM Equal Access Chrome Extension or Firefox Add-on.
  • Open DevTools: F12, find the Accessibility Checker panel in the DevTools tabs.
  • Run a scan: Click Scan. Results appear grouped by violation type with element references.
  • Filter by WCAG level: Filter to WCAG 2.1 AA to focus on required criteria only.
  • Export: Export to XLSX for tracking across multiple pages and reporting to stakeholders.
  • Multi-page scan: IBM Equal Access can scan multiple URLs in sequence via its reporting feature: useful for site-wide audits.

The specialist case for each
  • ANDI: use it any time you need to understand what a screen reader will announce for a specific element. It is the fastest way to diagnose accessible name and description issues.
  • IBM Equal Access: use it alongside axe DevTools for broader automated coverage, for Section 508 requirements, and when you need an exportable multi-page audit report.

Mobile Testing: What These Tools Cannot Do

Browser-based tools like axe DevTools, WAVE, and Lighthouse run on desktop browsers. They cannot test native mobile apps, and they cannot replicate the experience of a screen reader user on a phone. The issues these tools catch still need to be verified on mobile. Use these apps to test the same failure patterns in a native mobile context.
