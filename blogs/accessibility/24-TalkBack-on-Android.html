24 TalkBack on Android: Screen Reader Testing on Android

TalkBack is the screen reader for a billion Android users. Every mobile accessibility test programme needs it.

1. Why TalkBack

TalkBack is Google's built-in screen reader for Android. It is pre-installed on all Android devices and is the primary assistive technology for Android users with visual impairments. Testing must be done on a physical device: Android Emulator does not replicate TalkBack gesture behaviour or reading order accurately.

Settings paths for TalkBack vary by Android version and device manufacturer. Samsung devices in particular use a different location on some versions. If a path below does not match what you see, search "TalkBack" in the Settings search bar.

2. Enabling and Configuring TalkBack

  • Enable: Settings, Accessibility, TalkBack, Toggle ON. Confirm the dialog: once TalkBack is on, all interactions require the TalkBack gestures.
  • Shortcut: Hold both volume buttons simultaneously for 3 seconds if the shortcut is configured at Settings, Accessibility, TalkBack, TalkBack shortcut.
  • Speech rate: Settings, Accessibility, TalkBack, Settings, Text to Speech settings
  • Recommended browser: Chrome on a physical Android device
  • Pause TalkBack: Three-finger single tap pauses speech

4. Reading Controls

Reading controls (swipe up then right) open TalkBack's navigation mode selector: the equivalent of VoiceOver's rotor. Select a category (Headings, Controls, Links, Characters, Words, Paragraphs) then swipe right/left to navigate between items of that type.

Key categories for testing: Headings (page structure), Controls (form labels and buttons), Links (link text quality), Default (element by element).

5. What to Test and What to Listen For

Headings

Reading controls, Headings. Swipe through all headings. TalkBack announces: "Heading, level 2, Our services." Missing heading level or no heading announcement indicates a visual-only heading (div or span styled as heading, not an h1-h6 element).

Forms

Reading controls, Controls. Navigate through all form fields. TalkBack announces the content description (the label), the field type (edit box), and the required state. Submit with errors: live region alerts must be announced immediately. Navigate back to error fields: the error description must be re-announced.

Correct: "Email address, required, edit box" | Failure: "edit box" with no label

Images

When TalkBack focus lands on an image: it announces the content description (alt text equivalent for native apps) or "unlabelled image" if none is set. In web pages, TalkBack reads the HTML alt attribute. For native app images, the Android contentDescription attribute must be set.

Dynamic content

Navigate away from a live region. Trigger an update. TalkBack must announce aria-live="polite" content when idle and role="alert" content immediately. For native Android apps, the equivalent is ViewCompat.setAccessibilityLiveRegion(): TalkBack behaviour is the same but the implementation differs from web.

6. Explore by Touch

TalkBack includes Explore by Touch: sliding a finger across the screen announces whatever is under the finger. This is useful for discovering the visual layout and checking that interactive elements are reachable by touch. Any area of the screen that can be tapped by a sighted user must be reachable and operable via TalkBack.

The testing flow
  • Reading controls, Headings: structural audit
  • Reading controls, Controls: form label audit
  • Reading controls, Links: link text audit
  • Navigate away from dynamic content areas, trigger updates, listen
  • Use Explore by Touch to find any areas that are visually interactive but not announced by TalkBack
