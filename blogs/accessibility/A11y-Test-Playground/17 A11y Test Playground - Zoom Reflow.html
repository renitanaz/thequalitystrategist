Zoom and Reflow Playground

Eight scenarios covering reflow at 320px, zoom failures at 200% and 400%, and reduced motion. Use Chrome DevTools responsive mode (320px) and browser zoom controls (Ctrl/Cmd +) to test each scenario.

🎯 Open DevTools first. Set responsive mode to 320px for reflow scenarios. Switch to 400% browser zoom for zoom scenarios.
1
Horizontal scroll at 320px: reflow failure
Fixed-width container forces horizontal page scroll.
What to do: Open DevTools, set viewport to 320px. Look at the demo below. WCAG 1.4.10Chrome DevTools

What to look for: The fixed-width container extends beyond 320px, causing a horizontal scrollbar on the page.
Scenario 1: fixed-width overflow
This container is 600px wide. At a 320px viewport it causes horizontal overflow. The user must scroll horizontally to read the full content: which is a WCAG 1.4.10 failure. Every word that extends beyond the viewport is inaccessible without horizontal scroll.
Fail WCAG 1.4.10 Fixed width 600px exceeds 320px viewport

Desktop nav with no mobile fallback. Items overflow off-screen.
What to do: Set DevTools to 320px. Check the nav bar below. WCAG 1.4.10Chrome DevTools

What to look for: Nav items overflow off the right edge. No hamburger menu. Items are unreachable.

3
Text overlaps at 200% zoom: fixed-height container
Container height is fixed. Text grows. Overflow clips.
What to do: Zoom browser to 200% (Ctrl/Cmd +). Look at the card below. WCAG 1.4.4Browser zoom

What to look for: The card has a fixed height of 80px. At 200% zoom, the text grows but the container does not: text is clipped and the button disappears.
Scenario 3: fixed-height container clips text at zoom

This card has a fixed height of 80px. At 200% zoom the text grows but the card does not. The button below the text disappears.

Fail WCAG 1.4.4 height:80px clips content at zoom: use min-height
4
Data table forces page-level horizontal scroll
Table scrolls the whole page: not a contained scroll area.

What to look for: The table is not in a scrollable wrapper. At 320px it forces the entire page to scroll horizontally, making ALL other content inaccessible without horizontal scroll.

Animation does not respect prefers-reduced-motion
Enable Reduce Motion in OS: animation still plays.
What to do: Open Chrome DevTools, Rendering panel, Emulate CSS media: prefers-reduced-motion: reduce. Observe the spinner and shimmer below. WCAG 2.3.3Chrome DevTools Rendering

What to look for: Spinner and shimmer continue at full intensity under reduced-motion emulation. No @media (prefers-reduced-motion) override in their CSS.
Scenario 5: animations ignoring prefers-reduced-motion
Spinner: no reduced-motion override
Skeleton shimmer: no reduced-motion override
Fail WCAG 2.3.3 No @media (prefers-reduced-motion) override
6
Auto-playing carousel with no pause control
Content moves. No way to stop it.
What to do: Observe the carousel below. Attempt to pause it. WCAG 2.2.2

What to look for: Carousel advances automatically every 3 seconds. No pause button. No keyboard mechanism to stop it. Content that moves continuously is a distraction and fails 2.2.2.
Scenario 6: auto-playing carousel, no pause

Slide 2: New product launch

No pause button. Carousel advances every 3 seconds without user control.
