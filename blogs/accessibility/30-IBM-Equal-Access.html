30 IBM Equal Access: A Secondary Scanner for Section 508 and Site-Wide Audits

A second automated engine to run alongside axe-core, not instead of it: different rule set, Section 508 coverage, and multi-page XLSX exports.

Series: Shift-Left Accessibility ·Blog 30 of 41 ·6 min read
In this blog

IBM Equal Access is a secondary tool. It is a second automated scanner to run alongside axe-core, not a replacement for it: use it when you specifically need Section 508 coverage, a different rule engine's second opinion, or a multi-page audit you can hand to stakeholders as a spreadsheet.

1. What IBM Equal Access Is

IBM Equal Access Accessibility Checker is a free browser extension developed by IBM. It uses a different rule engine from axe-core, which means it catches a different set of violations. Running IBM Equal Access alongside axe DevTools gives broader automated coverage than either tool alone.

IBM Equal Access is particularly strong on Section 508 compliance (US federal accessibility standard), ARIA validation, and multi-page scanning. It exports results to an Excel spreadsheet: useful for enterprise audit reporting and tracking remediation across a large site.

In practice: point it at a list of URLs, let it scan overnight, and it hands back one spreadsheet with every page's violations, counted by severity. That single exportable file is what makes it worth running alongside axe-core for a site-wide audit.

2. How to Use IBM Equal Access

  • Install: IBM Equal Access Chrome Extension or Firefox Add-on.
  • Open DevTools: F12, find the Accessibility Checker panel in the DevTools tabs.
  • Run a scan: Click Scan. Results appear grouped by violation type with element references.
  • Filter by WCAG level: Filter to WCAG 2.1 AA to focus on required criteria only.
  • Export: Export to XLSX for tracking across multiple pages and reporting to stakeholders.
  • Multi-page scan: IBM Equal Access can scan multiple URLs in sequence via its reporting feature: useful for site-wide audits.

Why bother with a second scanner
  • IBM Equal Access is a secondary tool: run it alongside axe DevTools, not instead of it. Its value is the parts axe doesn't cover, not broader replacement coverage.
  • Reach for it specifically for Section 508 requirements, a second engine's opinion on ARIA validity, or an exportable multi-page audit report for stakeholders.

How to Test With IBM Equal Access

Tier 1: Pipeline automation

IBM Equal Access has a Node CLI (npm install -g accessibility-checker) that can scan URLs and fail builds. The binary is achecker, not the package name, and it scans a text file listing URLs rather than taking a single URL as an argument. Run it alongside axe-core for broader automated coverage since the two engines catch different violations.

echo "https://example.com" > urls.txt
npx achecker urls.txt

Tier 2: Semi-automated: IBM Equal Access in the browser

See Section 2 above for the full workflow: install, open DevTools, run a scan, filter by WCAG level, and export. Platforms: Chrome and Firefox on Windows and Mac.

Tier 3: Manual: what IBM Equal Access cannot catch

  • Screen reader announcements: NVDA + Firefox on Windows, VoiceOver + Safari on Mac.
  • Accessible name quality: IBM Equal Access flags a missing name; it does not judge whether an existing one is meaningful. Use ANDI to inspect a specific element's computed name.
  • Keyboard navigation and focus order: requires Tab navigation to observe.
  • Dynamic content after interaction: a scan captures the DOM at load; trigger interactions, then re-run.
📱
Testing this on mobile
IBM Equal Access has no native-app equivalent: it is a browser extension and Node CLI, both DOM-based. For native iOS and Android apps to practise the same checks on, see Blog 41: Mobile Accessibility Testing Practice Apps.
