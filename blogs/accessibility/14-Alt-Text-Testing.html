14 Alt Text Testing: Meaningful vs Decorative vs Wrong

The screen reader does not see the image. It reads what you wrote. Write it wrong and the user hears garbage.

1. What WCAG 1.1.1 Requires

WCAG 1.1.1 (Non-text Content) requires that every non-text element has a text alternative that serves the equivalent purpose. The rule is not "add alt text to every image." The rule is that the text alternative must convey the same information the image conveys to a sighted user.

This means the requirement differs by image type. A meaningful image needs a description. A decorative image needs an empty alt attribute. A functional image needs alt text that describes its purpose, not its appearance.

A missing alt attribute and an empty alt attribute are not the same thing. Missing alt: the screen reader reads the filename. Empty alt (alt=""): the screen reader skips the image entirely. Both are correct in different situations. Both are wrong in others.

2. The Three Categories

The three image categories and their alt text requirements
Category Definition Correct alt text Example
Meaningful Conveys information that is not available in surrounding text A concise description of what the image shows and why it matters in context A chart showing Q3 revenue: alt="Bar chart showing Q3 revenue of £2.4M, up 18% from Q2"
Decorative Visual styling only. Removing the image would not change the meaning of the page alt="": empty string, no space. Screen reader skips it. A background swoosh, a divider illustration, a stock photo that adds no information
Functional An image that performs an action: a linked image, an icon button, a logo that links home Describes the destination or action, not the image itself A shopping cart icon that links to checkout: alt="Go to checkout" not alt="shopping cart icon"

3. Failure Patterns and What They Sound Like

Every alt text failure has a specific sound when read by a screen reader. Knowing what each failure announces helps testers identify and log defects precisely.

Fail
No alt attribute: <img src="chart.png">
NVDA announces: "chart dot png graphic"
The screen reader reads the filename. The user learns nothing about the image. Often worse with generated filenames like IMG_20241103_094512.jpg.
Fail
Filename as alt: <img src="hero.jpg" alt="hero.jpg">
NVDA announces: "hero dot jpg graphic"
Technically has an alt attribute. Functionally identical to no alt. Often added by CMSs that auto-populate alt from filename.
Fail
Generic alt: <img src="team.jpg" alt="image">
NVDA announces: "image graphic"
Meaningless. Also fails for alt="photo", alt="graphic", alt="icon". The word "image" is redundant: screen readers already announce the role.
Fail
Decorative image without empty alt: <img src="wave.svg" alt="decorative wave">
NVDA announces: "decorative wave graphic"
A decorative image should be silent. Using alt="decorative" or alt="decorative wave" makes the screen reader announce it anyway. Use alt="" instead.
Fail
Functional image describes appearance: <a href="/cart"><img src="cart.svg" alt="shopping cart icon"></a>
NVDA announces: "shopping cart icon link"
The user knows it looks like a cart. They do not know where the link goes. Alt text for a functional image must describe the destination or action: alt="Go to checkout".
Redundant
Alt text repeats surrounding text: <img src="ceo.jpg" alt="Jane Smith, CEO"> immediately followed by <h3>Jane Smith, CEO</h3>
NVDA announces: "Jane Smith, CEO graphic Jane Smith, CEO heading level 3"
Not a WCAG failure but a poor experience. The information is announced twice. Consider alt="" if the heading already provides the full context.
Pass
Meaningful image: <img src="chart.png" alt="Bar chart: Q3 revenue £2.4M, up 18% from Q2">
NVDA announces: "Bar chart: Q3 revenue £2.4M, up 18% from Q2, graphic"
The user gets the same information a sighted user gets from the chart. Concise, specific, in context.

4. How to Test: Automation, Tools, and Platform Coverage

🎯
Practice these yourself
All failure patterns above are available as interactive demos in the Alt Text Playground. Mobile testing steps are in the Mobile Testing Guide.

Tier 1: Pipeline automation

axe-core in Playwright or Cypress, and Pa11y, will flag:

  • Images with no alt attribute
  • Images with an empty alt attribute used on meaningful images (where the image has no surrounding text providing context)
  • Linked images where the alt text is empty and there is no other accessible name on the link
  • Role="img" elements with no accessible name

Tier 2: Semi-automated tools

  • WAVE Images panel: click the Images tab in WAVE to see every image on the page with its alt text listed alongside. Missing alt flagged in red. Suspicious alt (filename, very short strings) flagged in yellow. Fastest overview of the page's image alt health.
  • axe DevTools: filter by image-alt rule. Shows the exact element and the missing or empty alt attribute.
  • Chrome DevTools accessibility tree: select any image, check the accessibility panel. Shows the computed accessible name: confirms what the screen reader will actually announce.

Tier 3: Manual checks only

Automation detects missing or empty alt attributes. It cannot judge whether the alt text is accurate, relevant, or appropriate for context. These always require a human:

  • Filename as alt text: automation sees a non-empty alt attribute and passes. A human must check whether the value is a filename, a generic word, or meaningless.
  • Alt text that does not match the image: automation cannot see the image. Only a human can verify that the description is accurate.
  • Alt text that misses key information: a chart with alt="chart" passes some automated checks. A human must verify that the alt text conveys the data the chart shows.
  • Redundant alt text: automation does not check for duplication with surrounding text. A human reviewer or screen reader walkthrough catches this.
  • Functional image alt describing appearance not action: automation confirms the alt is non-empty. A human must verify it describes the destination or action, not the image.
  • Complex images: charts, diagrams, infographics, maps. These may need a long description in addition to a short alt. Only a human can judge whether the short alt is sufficient.

Windows: NVDA

Tab to each image or press G in NVDA browse mode to jump to the next graphic. NVDA announces the alt text. If it announces a filename, the alt is wrong. If it announces "graphic" with nothing else, the alt is missing or empty on a meaningful image. Press Insert+F7 to open the elements list and select Graphics to see all images and their alt text at once.

Mac: VoiceOver

Enable VoiceOver with Cmd+F5. Open the rotor with VO+U and navigate to Images. Every image and its announced name is listed. Alternatively, use VO+Cmd+G to jump between graphics and listen to what VoiceOver announces for each one.

iOS: VoiceOver

Enable VoiceOver: Settings, Accessibility, VoiceOver, Toggle ON. Open the rotor and set it to Images. Swipe up or down to navigate between images. VoiceOver announces the alt text. A missing alt announces the filename or "image." An empty alt on a meaningful image announces nothing: the image is skipped entirely.

Android: TalkBack

Enable TalkBack: Settings, Accessibility, TalkBack, Toggle ON. Single-finger swipe right to navigate elements. When focus lands on an image, TalkBack announces its accessible name. Open reading controls (swipe up then right) and select Images to navigate between images only. A missing alt announces the filename or nothing. A decorative image with alt="" is skipped.

Mobile testing for alt text must be done on a real device. Simulators do not reliably replicate how VoiceOver and TalkBack announce image content in web views and native app screens.

5. Writing Good Alt Text

Good alt text follows three rules: it is accurate, it is concise, and it is appropriate for context. Context matters more than any formula.

  • Be specific about what matters. "Photo of a woman" is less useful than "Sarah Chen, lead engineer, at the product launch." The information that is useful to a sighted user is the same information the alt text should convey.
  • Do not start with "image of" or "picture of." Screen readers already announce the role. Starting with "image of" means users hear "image of image of a woman."
  • For charts and graphs: include the key data point, not a description of the chart type. alt="Line graph showing revenue growth" tells the user nothing. alt="Revenue grew from £1.2M in Q1 to £2.4M in Q3" gives them the information.
  • For logos used as links: the alt text is the link destination. alt="Acme Inc: go to homepage" or simply alt="Acme Inc homepage".
  • For icons: if the icon has adjacent visible text (a search icon next to the word "Search"), the icon is decorative: use alt="". If the icon is the only element in a button or link, the alt text is the action.
  • For complex images: write a short alt (under 100 characters) and provide a longer description in a nearby paragraph, a <details> element, or an aria-describedby reference.

6. Writing Alt Text Defects

Alt text defect types with WCAG reference, severity, and reproduction steps
Defect WCAG Severity Reproduction
Image has no alt attribute 1.1.1 Critical Inspect element: no alt attribute present. NVDA announces filename. WAVE flags red.
Meaningful image has empty alt 1.1.1 Major Image conveys information not in surrounding text. alt="" causes screen reader to skip it. Confirm with NVDA: image not announced.
Alt text is the filename 1.1.1 Major Inspect element: alt value matches src filename. NVDA announces filename. WAVE flags yellow.
Alt text is generic 1.1.1 Major Alt value is "image", "photo", "graphic", "icon". Conveys no information. Check all images via WAVE Images tab.
Functional image describes appearance not action 1.1.1 / 2.4.4 Major Linked image alt text describes the image visually. NVDA announces description without link destination. User cannot determine where the link goes.
Decorative image not suppressed 1.1.1 Moderate Decorative image has non-empty alt. NVDA announces it in the content flow, adding noise. Should use alt="".
Complex image with insufficient alt 1.1.1 Moderate Chart or diagram alt text describes the visual type but not the data. NVDA announces "bar chart" with no data. A longer description is required.
The fast check

Open WAVE and click the Images tab. Every image on the page, with its alt text, in one list. Red flags are missing alt. Yellow flags are suspicious alt. Then run NVDA and press Insert+F7 to open the graphics list and listen to every announcement. Those two steps catch 90% of alt text defects without touching the DOM.
