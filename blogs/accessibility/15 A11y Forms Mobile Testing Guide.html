15 A11y Forms Mobile Testing Guide

How to test form accessibility on iOS VoiceOver and Android TalkBack. Use alongside the Forms Playground: same scenarios, tested on a real device.

⚠️ Physical device required. Simulators do not reliably replicate how VoiceOver and TalkBack announce form labels, errors, and required states.

Test on Real Native Apps

The playground covers web forms. Native app forms behave differently: no browser, no WAVE, no axe DevTools. These free apps let you test the same form accessibility failures on real iOS and Android native screens.

How to run the form tests in a native app

iOS: VoiceOver

1
Enable VoiceOver: Settings, Accessibility, VoiceOver, Toggle ON. Open the app in Safari is not needed: VoiceOver works across all native screens.
2
Open the rotor, set to Form Controls. Swipe down through each input. VoiceOver must announce the label before the field type. "Email address, text field" is correct. "Text field" alone is a failure.
3
Double-tap the submit button without completing required fields. Listen for an error announcement. If VoiceOver stays silent and focus stays where it was, errors are not announced.
4
Navigate back to each error field. VoiceOver must announce the error description alongside the label and field type. If it only says "invalid" with no description, the error is not linked.

Android: TalkBack

1
Enable TalkBack: Settings, Accessibility, TalkBack, Toggle ON. Open the app directly: TalkBack works across all native screens.
2
Open reading controls (swipe up then right), set to Controls. Swipe through each input. TalkBack must announce the content description before the field type. "Email address, edit box" is correct. "Edit box" alone is a failure.
3
Double-tap the submit button without completing required fields. Listen for an immediate error announcement. If TalkBack stays silent, the native form is not surfacing errors to the accessibility layer.
4
Swipe back to each error field. TalkBack must re-announce the error description. If only "invalid" is announced with no message, the content description for the error state is missing.
Native apps implement labels via contentDescription (Android) and accessibilityLabel (iOS): not HTML labels. The failures look identical to the web. The underlying code is different. Accessibility Scanner and DAC Colour Contrast (Android) or Accessibility Checker - AI EAA (iOS) can help identify missing labels on native screens.
