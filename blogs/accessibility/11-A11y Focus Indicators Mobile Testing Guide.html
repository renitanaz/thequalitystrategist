A11y Focus Indicators Mobile Testing Guide

How to test focus indicator failures on iOS VoiceOver and Android TalkBack. Use alongside the Focus Indicators Playground: same six scenarios, tested on a real device.

⚠️ Physical device required. Xcode Simulator and Android Emulator do not reliably reproduce VoiceOver and TalkBack focus rect behaviour.
iOS · VoiceOver

VoiceOver on iPhone and iPad

Before you start:
  • Enable VoiceOver: Settings, Accessibility, VoiceOver, Toggle ON
  • Or triple-click the side button if added to Accessibility Shortcut
  • Open the Focus Indicators Playground in Safari
  • VoiceOver draws a black rectangle around the focused element: this is separate from the CSS focus ring. You are checking for both.

No focus indicator anywhere
WCAG 2.4.7
Scenario 1 from the desktop playground
1
Open the playground in Safari with VoiceOver on.
2
Swipe right through the button, link, and input in Scenario 1.
3
Watch the screen. VoiceOver draws its black rect around each element. Now turn VoiceOver OFF (triple-click). Tab through using a Bluetooth keyboard if available.
Expected failure: With VoiceOver ON, the black VoiceOver rect is visible but there is no CSS focus ring. With VoiceOver OFF, no visual indicator at all. A sighted keyboard user cannot see where focus is.
Key distinction: VoiceOver's black rect is not the CSS focus ring. It is provided by the OS. It hides the missing CSS ring when VoiceOver is active. Always test with VoiceOver OFF too: that is the sighted keyboard user's experience.
2
Low contrast focus ring
WCAG 1.4.11
Scenario 3 from the desktop playground
1
Navigate to Scenario 3 on the playground page.
2
Turn VoiceOver OFF. Connect a Bluetooth keyboard. Press Tab to focus the button and card.
3
Look at the screen in normal lighting. Can you see the focus ring on the light background?
Expected failure: Ring colour #d0ccc0 on background #f0ede6 is 1.3:1 contrast. In normal lighting on a phone screen, the ring is invisible. With VoiceOver ON, the OS rect hides the problem.

Focus ring lost in error state
WCAG 2.4.7
Scenario 5 from the desktop playground
1
Navigate to Scenario 5. Turn VoiceOver ON.
2
Swipe right to the email input. VoiceOver announces the label and focuses it.
3
Double-tap the Submit button to trigger the error state.
4
Swipe right back to the email input. VoiceOver announces "invalid": but is the CSS ring still visible?
Expected failure: VoiceOver announces the error state via aria-invalid. But the CSS ring is gone: replaced only by the red border. Turn VoiceOver OFF with a Bluetooth keyboard to confirm: no ring on the focused error input.
4
Programmatic focus with no ring
WCAG 2.4.7
Scenario 6 from the desktop playground
1
Navigate to Scenario 6. Turn VoiceOver ON.
2
Swipe right to the Open modal button. Double-tap to activate it.
3
VoiceOver announces the modal heading. Look at the screen: is there a CSS ring on the heading?
4
Now swipe right to the Close button. Notice the ring appears on the button but not on the heading.
Expected failure: VoiceOver places its black rect on the modal heading (confirming focus moved). No CSS ring. Then focus moves to the Close button which has a ring: the contrast makes the heading's missing ring obvious.

Correct focus indicators
WCAG 2.4.7 · 2.4.11 · 1.4.11
Scenario 7 from the desktop playground
1
Navigate to Scenario 7. Turn VoiceOver ON then OFF alternately.
2
With VoiceOver ON: swipe right through all elements. The VoiceOver rect AND the blue CSS ring should both be visible.
3
With VoiceOver OFF: use Bluetooth keyboard. CSS ring should be visible on every element independently.
Expected pass: Blue 3px ring visible with VoiceOver ON alongside the OS rect, and independently with VoiceOver OFF. Ring adapts to border-radius of each element. Consistent across all element types.
Android · TalkBack

TalkBack on Android

Before you start:
  • Enable TalkBack: Settings, Accessibility, TalkBack, Toggle ON
  • Or hold both volume keys for 3 seconds
  • Open the Focus Indicators Playground in Chrome
  • TalkBack draws a green rectangle around the focused element. Same principle as VoiceOver: the green rect is OS-level and independent of the CSS focus ring.

Scenario 1 from the desktop playground
1
Open the playground in Chrome with TalkBack on.
2
Swipe right through the button, link, and input in Scenario 1.
3
Watch the green TalkBack rect. Then disable TalkBack and connect a Bluetooth keyboard. Tab through the same elements.
Expected failure: TalkBack ON shows the green rect but no CSS ring. TalkBack OFF with a keyboard shows no indicator at all. Same root cause as iOS: the OS rect masks the missing CSS ring.
