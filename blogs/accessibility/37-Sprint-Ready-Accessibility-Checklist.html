How to Use This Checklist Across Tiers

Tier 1: Pipeline automation

The Automated Checks section of this checklist (Section 2) maps to Tier 1. Run axe-core in CI on every commit. The pipeline gate handles: missing labels, contrast failures, invalid ARIA, empty buttons, duplicate IDs, and structural violations. Zero Critical or Serious violations is the pipeline exit criterion.

Tier 2: Semi-automated tools

Run before marking any story done. Covers the same checks as Tier 1 with visual context, plus Tab Stops for focus order:

  • axe DevTools in the browser: verify zero new violations vs the pipeline baseline
  • WAVE: visual overlay confirms what axe flags and surfaces structural issues in context
  • Accessibility Insights Tab Stops: walk the focus path through all new interactive elements

Tier 3: Manual: the rest of this checklist

Sections 3 through 9 of this checklist are Tier 3. They require a human with a keyboard and optionally a screen reader. Minimum manual coverage per story:

  • Keyboard (all platforms): Tab through every new interactive element. Check focus indicators, order, and traps.
  • NVDA + Firefox (Windows): Tab through new elements. Verify label, role, and state announcements.
  • VoiceOver + Safari (Mac): Same walkthrough. Use rotor for headings and form controls.
  • iOS VoiceOver: Swipe through new components on physical iPhone.
  • Android TalkBack: Swipe through on physical Android device.

1. How to Use This Checklist

This checklist covers the most common and highest-impact accessibility failures. Run it on every feature before marking a story done. It is not a full WCAG audit: it is the minimum bar for a sprint exit. A full audit happens at release. This happens every sprint.

Each item maps to a WCAG criterion. Each item can be checked in under two minutes. The full checklist takes 30 to 60 minutes for a typical feature depending on complexity.

This checklist assumes automated axe-core checks are already running in the pipeline. The items here are what automation cannot catch: the manual layer that must be done by a human before the story closes.

2. Automated Checks

Pipeline and browser tools
axe DevTools scan on all new and modified pages: zero critical and serious violations
WAVE scan confirms no red error icons on any new content
Colour contrast of all new text elements checked: 4.5:1 for normal text, 3:1 for large text and UI components
axe-core CI pipeline passes: no new violations introduced by this feature

3. Keyboard Testing

Tab through every new interactive element
All new interactive elements (buttons, links, inputs, custom controls) reachable by Tab
Focus indicator visible on every interactive element: never suppressed
Tab order follows visual reading order: no unexpected jumps
No keyboard traps: Tab can always escape any component
All actions achievable by keyboard that are available by mouse
Escape closes modals, dropdowns, and tooltips

4. Screen Reader Checks

NVDA + Firefox: Tab through all new interactive elements
Every button announces a meaningful label and "button" role
Every link announces a meaningful destination and "link" role
Every form field announces its label, type, and required state
Every image announces meaningful alt text: or is silent if decorative
Page heading structure is logical: no skipped levels, no visual-only headings
Landmark regions present: main, nav, footer, search where appropriate

5. Visual and Display Checks

Visual assessment
Page reflows at 320px viewport with no horizontal scrollbar
Content readable and functional at 200% browser zoom
Animations respect prefers-reduced-motion: enable Reduce Motion in OS and verify
Information is not conveyed by colour alone: pattern, text, or icon used alongside colour
Text is readable without overriding author styles (browser accessibility settings)

6. Forms

For every new or modified form
Every input has a visible label: placeholder alone is not a label
Required fields are indicated programmatically (aria-required) and visually
Submit with empty required fields: errors are announced immediately by screen reader
Error messages describe what went wrong and how to fix it: not just "invalid"
On error refocus, field announces its label + error description together
Radio button groups have a fieldset and legend describing the question

7. Dynamic Content

For any content that updates without a page reload
Toast notifications announced by screen reader without focus moving
Filter and search results announce update when content changes
Loading states announce completion: not just the start
Live region containers exist in DOM before content is injected
role="alert" used only for critical messages: not for routine updates

8. Components

For modals, accordions, tabs, dropdowns, carousels
Modal: focus moves inside on open, trapped while open, returns to trigger on close
Modal: announced as "dialog" with title when focus enters
Accordion: trigger is a button with aria-expanded, panel hidden with display:none or hidden attribute
Tabs: active tab announced as "selected", inactive tabs as "not selected"
Carousel: pause control present if auto-advancing, prev/next controls labelled
Custom dropdown: role, expanded/collapsed state, and selected value all announced

9. Media

For any new video or audio content
Prerecorded video has accurate captions: not unreviewed auto-generated
Prerecorded video has audio description for visual content not in the audio
Audio-only content has a text transcript
Media player controls keyboard accessible and labelled
Video does not autoplay with audio unless a pause mechanism is the first keyboard stop

10. Definition of Done for Accessibility

A story is not done until all of the following are true:

  • axe-core CI pipeline passes with zero new critical or serious violations
  • All manual checklist items above are verified and any failures are logged as defects
  • Critical and Major accessibility defects raised in this story are fixed before the story closes
  • Moderate and Minor defects are logged in the backlog with a target sprint
Accessibility is part of the definition of done: not a separate phase after development. A feature that ships with a critical accessibility defect has not passed QA.
The 10-minute fast track for small changes
  • Run axe DevTools. Fix any new violations.
  • Tab through every new interactive element. Check focus indicators.
  • Enable NVDA. Tab through. Listen to every button, link, and form field.
  • Trigger any dynamic content while focus is elsewhere. Listen for announcements.
