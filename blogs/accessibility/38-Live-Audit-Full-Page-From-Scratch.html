38 Live Audit: Full Page From Scratch: The Complete Accessibility Testing Methodology

This is the full methodology. One page. Every tier. Every tool. Every check. Start here when you need to audit a page you have never seen before.

How This Audit Maps to the Three Tiers

Tier 1: Pipeline automation

Section 2 of this blog is Tier 1. Review automated output before starting any manual work. Existing violations from the pipeline are pre-existing defects: record them separately from what you find manually. If no pipeline exists, run axe DevTools as your automated baseline first.

Tier 2: Semi-automated tools

Section 3 of this blog is Tier 2. Run WAVE and axe DevTools in sequence. Use Accessibility Insights Tab Stops for the keyboard focus path. Use ANDI for accessible name inspection on any element where the name is questionable.

Tier 3: Manual: keyboard, screen reader and visual

Sections 4 through 6 of this blog are Tier 3. Run them in this order:

  • Keyboard first: Disconnect the mouse. Tab through everything. Document every stuck point before opening a screen reader: keyboard failures are easier to locate without audio.
  • NVDA + Firefox (Windows): 8-step structural audit. Elements list for overview.
  • VoiceOver + Safari (Mac): Rotor for headings, links, and form controls. Tab Stops for focus path.
  • iOS VoiceOver (physical iPhone): Swipe navigation. Test every form, modal, and dynamic update.
  • Android TalkBack (physical device): Reading controls. Explore by touch. Test the same flows.
  • Visual checks: 320px reflow, 400% zoom, Reduce Motion, colour independence, media.

Apply this methodology to the Axe-Core CI Playground: it has deliberate failures across every tier plus passing implementations to verify. Work through all six phases and produce a real finding list.

1. Before You Start

Before opening a single tool, establish context:

  • What is the page purpose? A contact form has different failure patterns than a data dashboard. Know what you are auditing.
  • Who are the users? If the product targets enterprise, JAWS testing is important. If it is consumer, prioritise VoiceOver iOS and TalkBack.
  • What WCAG level is required? WCAG 2.1 AA is the standard for most organisations and legal frameworks. Confirm this before you start.
  • What is the scope? Full page audit or component audit? Full page audits include structure, navigation, and all interactive elements. Component audits focus on a specific widget or flow.
  • Document your test environment: Browser version, screen reader version, OS version, date. Reproducibility depends on this information.

2. Tier 1: Automated Pipeline Checks

If the page is already in a CI pipeline with axe-core, review the most recent pipeline output before starting. Any existing automated violations are pre-existing defects: distinguish them from anything you find manually.

If no pipeline exists, run axe DevTools in the browser as your automated baseline. Record all violations. This is your automated floor: everything you find manually is additional to this.

3. Tier 2: Browser Tool Scan

Step 1: WAVE

Activate WAVE. Check the summary: errors first, then alerts, then structure. Click through every red E icon. Record each one. Open the Structure tab and verify the heading hierarchy. Click every green feature icon for alt text and labels: verify they are meaningful, not just present.

Step 2: axe DevTools

Run axe DevTools. Review violations by impact: critical first, then serious. For each violation: record the rule ID, WCAG criterion, affected element, and fix guidance. Review the incomplete list: every incomplete item requires a manual check.

Step 3: Chrome DevTools accessibility tree

Open the Elements panel. Select key interactive elements: buttons, inputs, custom widgets. Check the accessibility tree for each: computed accessible name, role, and state. Verify they match what you expect.

Step 4: Colour contrast

If WAVE or axe DevTools have not flagged contrast failures, spot-check body text, UI component text (button labels, tab labels), and placeholder text. Use the Chrome DevTools colour picker to check contrast ratios on any element you are uncertain about.

4. Tier 3: Keyboard Testing

Disconnect the mouse. Navigate the entire page by keyboard only.

  1. Tab once: does a skip link appear?
  2. Tab through the navigation: all items reachable, focus indicator visible on each
  3. Tab through the main content: all interactive elements reachable in a logical order
  4. Activate each interactive element: Enter for links and buttons, Space for checkboxes and buttons
  5. Open every modal, dropdown, accordion, and tab set: verify focus management and Escape behaviour
  6. Submit every form empty: verify error handling is keyboard accessible
  7. Trigger every dynamic update: add to cart, filter, search, upload
  8. Log every point where you get stuck or lose focus as a defect

5. Tier 3: Screen Reader Testing

NVDA + Firefox (Windows)

Enable NVDA. Use the 8-step structural audit from Blog 20:

  1. Page title: load the page, listen to first announcement
  2. Landmarks: press D to cycle through all landmarks
  3. Headings: press H to walk the heading structure
  4. Interactive elements: Tab through, listen to label, role, and state for each
  5. Forms: Tab to each field, check labels; submit empty, check errors
  6. Images: press G to cycle through graphics, check alt text
  7. Links: press K to cycle through links, check link text quality
  8. Dynamic content: move focus away, trigger each dynamic update, listen

Open the Elements List (Insert+F7) at the start. Check Headings, Links, and Form Fields tabs for a structural overview in under two minutes.

VoiceOver + Safari (Mac)

Enable VoiceOver. Open the rotor (VO+U). Check: Headings for structure, Links for link text quality, Form Controls for label coverage. Navigate Tab Stops using Accessibility Insights if focus order is complex. Use the Safari Accessibility Inspector for element-level inspection.

VoiceOver + Safari (iOS) and TalkBack + Chrome (Android)

On physical devices: set rotor/reading controls to Headings and swipe through the page. Set to Form Controls and verify every field. Trigger dynamic updates while focus is away. Test all interactive components with the double-tap gesture.

6. Tier 3: Visual Checks

  • Reflow: Open DevTools, set viewport to 320px. Scroll the page. Any horizontal scrollbar is a 1.4.10 failure.
  • Zoom: Zoom to 400%. Walk through navigation, forms, and modals. Any broken layout or unreachable content is a failure.
  • Reduced motion: Enable Reduce Motion in OS (or emulate in DevTools Rendering). Navigate the page. Any animation that plays at full intensity is a candidate for a 2.3.3 failure.
  • Media: Play any video. Enable captions. Watch for synchronisation and accuracy. Enable audio description if available. Test media player controls by keyboard.
  • Colour independence: Identify any places where colour alone conveys information. Check that a secondary indicator (pattern, text, icon) is present alongside colour.

7. Documenting Findings

For each finding, record:

  • Finding number and title (component + failure + WCAG criterion)
  • Location (URL, page name, component)
  • Current behaviour and expected behaviour
  • WCAG criterion and level
  • Severity (Critical / Major / Moderate / Minor)
  • How it was found (automated / NVDA / keyboard / visual)
  • Steps to reproduce
  • Fix guidance

8. The Audit Summary

An audit summary for stakeholders must include:

  • Scope: What was tested, what was not, what environment, what date
  • Methodology: Which tools (axe DevTools, WAVE, NVDA, VoiceOver, keyboard), which WCAG level
  • Finding counts by severity: Critical: N, Major: N, Moderate: N, Minor: N
  • Finding counts by WCAG principle: Perceivable: N, Operable: N, Understandable: N, Robust: N
  • Conformance statement: "This page does not currently conform to WCAG 2.1 Level AA. N critical and N major issues require remediation before conformance can be claimed."
  • Prioritised finding list: Critical and Major findings listed in full. Moderate and Minor summarised.

The full audit in order
  • Review automated output. Record all existing violations.
  • Run WAVE. Record errors, verify alerts, check structure, verify features.
  • Run axe DevTools. Record violations by impact. Review incomplete list.
  • Disconnect mouse. Tab through everything. Log every stuck point.
  • Enable NVDA. Run the 8-step structural audit. Listen to every element.
  • Test on mobile: VoiceOver iOS, TalkBack Android.
  • Check 320px reflow, 400% zoom, reduced motion, colour contrast, media.
  • Write every finding with full reproduction steps and fix guidance.
  • Produce a summary with severity counts and a conformance statement.
