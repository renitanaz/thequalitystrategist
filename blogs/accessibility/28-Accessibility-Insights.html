28 Accessibility Insights: FastPass, Assessment and Tab Stops in One Tool

Accessibility Insights combines automated scanning with structured guided manual testing. It is the only free tool that walks you through WCAG manual checks step by step.

1. What Accessibility Insights Is

Accessibility Insights for Web is a free browser extension developed by Microsoft. It combines automated scanning (powered by axe-core) with structured guided manual testing flows: the only free tool that actively walks you through manual WCAG checks with instructions, pass/fail recording, and a downloadable report.

It has three core testing modes: FastPass for automated checks, Tab Stops for keyboard navigation visualisation, and Assessment for a full guided WCAG 2.1 AA evaluation. Each serves a different point in the testing process.

Accessibility Insights is a Tier 2 semi-automated tool. FastPass uses the same axe-core engine as axe DevTools. The unique value is Assessment: a structured walkthrough of every WCAG 2.1 AA criterion that cannot be automated, with instructions for each manual check.

2. FastPass: Automated Checks in 30 Seconds

FastPass runs two checks simultaneously: an automated scan (axe-core) and a colour contrast analyser. It completes in seconds and shows all failures grouped by impact. FastPass is the fastest entry point for any accessibility review: run it on every page before starting manual testing.

  • Automated checks: same axe-core rules as axe DevTools: missing labels, invalid ARIA, contrast failures, empty buttons
  • Colour contrast: highlights every element failing 4.5:1 for normal text and 3:1 for large text
  • Result view: failures listed with element highlight, WCAG criterion, and fix guidance
  • Export: FastPass results exportable as HTML report for defect logging

3. Tab Stops: Keyboard Testing Visualised

Tab Stops mode draws numbered arrows on the page showing the exact Tab key focus order as you navigate. This is the most effective visualisation tool for keyboard focus order testing: you can see the focus path without having to remember where focus was two Tab presses ago.

  • Enable Tab Stops mode, then press Tab through the page
  • Arrows appear on screen connecting each focusable element in order
  • Red arrows indicate a missing or unexpected focus jump
  • Identifies elements that receive focus but are not visible (missing focus indicator), elements that skip unexpectedly, and focus traps
Tab Stops does not test whether the focus order is logical: it shows you what the order is. A focus path that jumps from the footer back to the header is visible immediately. Without Tab Stops you would have to count Tab presses mentally to detect the same issue.

4. Assessment: Guided Manual WCAG Testing

Assessment is a structured walkthrough of all WCAG 2.1 AA criteria that require human judgement. For each criterion, it provides: what to test, how to test it, examples of pass and fail, and a pass/fail/not applicable recording field.

Assessment generates a downloadable HTML report with all results: useful for audit documentation, accessibility statements, and handover to development teams.

Key areas covered by Assessment that no automated tool can check:

  • Audio and video: captions present and accurate, audio descriptions, transcripts
  • Pointer gestures: all multi-point gestures have a single-pointer alternative
  • Consistent navigation: navigation order consistent across pages
  • Error prevention: legal and financial submissions are reversible or confirmable
  • Cognitive and timing: timeouts, moving content, pause mechanisms
  • Reading order: the visual order matches the DOM order

How to Test With Accessibility Insights

Tier 1: Pipeline automation

Accessibility Insights does not integrate into CI/CD pipelines directly. For pipeline automation, use axe-core in Playwright or Cypress: it uses the same rule engine as Accessibility Insights FastPass. See Blog 31 for CI setup.

Tier 2: Semi-automated: Accessibility Insights in the browser

  • Install the Accessibility Insights Chrome extension
  • FastPass: Click FastPass. Automated checks and colour contrast run simultaneously. Fix all violations before proceeding.
  • Tab Stops: Enable Tab Stops mode. Press Tab through the entire page. Red arrows show focus jumps. Loops show focus traps.
  • Assessment: Run for a full guided WCAG 2.1 AA walkthrough with documented pass/fail per criterion. Export HTML report.
  • Platforms: Chrome on Windows and Mac. Edge also supported. Not available for mobile browsers.

Tier 3: Manual: what Accessibility Insights cannot catch

  • Screen reader announcements: NVDA + Firefox on Windows, VoiceOver + Safari on Mac. FastPass confirms ARIA attributes: not whether they produce the right announcement.
  • Alt text quality: Assessment flags missing alt: read every alt text to verify meaningfulness.
  • iOS VoiceOver: Physical iPhone + Safari. Accessibility Insights does not run on iOS.
  • Android TalkBack: Physical Android device + Chrome. Same limitation.
  • Focus indicator visibility: Tab Stops shows the path: visually verify the indicator is visible enough on each element.

7. WCAG 2.1 AA Coverage

Accessibility Insights has the widest WCAG 2.1 AA coverage of any single browser tool because Assessment covers manual-only criteria that no automated tool can reach. FastPass alone matches axe DevTools. Assessment combined with FastPass covers nearly all WCAG 2.1 AA criteria.

Use Accessibility Insights Assessment when you need to produce a formal WCAG 2.1 AA conformance report. It is the most structured free workflow available for a complete manual audit with documented evidence.
When to use which mode
  • Every page: run FastPass first. Fix all violations before proceeding.
  • Every interactive page: run Tab Stops. Walk through the full keyboard path. Check every focus state.
  • Full audit: run Assessment. Complete every criterion, record pass/fail, export the report.

Mobile Testing: What These Tools Cannot Do

Browser-based tools like axe DevTools, WAVE, and Lighthouse run on desktop browsers. They cannot test native mobile apps, and they cannot replicate the experience of a screen reader user on a phone. The issues these tools catch still need to be verified on mobile. Use these apps to test the same failure patterns in a native mobile context.
