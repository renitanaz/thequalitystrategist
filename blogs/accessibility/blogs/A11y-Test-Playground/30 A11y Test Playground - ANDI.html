ANDI Playground

Practice inspecting accessible names, roles, and descriptions with ANDI. Click each element after activating ANDI and compare what ANDI reports against what you expect.

🎯 Setup: Drag the ANDI bookmarklet to your bookmarks bar. Click it on this page. Select the Focusable Elements, Images, or Tables module depending on the scenario.
1
Placeholder used as the only accessible name
ANDI module: Focusable Elements · WCAG 3.3.2
What to do: Activate ANDI, select Focusable Elements. Click the input below. Note what ANDI shows as the Accessible Name source.
Scenario 1: input with placeholder only: no label
ANDI reports on this element: Accessible Name: Enter your full name (from placeholder)
Alert: Placeholder is the only accessible name: it disappears when user types
Fail WCAG 3.3.2 Add a visible label element
2
aria-label overrides the visible label text
ANDI module: Focusable Elements · WCAG 2.5.3
What to do: Activate ANDI, Focusable Elements. Click the button below. Note that ANDI shows the aria-label, not the visible text. These are different: a screen reader user hears something different from what a sighted user sees.
Scenario 2: visible label says "Submit" but aria-label says something different
ANDI reports on this button: Accessible Name: Send contact form to support team (from aria-label)
Visible text: Submit
Alert: Accessible name does not match visible label: fails WCAG 2.5.3 Label in Name
Warning WCAG 2.5.3 aria-label must contain visible text
