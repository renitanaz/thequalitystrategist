Colour Contrast Playground

Seven scenarios: six contrast failures and one passing example. Test with WAVE Contrast tab, axe DevTools, and Chrome DevTools colour picker. Each scenario is a self-contained demo with exact hex values and ratios.

🎯 Open WAVE on this page and click the Contrast tab to see all failures mapped at once.
1
Body text too light on white background
The most common production failure: grey text that "looks fine" to a designer on a calibrated monitor.
What to do: Run WAVE or axe DevTools on this page. Or use Chrome DevTools colour picker on the paragraph below. WCAG 1.4.3WAVEaxe DevTools

What to look for: Text colour #aaaaaa on white #ffffff measures 2.3:1. Minimum required is 4.5:1.
Scenario 1: grey text on white

This paragraph uses light grey text on a white background. It may look acceptable at full brightness on a good screen. It fails WCAG 1.4.3 for users with low vision, on budget screens, or in bright sunlight.

2
Brand yellow text on white background
Yellow text on white is almost always a failure regardless of the shade.
What to do: Use Chrome DevTools colour picker: inspect the heading, click the colour swatch, check the contrast ratio shown in the picker. WCAG 1.4.3Chrome DevTools

What to look for: #f5c400 on #ffffff = 1.9:1. Well below the 4.5:1 minimum.
Scenario 2: yellow text on white

This heading uses brand yellow

Body copy in the same brand yellow. Both fail even though yellow is a prominent, saturated colour.

Fail WCAG 1.4.3 #f5c400 on #fff = 1.9:1 (need 4.5:1)
3
Placeholder text contrast failure
Automation often misses this. Requires manual colour picker check.
What to do: Inspect the input below in Chrome DevTools. Find the ::placeholder pseudo-element and check its colour against the input background. WCAG 1.4.3Chrome DevTools

What to look for: Placeholder colour #bbbbbb on #ffffff = 1.6:1. Many automated tools skip placeholder text entirely.
Scenario 3: low-contrast placeholder text

The placeholder text above is #bbbbbb on #ffffff: 1.6:1 contrast.

Fail WCAG 1.4.3 #bbb placeholder on #fff = 1.6:1 Often missed by automation
4
UI component boundary: input border too light
The border defines the component. If it disappears, the input disappears.
What to do: Use Chrome DevTools colour picker on the input border. Or run axe DevTools: it checks border-color against the adjacent background under WCAG 1.4.11. WCAG 1.4.11axe DevToolsChrome DevTools

What to look for: Border #e0e0e0 on background #ffffff = 1.2:1. UI boundaries need 3:1 minimum.
Scenario 4: low-contrast input border

Border #e0e0e0 on #ffffff: 1.2:1. Near-invisible on white. Users cannot see where the input starts and ends.

Fail WCAG 1.4.11 #e0e0e0 border on #fff = 1.2:1 (need 3:1)
5
Text over a gradient background: automation gets it wrong
axe-core reads the CSS background-color, not the actual visual. This is always a manual check.
What to do: Run axe DevTools. Notice it may not flag this. Then use the Chrome DevTools colour picker to sample the actual background colour under the text manually. WCAG 1.4.3Chrome DevTools (manual)

What to look for: White text on a light part of the gradient fails. axe-core reads the base background-color value, not the gradient at that pixel.
Scenario 5: text over gradient: automation blind spot

Hero section heading

This text starts on dark blue (high contrast) and ends near off-white (very low contrast). axe-core reads the CSS background: linear-gradient(...) and may report no issue: or use the start colour only.

Fail (right side) WCAG 1.4.3 #fff on #f0ede6 = 1.1:1 at gradient end Automation blind spot: check manually
6
Colour used as the only signal: WCAG 1.4.1
This is a contrast and colour blindness failure. Red and green mean nothing without text or icon support.
What to do: Open Chrome DevTools, Rendering panel, Emulate vision deficiencies: Deuteranopia. Look at the status indicators below. WCAG 1.4.1Chrome DevTools Rendering

What to look for: Under Deuteranopia simulation, red and green dots become indistinguishable. The meaning of Available and Unavailable is lost entirely.

7
Correct contrast: the passing example
All thresholds met. Colour plus text label. Passes Deuteranopia simulation.
What to do: Run WAVE and axe DevTools on this scenario. Enable Deuteranopia simulation. WCAG 1.4.3 · 1.4.11 · 1.4.1WAVEaxe DevTools

What to look for: No contrast violations. Status icons use colour plus shape plus text label: meaning survives colour blindness simulation.
