A11y Test Playground

NVDA Playground

Eight scenarios with paired failure and pass examples. Enable NVDA + Firefox before you start. Each scenario shows what NVDA announces for the failure and what it should announce for the correct implementation.

🎯 Core rule: disconnect your mouse. Navigate with keyboard only. If you cannot complete each task by listening alone: that is a defect.
1
Heading structure: visual heading, not semantic
Looks like a heading. NVDA does not know it is one.
What to do: Press H to navigate headings. Try to land on "Our Services." WCAG 1.3.1

What to look for: NVDA skips "Our Services" entirely: it is a div with font-size styling, not an h2.
Scenario 1: visual heading with no semantic markup

About us

We are a quality engineering consultancy.

Our Services

We offer testing strategy, automation, and accessibility auditing.

NVDA with H: "About us, heading level 2": then jumps past "Our Services" to the next semantic heading. "Our Services" is not announced as a heading.
Fail WCAG 1.3.1 div styled as heading: not an h2/h3 element
2
Link text: "read more" with no context
Destination unknowable from link text alone.
What to do: Press K to navigate links. Listen to what NVDA announces for the "Read more" link. WCAG 2.4.4

What to look for: NVDA announces "Read more, link": the user cannot determine where the link goes without reading surrounding context.
Scenario 2: non-descriptive link text

We published a full accessibility audit report covering WCAG 2.1 AA compliance across 47 components.

Read more
NVDA announces: "Read more, link": destination completely unknown when navigating by links list (Insert+F7)
Should announce: "Read our WCAG 2.1 AA audit report, link": or use aria-label to add context
Fail WCAG 2.4.4 Link purpose not clear from link text alone
3
Image: missing alt vs correct alt
Two identical-looking images. One NVDA can describe. One it cannot.
What to do: Press G to navigate graphics. Listen to what NVDA announces for each image. WCAG 1.1.1

What to look for: First image announces filename. Second image announces the data.
Scenario 3: image alt text comparison

Image 1: no alt text

NVDA announces: filename or "graphic": no information about the chart data

Image 2: correct alt text

NVDA announces: "Bar chart: defect count reduced from 48 in Q1 to 12 in Q4, a 75% reduction, graphic" ✓
Image 1: Fail Image 2: Pass WCAG 1.1.1
4
Form: unlabelled input vs correctly labelled input
Tab to each field. Listen.
What to do: Tab to each input field below. Listen to NVDA's announcement. WCAG 1.3.1 / 3.3.2

What to look for: First field: "edit text, blank." Second field: "Email address, required, edit text."
Scenario 4: labelled vs unlabelled inputs

Input 1: no label

NVDA announces: "edit text, blank": no label, no purpose

Input 2: correct label + required

NVDA announces: "Email address, required, edit text" ✓
Input 1: Fail Input 2: Pass WCAG 1.3.1 / 3.3.2
5
Table: no column headers vs correct headers
Navigate cell by cell. Does NVDA tell you what column you are in?
What to do: Press T to find each table. Then use Ctrl+Alt+arrow keys to navigate cell by cell. WCAG 1.3.1

What to look for: Table 1: cell data announced with no column header. Table 2: column header announced before each cell value.
Scenario 5: tables without and with headers

Table 1: no th elements

Jane Smith Lead Engineer £85,000
Tom Lee QA Architect £90,000
NVDA on cell navigation: "Jane Smith": no column header. User does not know if this is Name, Role, or Salary.

Table 2: correct th with scope

Name Role Salary
Jane Smith Lead Engineer £85,000
NVDA on cell navigation: "Name column, Jane Smith": column header announced before cell value ✓
Table 1: Fail Table 2: Pass WCAG 1.3.1
6
Form error: announced vs silent
Submit empty. Listen for the error.
What to do: Tab to each Submit button below. Press Enter or Space to activate. Listen to NVDA. Then Tab back to the input. WCAG 3.3.1

What to look for: Form 1: silence after submit. Form 2: error announced immediately via role="alert," then described again on field refocus.
Scenario 6: error handling comparison

Form 1: colour-only error, no ARIA



NVDA after submit: silence: only the border colour changed, which NVDA cannot see

Form 2: correct ARIA error

Username is required. Enter at least 3 characters.

NVDA after submit: "Username is required. Enter at least 3 characters." (role="alert" fires immediately) ✓
On refocus: "invalid, Username, Username is required. Enter at least 3 characters., edit text" ✓
Form 1: Fail Form 2: Pass WCAG 3.3.1
7
Live region: toast announced vs silent
Focus on a heading. Click the button. Listen.
What to do: Press H to focus on the heading above each demo. Then Tab to the button and press Enter. WCAG 4.1.3

What to look for: Button 1: no announcement after click. Button 2: NVDA announces the toast message without focus moving.
Scenario 7: live region comparison

Button 1: no live region

✓ Draft saved
NVDA announces: silence: toast has no live region

Button 2: correct role="status"

✓ Draft saved
NVDA announces: "Draft saved successfully": politely, without moving focus ✓
Button 1: Fail Button 2: Pass WCAG 4.1.3
8
Elements list: structural audit in 30 seconds
Insert+F7: your fastest structural overview tool.
What to do: Press Insert+F7. Switch between Headings, Links, and Form Fields tabs. Review what is listed. Technique

What to look for: Headings tab shows the page structure. Links tab shows all link text: any "read more" or "click here" are immediately visible. Form Fields tab shows all inputs and their labels.
Scenario 8: use the elements list on this page

Press Insert+F7 now. The elements list opens as a dialog. Use it to audit this playground page:

  • Headings tab: is the heading hierarchy logical?
  • Links tab: are all link texts descriptive?
  • Form Fields tab: do all inputs show their labels?
  • Buttons tab: are all button labels meaningful?
Target: every heading announced with a level, every link with a clear destination, every field with a label. This is the 30-second structural audit.
