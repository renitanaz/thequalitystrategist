A11y Test Playground

Forms Playground

Nine scenarios: seven failures, one warning, and one passing example. Test with NVDA, axe DevTools, and WAVE. Each scenario shows what NVDA announces so you know exactly what to listen for.

🎯 Tab through each form with NVDA running. For error scenarios, submit the form and listen for what gets announced: and what doesn't.
1
Input with no label
The most fundamental form failure.
What to do: Tab to the input below with NVDA running. WCAG 1.3.1axe DevToolsWAVE

What to look for: NVDA announces "edit text, blank": no label, no purpose, nothing.
Scenario 1: unlabelled input
NVDA announces: "edit text, blank": placeholder is not read as a label
Fail WCAG 1.3.1 No <label>, no aria-label, no aria-labelledby
2
Placeholder used as only label
Disappears the moment the user starts typing.
What to do: Tab to the input. Type a character. Watch what happens to the placeholder. WCAG 1.3.1 / 3.3.2

What to look for: Placeholder vanishes. NVDA never announces it as a label. The user cannot check what they are filling in while typing.
Scenario 2: placeholder-only labelling
NVDA announces: "edit text, blank": then when you type, the placeholder disappears and context is gone
Fail WCAG 1.3.1 / 3.3.2 Placeholder is not a substitute for a label
3
Error indicated by colour only
Red border. No text. No announcement.
What to do: Click Submit below. Tab back to the input with NVDA. WCAG 1.4.1 / 3.3.1NVDA

What to look for: Red border appears but NVDA announces nothing about an error. No aria-invalid, no error text, no announcement.
Scenario 3: colour-only error
NVDA announces after submit: nothing new: only the red border changes, which NVDA cannot see
Fail WCAG 1.4.1 / 3.3.1 No aria-invalid, no error text, no role="alert"
4
Error message exists but not linked to input
Error is visible. NVDA cannot connect it to the field.
What to do: Click Submit. Tab back to the email field. Listen to NVDA. WCAG 3.3.1NVDAaxe DevTools

What to look for: Error text appears visually but NVDA only announces "invalid, edit text": the error description is not connected via aria-describedby.
Scenario 4: error not linked with aria-describedby
Enter a valid email address.
NVDA announces on refocus: "invalid, Email address, edit text": error state announced but the error description is NOT read because aria-describedby is missing
Fail WCAG 3.3.1 aria-invalid set but no aria-describedby linking to error
5
Error message too vague
Linked correctly. Useless content.
What to do: Click Submit. Listen to NVDA announce the error. WCAG 3.3.3NVDA

What to look for: Error is announced correctly by NVDA but the message "Invalid" gives the user no information about what to fix.
Scenario 5: vague error message
Invalid
NVDA announces: "Invalid": the user knows there is an error but has no idea what to do
Fail WCAG 3.3.3 Error linked correctly but message too vague
6
Required field marked by asterisk only: no programmatic meaning
Visual asterisk. Nothing in the code says "required."
What to do: Tab to the field below. Listen to NVDA. WCAG 1.4.1 / 3.3.2NVDA

What to look for: NVDA announces "Full name, edit text": no mention of required. The asterisk is visual only, no required or aria-required attribute.
Scenario 6: visual asterisk with no code meaning
* denotes required field
NVDA announces: "Full name, edit text": required state not announced. User does not know this field is mandatory.
Fail WCAG 1.4.1 / 3.3.2 No required or aria-required attribute
7
Radio button group with no fieldset or legend
Each option is announced. The question is not.
What to do: Tab to the radio buttons with NVDA. WCAG 1.3.1axe DevToolsNVDA

What to look for: NVDA announces each option label but never the group question. The user hears "Yes, radio button" with no context about what Yes means.
Scenario 7: radio group without fieldset/legend

Do you want to receive marketing emails?

NVDA announces: "Yes, radio button, 1 of 2": the group question is never announced because there is no fieldset/legend
Fail WCAG 1.3.1 Wrap in <fieldset> + <legend>
8
Personal data fields missing autocomplete attributes
Not caught by NVDA. Caught by axe DevTools.
What to do: Run axe DevTools on this page. Filter by autocomplete-valid. WCAG 1.3.5axe DevTools

What to look for: Fields collecting name, email, and phone have no autocomplete attribute. axe flags this. Password managers and autofill cannot assist users.
Scenario 8: missing autocomplete attributes
axe flags: "autocomplete-valid" violation on each personal data field: autocomplete attribute absent
Moderate WCAG 1.3.5 Add autocomplete="name", "email", "tel"
9
Correct form: the passing example
Labels, errors, required, fieldset, autocomplete: all correct.
What to do: Tab through the form with NVDA. Submit empty to trigger errors. Tab back to each field. WCAG 1.3.1 / 1.3.5 / 3.3.1 / 3.3.2 / 3.3.3NVDAaxe DevTools

What to look for: Each field announces label, type, and required state. On submit, errors are announced immediately. On refocus, error descriptions are re-announced.
Scenario 9: fully accessible form
Please fix the errors below before continuing.
Enter your full name.
Enter a valid email address, e.g. name@example.com
Do you want to receive marketing emails?

Fields marked * are required

NVDA on tab to name field: "Full name, required, edit text"
NVDA on submit with empty fields: "Please fix the errors below before continuing" (role="alert" fires immediately)
NVDA on refocus of name field: "invalid, Full name, required, Enter your full name, edit text"
Pass WCAG 1.3.1 / 1.3.5 / 3.3.1 / 3.3.2 / 3.3.3
