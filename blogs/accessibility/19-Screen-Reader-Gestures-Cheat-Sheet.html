Key VoiceOver iOS rotor settings for testing

The rotor is the core navigation tool. Set it to the appropriate category and swipe up/down to move between items of that type:

  • Headings: navigate page structure
  • Links: test link text and purpose
  • Form Controls: test labels, required states, error associations
  • Images: test alt text announcements
  • Landmarks: test page regions
  • Characters / Words / Lines: fine-grained text reading

5. Browse Mode vs Forms Mode

NVDA and VoiceOver use two distinct modes when navigating web content. Understanding the difference prevents the most common screen reader testing confusion.

Browse mode (also called reading mode or virtual cursor mode)

Default mode when navigating a web page. Arrow keys move through content character by character, word by word, or line by line. Single letter shortcuts (H for headings, K for links) work here. Tab still moves between interactive elements. This is the mode for reading content and navigating page structure.

Forms mode (also called focus mode or application mode)

Active when focus enters a form field, a widget, or a region with role="application". Keyboard input goes directly to the field: single letter shortcuts stop working. Arrow keys navigate within the component. NVDA announces "forms mode" when switching. This is the mode for filling in inputs, operating custom widgets, and interacting with components.

NVDA switches modes automatically in most cases. If you Tab into a field and your H/K shortcuts stop working: you are in forms mode. Press Insert+Space to toggle back to browse mode. If a custom widget traps you in forms mode with no escape, that is an accessibility defect.
