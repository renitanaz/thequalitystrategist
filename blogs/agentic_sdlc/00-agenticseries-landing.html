Agentic SDLC, Part 1: Agents a QA Team Can Trust

Build agents that draft tests, choose regression runs and write bug reports against a real app, with a limit on what each one can do and a person at every gate.

1. What this series is

An agent is a program where an AI model chooses its own next step, using tools you give it. A QA team can use one to draft test ideas, pick which regression tests to run, or write a first bug report. This series builds each of those against a real app, PeakAndPack, and spends as much time on the limits as on the agents: what each agent may touch, what it may spend, and where a person has to say yes.

The idea running through every phase is a split between two steps that are easy to blur. The agent produced an answer is one step. The answer is safe to act on is another. The code in each phase keeps them apart, with a tool list, a folder rule, a fallback or an approval gate between them.

2. Who it is for

Testers and QA engineers who write Playwright tests (or have worked through Playwright: Zero to Architect) and want to know what an agent can safely do in their delivery cycle, and what it cannot. You do not need any prior experience with Claude, Claude Code or agents. Phase 0 starts from the beginning.

The Playwright series is the recommended background. Phase 5 (test data), Phase 7 (calling APIs) and Phase 12 (pipelines) are the three this series leans on most.

3. Why it comes in two parts

Part 1 needs only PeakAndPack, so you can build all of it now. Part 2 covers the phases that need other demo apps or earlier series to exist first (requirements analysis, bug detection on other apps, reporting and release readiness, local models, and the capstone). The phase numbers keep their original numbering across both parts, so Part 1 skips some numbers on purpose.

4. Three rules every phase follows

  1. An agent drafts, a person decides, anything with a side effect waits for a yes. Filing, committing, publishing and releasing are never silent.
  2. When unsure, do more, not less. A selection the agent cannot place runs the full suite. A file it cannot judge is treated as unknown, not as safe.
  3. Every run has a ceiling. A cap on turns and on spend, set in the code, on every agent call.

The series also names which kind of "self-fixing" it means each time it comes up. Locator-level self-healing is an algorithm that runs unattended, with no AI model and no person. Code-level auto-fix is an agent proposing a change, and a person approves it, always, because a failing test can mean a real bug, an intended change nobody updated the test for, or a bad test. The argument is in Playwright Phase 13.

6. What you need

  • Claude Code, signed in. Phase 0 checks this. A Claude account that includes Claude Code is required.
  • Node.js 20 or later and the peakandpack-tests project from the Playwright series.
  • A GitHub account, one practice repository for bug reports, and, for Phase 9, a second repository (the app) to play the development team.
  • An Anthropic API key for Phase 9, because a pipeline cannot sign in as you.
  • PeakAndPack running locally. The agents click through it, so use your own copy and not the shared live demo.
  • A Jira site (optional, for Phase 2). Every example also works with GitHub.

Cost. Agent runs use paid model calls. Every script in this series sets a spending cap and a turn limit, and the early phases cap a run at well under a dollar. Check your own usage as you go, because costs depend on your plan and on how the agent behaves on your data.

7. How each phase is written

Every code block is followed by a collapsed "Explain this code, line by line" section, which says what each line does and why it is there. Every phase ends with deliverables, an assignment with a collapsed solution, and a bonus challenge. Try the assignment before opening the solution.
