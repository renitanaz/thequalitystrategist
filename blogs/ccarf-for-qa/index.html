CCAR-F for QA: what the blueprint actually asks of you

The Architect Foundations blueprint, read by someone whose job is not just to ship it, but to catch the risk.

The Quality Strategist · Capsule hub · 6 min read

If you're prepping for CCAR-F and wondering what it has to do with QA, that's exactly what this series answers. It works through the CCAR-F syllabus one domain at a time, and turns each one into something you actually build, not just read about, so the concepts hold up under practical use.

What this capsule actually is

Five posts, five working deliverables, all built against PeakAndPack, a live demo app seeded with real, verifiable bugs. Every post: one concept, one worked example, a boxed line tying it to the exact blueprint domain and weight, and a closing section naming what it doesn't solve. Under 8 minutes to read. Density from a quality seat is the actual differentiator.

Before you start: what you'll need

Two separate things live in this capsule, and they're not connected: Claude Code, which you install and run locally on your own computer, and PeakAndPack, a live demo website you just look at in a browser. Claude Code is what actually runs every post's example files.

The project this capsule keeps referring back to is PeakAndPack, a live demo storefront: peakandpack-ui.onrender.com. Go through it. The first load can take 5 to 10 seconds while the server wakes up, that's normal, not broken. Once it loads, scroll the product list: a few real, known issues are seeded into it, a sleeping bag priced at -$89, an item with no name, a water bottle at $9,999.99. Every "BUG-XXX" this capsule mentions traces back to something visibly wrong on that page, like these. The API behind it, used by every deliverable's live-check calls, is at peakandpackshopdemo.onrender.com, you won't need to visit that one directly, the scripts and commands call it for you.

To actually build along, though, you won't need PeakAndPack's own code at all, there's no repo for it. Every deliverable in this capsule works exactly the same inside a throwaway folder, just an empty folder you make yourself, anywhere on your computer (mkdir ccarf-practice, for example), with no connection to PeakAndPack or any other codebase.

Before you start, that's the whole list of what you need: Claude Code installed (covered below), and an Anthropic account to log into it with.

If Claude Code isn't installed yet, here's the fastest path on a brand-new machine. Open a terminal, Terminal on Mac, Command Prompt or PowerShell on Windows, or if you already have VS Code, its built-in terminal works just as well (menu bar, Terminal → New Terminal, or Ctrl+`). Then check whether Node.js is already there:

node -v

If that errors out, install Node.js from nodejs.org first, the default installer is enough, no settings to configure. Once that's done, from the same terminal, run:

npm install -g @anthropic-ai/claude-code

Then make a folder to work in, for example mkdir ccarf-practice, move into it, and run claude. Log in when it prompts you. That's the whole install. If you hit anything unusual, platform-specific installers and troubleshooting live in the official docs.

Past that, each post has its own short setup section covering exactly where that post's specific files go, since the shape of the deliverables changes post to post.

What this hub does not solve

  • It does not get you registered if your organisation isn't on the Claude Partner Network.
  • It does not substitute for sitting the exam, or for hands-on time with Claude Code beyond what each post's worked example covers.
  • It does not carry the authority of a passed exam, only of a QA architect's read of a public blueprint, checked against official sources and an app you can go run yourself.
