Cleared the CCAR-F Exam

Sept 2026 · CCAR-F Revision Series

A short write-up on how I studied, what actually mattered on exam day, and where to find good material - written right after sitting the Claude Certified Architect, Foundations exam.

It's an architect exam, not a developer exam

The single most useful thing to internalize before you start studying: this exam tests architectural judgment, not implementation recall.

  • You won't be asked to write out a hook script character-for-character or recite a config file from memory.
  • You're asked to reason about why one approach is more reliable than another.
  • And how a mechanism actually behaves under a specific failure mode.
  • Just as often, why not a tempting-sounding alternative actually holds up.

Every scenario question in the sample set follows the same pattern:

  • A system is already misbehaving in some specific, plausible way.
  • You have to pick the fix that addresses the actual root cause, not one that just sounds reasonable on the surface.
  • Knowing the exact syntax of a flag or a config key rarely decides the answer.
  • Knowing why that mechanism exists, and what it does and doesn't guarantee, almost always does.
If you take one thing from this post: stop optimizing for memorizing exact syntax. Optimize for being able to explain, out loud, why a given design choice is more reliable than the obvious-sounding alternative.

How I'd study, if I had to start again

Not a list of things I tried - this is the actual order I'd run through it in, to make the best use of the time, subtopic by subtopic:

  1. Introduce self to the topic: Go through claudecertificationguide.com, subtopic by subtopic. Don't skip ahead.
  2. Claude as study buddy: For that subtopic, use Claude itself as a study partner - ask it as many "what if" and "why" questions about it as you can think of before moving on.
  3. Official guide connect: Then read the official exam guide (PDF)'s section for that same subtopic. You already understand it by this point, so this pass is about aligning with the official framing, not learning it cold.
  4. Capture the keywords: Note down the keywords as you go. You will forget them within a few days once you've moved on to the next few subtopics - write them down now, not later.
  5. Connect and justify: As you move into each new topic, connect it back to the ones before it, and ask why it's actually needed in a real, running production system - not just what the guide says about it.
  6. Loop it: Run that loop - guide site, Claude Q&A, exam guide, keywords, connect-and-justify - for every subtopic, in every domain.

Once that first full pass is done, run through this Udemy course as a quick brush-up and correction pass - fast, and it catches anything you misunderstood the first time round.

Start mocks in parallel with that brush-up, not after it - easiest first, building up to the ones that force you to intertwine concepts across subtopics. My order:

  1. The claudecertificationguide.com mock test.
  2. The OlivierAlter Claude Certified Architect Foundations repo (GitHub).
  3. The Udemy course's own mock questions - I only worked through 4 of theirs.
  4. Every other random question set you can find online, just to keep the mind intertwining concepts across sources.

Worth naming honestly: prior hands-on exposure to agentic development helped - it made it easier to relate to the exam's scenarios rather than reasoning about them purely in the abstract. If you don't have that background yet, budget extra time to actually build something small and agentic before you sit the exam, not just read about it.
