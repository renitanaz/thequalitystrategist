Context Management & Reliability

Task Statements 5.1–5.6

Source: Claude Certified Architect – Foundations Certification Exam Guide, Domain 5 section, official sample Questions 3 and 8.

Topics Mind Map

1Topic Keywords

5.1 · Context Management

Persistent Case facts block
  • Issue - condensing turns into a summary silently drops numeric values, dates, and stated expectations; multi-issue conversations risk cross-contaminating each other's facts.
  • Fix - extract transactional facts (amounts, dates, IDs, statuses) into a structured block included in full in every prompt, outside the summarized history - one entry per issue if there are several.
Lost in the middle
  • Issue - models reliably process the start and end of long inputs but may omit findings buried in the middle.
  • Fix - place key findings summaries at the start, and use explicit section headers throughout.
Trim external output (tools & agents)
  • Issue - verbose tool results (e.g. 40+ order-lookup fields) and upstream agents' raw reasoning chains both accumulate cost in context.
  • Fix - trim tool output to only the needed fields in a PostToolUse hook; have upstream agents return structured data (facts, citations, scores) instead of prose.
Prompt caching
  • Issue - reprocessing the same static prefix (instructions, tool defs, reference docs) every request wastes cost.
  • Fix - mark it with a cache_control breakpoint - static first, volatile after - reused cheaply for ~5 minutes.

5.2 · Escalation

Explicit escalation triggers
Customer requests a human, policy exception/gap (not just complexity alone), or inability to make meaningful progress.
Unreliable escalation proxies
Sentiment and self-reported confidence scores are both unreliable proxies for actual case complexity.
Multiple matches
When a lookup returns more than one candidate record, ask for an additional identifier - never pick by heuristic.
Explicit Escalation Criteria in System Prompts
Add escalation criteria with few-shot examples to the system prompt - when to escalate, when to resolve autonomously, and the exact handoff format. The proportionate first fix, before reaching for a classifier model or sentiment analysis.

5.3 · Error Propagation

Structured error context
Failure type, attempted query, partial results, alternative approaches - what actually enables intelligent coordinator recovery.
Access failure vs. valid empty result
The same core distinction as D2's error categories, now at the coordinator/subagent level.
Suppression anti-pattern
Silently returning empty results as "success," or terminating the whole workflow on one failure - both named anti-patterns.
Coverage annotations
Flag which findings are well-supported vs. where a source was unavailable, instead of silently omitting the gap - the synthesis-layer counterpart to never suppressing errors.

5.4 · Codebase Context

Context degradation and Scratchpad file
  • Issue - in extended sessions, the model starts giving inconsistent answers or citing "typical patterns" instead of the specific things it found earlier; not a token-limit problem, but verbose discovery output burying earlier precise findings under newer text.
  • Mitigation strategy - a persistent project file recording key findings; reference it instead of conversation context, so it survives context boundaries and keeps the main agent's context clean.
Subagent Delegation
  • Issue - the main agent doing all exploration directly fills its own context with verbose output from every file read and search.
  • Mitigation strategy - delegate specific investigation questions to subagents with their own isolated context; each returns a structured summary. The real value is context isolation, not just parallelisation.
Summary Injection Between Phases
  • Issue - Phase 2 subagents with no knowledge of Phase 1 findings duplicate exploration already done - a "cold start" problem.
  • Mitigation strategy - summarise key findings from Phase 1 and inject that summary into Phase 2 subagents' initial context before they start.
Crash Recovery via Structured State Manifests
  • Issue - a session crash or interruption loses all accumulated exploration progress.
  • Mitigation strategy - each agent exports structured state (explored paths, findings, next steps) to a known location; the coordinator loads it on resume instead of replaying history.
/compact, used proactively
  • Issue - waiting until context is already full means the degradation it's meant to prevent has often already happened.
  • Mitigation strategy - run it proactively during extended sessions, not only once the limit is hit - protects quality, not just quantity.

5.5 · Human Review

Aggregate-accuracy masking
A single overall accuracy number (e.g. 97%) can hide much weaker performance on one document type or field.
Stratified random sampling
Sampling across confidence bands (high/medium/low), not just low, to catch systematic errors hidden inside "confident" outputs.
Field-level confidence
Confidence scored per field, calibrated against a labeled validation set - a model can be confidently wrong.
Reviewer capacity prioritization
Route the highest-uncertainty items to reviewers first - never spread capacity evenly across all extractions.

5.6 · Provenance

Claim-source mapping
Structured link between a claim and its source (URL, document, excerpt) that must survive summarization/synthesis intact.
Conflicting sources
Annotate the conflict with attribution for both values - never arbitrarily pick one.
Temporal context
Requiring publication/collection dates prevents a newer source superseding an older one from being misread as a contradiction.
Attribution through the pipeline
Research → analysis → synthesis → report - attribution must survive every step; synthesis is where it's most often lost.

Diagram: Case Facts vs. the Fading Transcript

How this diagram fits together

The fading text (left) isn't a stylistic choice - it's showing what a summarized transcript actually does to Turn 7's date or Turn 9's detail: they get compressed into something vaguer with each summarization pass, exactly the numeric/date loss this task statement warns about.

The persistent case facts block (right) sidesteps the problem entirely by never entering the part of the prompt that gets summarized - it's included in full, every turn, so there's nothing for a summarization pass to blur.

Diagram: Escalation Decision

How this diagram fits together

Four paths out of the same question, and only one of them involves any judgment call at all.

  • Explicit request for a human - a hard override, no further investigation first.
  • Genuine policy gap - a hard escalate, because there's no policy to apply.
  • Inability to make meaningful progress - a separate trigger from a policy gap: the agent tried, the tools or its own access couldn't get it there. Both land in the same structured handoff, but for different reasons.
  • Everything else - stays with the agent, including a frustrated customer, as long as the issue is actually in scope.

The two crossed-out cards at the bottom are the named anti-patterns: sentiment-based escalation fails because frustration doesn't track case complexity, and self-reported confidence scores fail because the model's own confidence is poorly calibrated - it can be sure about the wrong things and unsure about the easy ones. Neither belongs anywhere in this decision.

The dotted lines on the right make the stakes concrete: both escalate outcomes actually hand off to a person, so the human agent icon only connects to those two boxes. Acknowledge & resolve has no line there - it's the one path that never leaves the agent.

Diagram: A Real Error Context, Before and After

How this diagram fits together

The before panel isn't wrong, exactly - status: failed is technically true. It's just useless: the coordinator can't tell retry from escalate from give-up.

The after panel adds three fields that turn a shrug into a decision:

  • failureType - says what kind of thing broke.
  • partialResults - means nothing gets thrown away just because the request didn't fully succeed.
  • alternatives - hands the coordinator options instead of forcing it to invent its own recovery plan from a bare error string.

3Active Recall
What exactly does progressive summarization risk losing, according to the guide?
Numerical values, percentages, dates, and customer-stated expectations - the exact details that matter most tend to be the first things a vague summary blurs away.
What's the fix for a long support session where the model might forget the original refund amount by turn 12?
Extract transactional facts (amounts, dates, order numbers, statuses) into a persistent "case facts" block that's included in full in every prompt, kept separate from the summarized conversation history.
Name three legitimate escalation triggers, and one thing that is not a reliable trigger.
Legitimate: an explicit request for a human, a genuine policy exception/gap, inability to make meaningful progress. Not reliable: sentiment (being upset alone) or a self-reported confidence score - both are unreliable proxies for actual complexity.
A lookup tool returns two matching customer records. What should the agent do?
Ask for an additional identifier to disambiguate. It should never pick one of the matches using a heuristic.
What four things belong in structured error context passed to a coordinator?
Failure type, the attempted query, any partial results, and potential alternative approaches.
Name the two error-handling anti-patterns the guide explicitly calls out.
Silently suppressing an error by returning empty results marked as success, and terminating the entire workflow on a single failure instead of attempting local recovery or proceeding with partial results.
What does "context degradation" look like in a long codebase-exploration session?
The model starts giving inconsistent answers, or falls back to referencing "typical patterns" in general instead of the specific classes/files it actually found earlier in the same session.
What's a recovery manifest, and what does it replace?
Structured state each agent exports to a known location on disk; the coordinator loads that manifest on resume and injects it into prompts. It replaces having to replay/reconstruct the full session history to recover from a crash.
Why sample high-confidence extractions too, not just the low-confidence ones?
A model can be confidently wrong. Stratified sampling across high/medium/low confidence bands catches systematic errors that would otherwise hide inside outputs the system already trusts.
Two sources disagree on a statistic. What's the correct synthesis behavior?
Preserve both values, annotate the conflict with source attribution for each, and check whether a publication/collection date difference actually explains it (a newer source may legitimately supersede an older one rather than truly "conflict" with it) - never arbitrarily pick one value.
Why does losing claim-source mappings during summarization matter?
Without the mapping, a downstream synthesis agent can no longer verify where a claim came from or reconcile it against other sources - this is a named reliability failure, not a cosmetic detail.

4Official Sample Questions (D5)
Q3. (Scenario 1, Customer Support) First-contact resolution is 55%, well below an 80% target. Logs show the agent escalates straightforward cases (standard damage replacements with photo evidence) while attempting to autonomously handle complex policy-exception cases. Most effective fix for escalation calibration?
A) Add explicit escalation criteria to the system prompt with few-shot examples showing escalate vs. resolve-autonomously.
B) Have the agent self-report a confidence score (1–10) and auto-route to humans below a threshold.
C) Deploy a separate classifier model trained on historical tickets to predict which requests need escalation.
D) Implement sentiment analysis and auto-escalate when negative sentiment exceeds a threshold.
Show answer
A. The root cause is unclear decision boundaries - explicit criteria plus examples is the proportionate first fix. B fails because the agent is already incorrectly confident on hard cases; self-reported confidence is poorly calibrated. C is over-engineered before prompt optimization has even been tried. D solves the wrong problem - sentiment doesn't correlate with case complexity, which is the actual issue.
Q8. (Scenario 3, Multi-Agent Research) A web-search subagent times out mid-investigation. Which error-propagation approach to the coordinator best enables intelligent recovery? (Same official question also referenced under D1 - it's core content for both 1.2 orchestration and 5.3 error propagation.)
A) Return structured error context to the coordinator: failure type, the attempted query, any partial results, and potential alternative approaches.
B) Retry with exponential backoff internally, returning a generic "search unavailable" status only after retries are exhausted.
C) Catch the timeout and return an empty result set marked as successful.
D) Propagate the timeout exception directly to a top-level handler that terminates the entire research workflow.
Show answer
A. Structured context gives the coordinator what it needs to decide: retry differently, try an alternative, or proceed with partial results. B's generic status hides context the coordinator needs. C is the suppression anti-pattern - marking a real failure as success prevents any recovery. D is the other anti-pattern - killing the whole workflow when recovery might have worked.

5Emergency Recap
Task Statement5.1
Preserving context across long sessions
  • Progressive summarization risks losing numeric values, dates, and stated expectations.
  • Lost-in-the-middle effect: models handle start/end reliably, middle content less so.
  • Extract transactional facts (amounts, dates, order numbers, statuses) into a persistent case facts block included in every prompt, outside the summarized history.→ See: Diagram, Case Facts vs. the Fading Transcript
  • Tool results consume tokens disproportionately to relevance - trim to relevant fields, and have upstream agents return structured data (facts, citations, scores) instead of verbose content.
  • Place key findings summaries at the beginning of aggregated inputs; organize detailed results with explicit section headers.
  • Require subagents to include metadata (dates, source, methodology) in structured outputs for accurate downstream synthesis.
  • The API is stateless - there's no server-side session, so every request must carry the complete conversation history or the model loses coherence. This is the tension case facts blocks resolve: summarize the narrative, keep the facts.
  • Prompt caching avoids reprocessing a stable prefix: mark it with a cache_control breakpoint, static content before, volatile content after. Get the order wrong and the prefix changes every request, so nothing matches - full price every call. Ephemeral breakpoints last ~5 minutes since last use, so it pays off for bursts of related requests, not calls hours apart.
  • Multi-issue sessions: give each issue its own structured entry (order ID, amount, status) in a separate context layer, so summarizing one issue can't contaminate another.
Task Statement5.2
Escalation & ambiguity resolution
  • Escalation triggers: explicit human request, a genuine policy exception or gap (not just complexity), inability to make progress - add explicit criteria with few-shot examples to the system prompt.→ See: Diagram, Escalation Decision
  • Honor an explicit request for a human immediately, without further investigation.
  • In-scope + frustrated is not itself a trigger: acknowledge and still attempt resolution, escalate only if the customer reiterates.
  • Sentiment and self-reported confidence are unreliable complexity proxies.
  • Multiple customer matches need an additional identifier to disambiguate, never a heuristic guess.
Task Statement5.3
Error propagation in multi-agent systems
  • Structured error context (failure type, attempted query, partial results, alternatives) enables intelligent coordinator recovery - a generic status hides all of this.→ See: Diagram, A Real Error Context
  • Access failures (need a retry decision) differ from valid empty results (successful query, no matches) - conflating them is a common mistake.
  • Silently suppressing errors as success, or killing the whole workflow on one failure, are both named anti-patterns.
  • Implement local recovery for transient failures inside the subagent; propagate only what couldn't be resolved locally, with partial results attached.
  • Structure synthesis output with coverage annotations flagging which findings are well-supported vs. where sources were unavailable.
Task Statement5.4
Context in large codebase exploration
  • Context degradation in extended sessions: inconsistent answers, referencing "typical patterns" instead of the specific classes found earlier.
  • Scratchpad files persist findings across context boundaries - maintain and reference them for later questions to counteract degradation.
  • Subagent delegation isolates verbose exploration - spawn subagents for specific investigative questions while the main agent preserves high-level coordination.
  • Structured state manifests support crash recovery - the coordinator loads and injects them into prompts on resume.
  • Summarize key findings from one exploration phase before spawning subagents for the next, injecting the summary into their initial context.
  • Use /compact proactively during extended sessions to protect context quality - waiting until the limit is hit is reactive, and the degradation it's meant to prevent has often already happened by then.
Task Statement5.5
Human review & confidence calibration
  • Aggregate accuracy (e.g. 97% overall) can mask poor performance on specific document types or fields - analyze accuracy by segment before reducing human review.
  • Stratified random sampling measures error rates across confidence bands, not just low-confidence ones - catches systematic errors hiding in "confident" outputs.
  • Field-level confidence must be calibrated against labeled validation sets before trusting it.
  • Route low-confidence or ambiguous/contradictory-source extractions to human review, prioritizing limited reviewer capacity.
  • Validation sequence: measure accuracy by segment, calibrate confidence, set thresholds, add stratified sampling - then reduce human review. Skipping straight to automation on aggregate metrics alone is the trap.
  • Prioritize reviewer queues dynamically by uncertainty, not evenly across all extractions or by arrival order - even distribution wastes capacity on items the model already handles well.
Task Statement5.6
Provenance & uncertainty in synthesis
  • Source attribution is lost during summarization unless claim-source mappings (URLs, document names, excerpts) are explicitly preserved through synthesis.
  • Conflicting statistics from credible sources should be annotated with attribution, never arbitrarily resolved to one value - let the coordinator decide how to reconcile.
  • Temporal data (publication/collection dates) prevents a real update being misread as a contradiction.
  • Structure reports with explicit sections distinguishing well-established findings from contested ones.
  • Render different content types appropriately - financial data as tables, news as prose, technical findings as structured lists.
  • Attribution must survive every pipeline step (research → analysis → synthesis → report) - synthesis is the most common place it's lost, since paraphrasing drops mappings unless explicitly preserved.
  • An analysis agent that finds conflicting values should complete its work with the conflict intact and annotated, not resolved - resolution is the coordinator's or consumer's call, not the analysis agent's.
Summary, one line per task statement:
  • 5.1 Extract exact facts into a persistent block outside the summary; don't trust a shrinking transcript with the numbers that matter.
  • 5.2 Explicit triggers, not sentiment or self-reported confidence; honor an explicit human request immediately.
  • 5.3 Structured error context enables recovery; local-recovery-first, propagate only what's unresolved; never suppress or nuke the whole workflow.
  • 5.4 Scratchpads and subagent delegation fight context degradation in long exploration; manifests enable crash recovery.
  • 5.5 One aggregate accuracy number hides weak segments; sample across confidence bands, calibrate confidence against labeled data.
  • 5.6 Preserve claim-source mappings through synthesis; annotate conflicts with attribution and dates instead of picking a winner.
