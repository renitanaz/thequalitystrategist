D1 · Agentic Architecture & Orchestration

27% · heaviest
  • 1.1 Trust stop_reason, never text-guessing or a cap as primary logic.
  • 1.2 Hub-and-spoke, coordinator dynamically selects subagents and iteratively refines via re-delegation.
  • 1.3 Context is explicit, never inherited; parallel = same response, multiple Task calls.
  • 1.4 Critical-path ordering is a programmatic gate, not a prompt request.
  • 1.5 PostToolUse normalizes, interception hooks gate - both are guarantees a prompt can't give.
  • 1.6 Fixed pipeline for predictable multi-aspect work, dynamic decomposition for open-ended work.
  • 1.7 Resume when nothing's stale, fork to explore two paths from one baseline, fresh+summary when the ground truth moved.

D2 · Tool Design & MCP Integration

18%
  • 2.1 The description is the routing signal - vague or overlapping descriptions cause misrouting, not model failure.
  • 2.2 Four error categories, each demanding a different agent response; never conflate an access failure with a valid empty result.
  • 2.3 Fewer tools per agent = more reliable selection (18 vs. 4–5 is the number to remember); tool_choice auto/any/forced controls how much freedom the model has.
  • 2.4 .mcp.json is shared/project, ~/.claude.json is personal; resources are for content, tools are for actions.
  • 2.5 Grep searches content, Glob matches paths, Edit needs uniqueness or falls back to Read+Write.

D4 · Prompt Engineering & Structured Output

20%
  • 4.1 Specific categorical criteria beat vague conservatism instructions - false positives cost trust across the board.
  • 4.2 2–4 targeted few-shot examples fix both format drift and ambiguous-case judgment.
  • 4.3 Forced/any tool_choice + JSON schema kills syntax errors; nullable fields stop fabrication; semantic errors still need checking.
  • 4.4 Retry only fixes fixable mistakes; if the source lacks the info, return null and flag it, don't loop.
  • 4.5 Batch = cheap but no latency guarantee, wrong for anything blocking; custom_id lets you resubmit just the failures.
  • 4.6 A generator reviewing its own output is a weaker check than an independent instance; split big reviews into local + integration passes.

D5 · Context Management & Reliability

15%
  • 5.1 Extract exact facts into a persistent block outside the summary; don't trust a shrinking transcript with the numbers that matter.
  • 5.2 Explicit triggers, not sentiment or self-reported confidence; honor an explicit human request immediately.
  • 5.3 Structured error context enables recovery; local-recovery-first, propagate only what's unresolved; never suppress or nuke the whole workflow.
  • 5.4 Scratchpads and subagent delegation fight context degradation in long exploration; manifests enable crash recovery.
  • 5.5 One aggregate accuracy number hides weak segments; sample across confidence bands, calibrate confidence against labeled data.
  • 5.6 Preserve claim-source mappings through synthesis; annotate conflicts with attribution and dates instead of picking a winner.
